## 1、上电复位 Reset_Handler → main () 完整调用

**上电/硬件复位**  

  ↓

**CPU读取向量表首地址：0x08000000**

  0x08000000：设置主堆栈指针 MSP = __initial_sp(栈顶)  __

  0x08000004：取出 Reset_Handler 的地址，PC跳转到 Reset_Handler    

↓

**Reset_Handler（汇编复位处理函数）**

├─ 调用 SystemInit()：配置系统时钟、FPU、向量表偏移寄存器SCB‑VTOR    

├─ 复制Flash中.data段数据到RAM（带初值全局变量）  

├─ 清零RAM中.bss段（无初值全局变量清零）

└─ 跳转到 rtthread_startup() 【RT‑Thread改写，不再跳__main】

 ↓

 **rtthread_startup() RT‑Thread入口函数 **   

├─ rt_hw_interrupt_disable() 关闭全局中断    

├─ rt_board_init()          板级硬件初始化    

├─ rt_components_board_init() 【执行INIT_BOARD_EXPORT注册的函数】    

├─ rt_system_heap_init()    系统堆初始化    

├─ rt_scheduler_init()      调度器初始化    

├─ rt_hw_timer_init()       硬件定时器初始化    

├─ rt_system_scheduler_start() 启动调度器，创建main线程        

↓ 

**main线程入口，执行 main() 函数**

## 2、INIT_BOARD_EXPORT与 INIT_APP_EXPORT底层原理

(1)本质：GCC 编译器扩展 + 链接脚本收集函数指针

两个宏底层共用一套机制，区别只是初始化优先级（段编号不同)

```
//简化底层宏
#define INIT_EXPORT(fn, level)  \
    const void *__rt_init_##fn __attribute__((used, section(".rti_fn."#level))) = fn;
```

**attribute((used))**：告诉编译器不要把这个变量优化删掉。

**attribute(section(".rti_fn.level")))**：把函数指针变量强制放到自定义段`.rti_fn.x`，不放在普通 data/text 段。

| 宏                      | 对应段      | 调用时机                                                     | 优先级 level      |
| :---------------------- | :---------- | :----------------------------------------------------------- | :---------------- |
| `INIT_BOARD_EXPORT(fn)` | `.rti_fn.1` | `rt_components_board_init()`，在调度器启动前，main 线程创建**之前** | 1，板级早期初始化 |
| `INIT_APP_EXPORT(fn)`   | `.rti_fn.6` | `rt_components_app_init()`，在 main 函数内部，应用层初始化   | 6，应用层初始化   |

(2) 链接脚本的工作

链接脚本中定义符号：`__rt_init_start`、`__rt_init_end`，并且加`KEEP()`，强制保留`.rti_fn.*`全部段，不被垃圾回收。

链接时，所有文件中用`INIT_*_EXPORT`标记的函数指针，**全部被链接器收集，按 level 从小到大顺序排布在.rti_fn 段**，形成一张函数指针数组。

(3) 运行时调用

1. `rt_components_board_init()`：从`__rt_init_start`遍历到`__rt_init_end`，调用 level=1（BOARD）的所有函数。此时中断还未打开，适合外设、时钟等板级底层初始化。
2. 当 main 线程运行进入`main()`，内部调用`rt_components_app_init()`，遍历执行 level=6（APP）的函数，做业务应用初始化。

核心：**不需要手动调用函数，编译链接阶段链接器自动收集函数指针；运行时 RT‑Thread 框架遍历这个指针数组自动调用**，实现 “注册即执行” 的自动初始化效果。

## 2. 内核基础与对象模型

### 2.1 对象容器与控制块

RT‑Thread 面向对象设计思想

RT‑Thread 用**C 语言模拟面向对象**：把内核资源（线程、信号量、消息队列等）抽象为`rt_object`基对象，所有内核控制块第一个成员都是`struct rt_object`；对象统一交给对象容器管理，提供统一接口，实现封装、继承思想。

`rt_object`记录对象类型、名字、链表节点，所有内核对象挂入全局对象容器链表

上层 API 不直接操作硬件，操作对象句柄，做到硬件隔离。

### `struct rt_thread`关键成员

| 成员               | 作用                                                         |
| :----------------- | :----------------------------------------------------------- |
| `stat`             | 线程状态，标记线程当前处于：初始 / 就绪 / 运行 / 挂起 / 关闭状态，调度器依据该字段管理线程 |
| `current_priority` | 线程当前优先级；线程运行时实际使用优先级，支持动态修改，可用于优先级继承 |
| `init_tick`        | 线程时间片（tick），时间片轮转调度时，线程剩余运行时间计数；时间片耗尽触发上下文切换 |
| `sp`               | 线程栈指针，保存线程切换时的栈地址；上下文切换时，保存 / 恢复该指针，实现线程现场保存 |

### 2.2 静态对象 vs 动态对象

| 对比项   | 静态对象                              | 动态对象                                         |
| :------- | :------------------------------------ | :----------------------------------------------- |
| 分配位置 | 编译期分配，放在全局 RAM (.data/.bss) | 运行时`rt_malloc()`从系统堆分配                  |
| 生命周期 | 程序整个运行周期，上电即存在          | 运行时创建，可动态销毁                           |
| 释放机制 | 不需要释放；程序结束才回收内存        | 调用`rt_object_delete()`释放回堆；堆内存碎片风险 |

> 高可靠场景强制使用静态线程的原因：

1. 动态创建依赖堆内存`rt_malloc`，堆会产生**内存碎片**，极端场景 malloc 失败，线程创建失败，系统死机；
2. 静态对象内存编译期确定，不会出现内存分配失败，内存可控、可预估；
3. 避免内存泄漏、野指针风险；工业、航天等高可靠系统不允许运行时动态申请内存。

## 3. 线程状态机与调度算法

### 3.1 RT‑Thread 五态模型

五种状态：**初始态、就绪态、运行态、挂起态、关闭态**

1. 初始态 (RT_THREAD_INIT)：线程对象初始化完成，未启动。

   API：`rt_thread_init()` / `rt_thread_create()` → 进入初始态

   `rt_thread_startup()`：初始态 → **就绪态**

   

2. 就绪态 (RT_THREAD_READY)：线程条件满足，等待 CPU 调度。

   高优先级线程抢占：就绪态 → **运行态**

   `rt_thread_suspend()`：就绪态 → **挂起态**

3. 运行态 (RT_THREAD_RUNNING)：线程正在 CPU 执行。

   更高优先级线程就绪抢占：运行态 → **就绪态**

   `rt_thread_delay()` / 等待信号量：运行态 → **挂起态**

   时间片耗尽：运行态 → **就绪态**

4. 挂起态 (RT_THREAD_SUSPEND)：线程阻塞，不参与调度（延时、等待资源）

   延时到期 / 获取信号量成功：挂起态 → **就绪态**

5. 关闭态 (RT_THREAD_CLOSE)：线程运行结束，退出。

   `rt_thread_exit()` / `rt_thread_delete()`：任意可终止状态进入关闭态。

## 3.2 调度机制剖析

### 抢占式调度

1. 核心规则：高优先级线程优先获得 CPU

   只要有更高优先级线程变为就绪态，立刻触发上下文切换，抢占当前正在运行的低优先级线程；低优先级线程让出 CPU，进入就绪队列等待。

2. 触发时机：中断退出、释放信号量、唤醒高优先级线程。

3. RT‑Thread 优先级数字越小优先级越高。

### 时间片轮转调度

1. **同一优先级多个线程之间的调度策略**。
2. 同优先级线程平分 CPU 时间，每个线程分配`init_tick`时间片；线程运行消耗 tick 计数，计数减为 0，线程让出 CPU，切换同优先级下一个就绪线程。
3. 如果线程主动阻塞（delay），剩余时间片会直接作废。
