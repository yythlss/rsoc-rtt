# RT-Thread 培训第二天笔记：内核启动流程与多线程实战

> 作者：林瑞源（第 3 组）
> 培训主题：RT-Thread 内核与多线程
> 硬件平台：星火 1 号（STM32F407，168MHz）

## 从上电到 main()：RT-Thread 启动流程

写 RT-Thread 程序时，`main()` 不是第一个跑的。从硬件复位到进入用户 `main()`，完整链路是：

```
硬件复位 → Reset_Handler(汇编) → SystemInit(168MHz)
  → entry() 被 RT-Thread 劫持 → rtthread_startup()
    → 关中断 → 板级初始化(执行 INIT_BOARD_EXPORT)
    → 打印 Logo → 初始化定时器/调度器
    → 创建 main 线程 → 创建空闲线程
    → 启动调度器（永不返回）
      → main 线程被调度
        → rt_components_init()（执行 INIT_DEVICE/COMPONENT/APP_EXPORT）
        → 用户 main()
```

关键点：即使用户 `main()` 里一行代码都不写，系统已有 main、定时器、空闲三个线程在跑。

## 自动初始化机制：INIT_xxx_EXPORT

原理很简单——把函数指针塞进链接器的一个特殊段，启动时代码遍历这个段逐个调用。不需要手动调 init 函数，声明 `INIT_DEVICE_EXPORT(my_init)` 就自动在设备初始化阶段执行。

## 线程五态与调度

RT-Thread 线程有五个状态：初始→就绪→运行→挂起→关闭。调度是**抢占式 + 时间片轮转**：高优先级线程随时抢占低优先级，同优先级按时间片轮转。

## 实战：三个线程 + KEY0 控制

在星火 1 号上创建了三个线程：
- **LED1（动态创建）**：闪烁，可用 KEY0 挂起/恢复
- **LED2（静态创建）**：另一种闪烁节奏
- **Monitor（动态创建）**：每隔几轮打印线程状态和栈使用率

### 踩坑点

1. **栈使用率**：本版 RT-Thread 没有 `rt_thread_stack_residue()`，手写 `my_stack_residue()` 扫描 '#' 填充字节计算剩余栈
2. **挂起/恢复竞态**：直接读线程 `stat` 字段判断是否挂起不靠谱（本版挂起后 stat=10 而非预期值），改用自定义 `led1_suspended` 标志在安全点自挂起，monitor 只看标志位
3. **串口输出串台**：多线程同时 `rt_kprintf` 会乱码，加 `print_mtx` 互斥锁保护打印

## 面向对象设计

RT-Thread 内核大量用 C 模拟面向对象：线程、信号量、互斥量等都是"对象"，有 `type` 字段标识类型，通过继承（结构体首成员放父类）实现多态。静态对象（编译期分配）和动态对象（`rt_*_create` 运行时分配）的区别在于内存管理方式不同。

## 小结

第二天最大的收获是搞清楚了 RT-Thread 从复位到 main 的完整启动链路——以前只知道写 `main()`，现在明白了中间自动初始化、调度器启动、空闲线程这些"看不见的部分"。线程实战让我体验了抢占式调度的实际效果，也踩了栈监控和挂起/恢复的坑。
