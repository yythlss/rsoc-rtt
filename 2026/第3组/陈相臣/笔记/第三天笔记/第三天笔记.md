- 计数信号量
- 互斥量

## 三、核心知识点

### 1. 计数信号量

计数信号量适合管理有限资源，例如停车场车位。

特点：

- 信号量初始值表示可用资源数量。
- 线程获取资源时执行 `rt_sem_take()`。
- 线程释放资源时执行 `rt_sem_release()`。
- 当信号量为 0 时，后续线程会等待，直到资源被释放。

适合场景：

- 多个相同资源需要分配和回收。
- 资源数量有限，例如车位、缓冲区、连接数等。

### 2. 互斥量

互斥量用于保护共享资源，保证同一时间只有一个线程访问临界区。

特点：

- 使用 `rt_mutex_take()` 获取锁。
- 使用 `rt_mutex_release()` 释放锁。
- 应保护完整操作过程，而不只是保护某一条语句。

售票系统就是典型场景：

- 检查余票
- 修改余票
- 记录票号
- 打印结果

整个过程都必须放在互斥量保护范围内，否则可能出现重复售票。

### 3. 事件集

事件集适合多个线程之间传递“条件就绪”信号。

特点：

- 一个事件对象可以包含多个事件位。
- 可以按 OR 模式等待任意事件。
- 可以按 AND 模式等待所有事件。
- 可以使用超时时间观察未就绪模块。

系统启动检查中，网络、传感器、存储三个模块都就绪后，主业务线程才允许启动。

### 4. 消息队列

消息队列用于线程之间传递结构化的数据。

特点：

- 消息队列有固定容量。
- 发送线程使用 `rt_mq_send()` 或 `rt_mq_send_wait()`。
- 接收线程使用 `rt_mq_recv()`。
- 队列满时，非阻塞发送会返回失败，不会让线程崩溃。

快递分拣中心就是消息队列的典型应用：

- 发件线程产生快递消息。
- 分拣线程接收消息。
- 分拣线程根据区域统计快递数量和总重量。

## 四、作业要求与实现

本次代码按四个实验拆分为四个独立源文件：

```text

```

四个文件都放到 RT-Thread Studio 工程的 `applications/` 目录下。

四个实验统一采用以下设计：

- 线程栈大小为 `1024` 字节。
- 业务线程优先级为 `25`，时间片为 `5`。
- 使用 `running` 标志防止 MSH 命令被重复启动。
- 使用 `done_sem` 等待所有业务线程退出后再清理资源。
- 线程名和 IPC 对象名通过局部数组动态生成，避免重复执行时重名。
- 创建线程、信号量、互斥量、事件、消息队列后都检查返回值。

程序通过 `MSH_CMD_EXPORT` 导出四个独立命令：

```text
parking_demo
ticket_demo
startup_demo
package_demo
```

### 练习一：停车场车位管理

代码文件：`parking.c`

对应命令：

```text
parking_demo
```

作业要求：

- 创建初始值为 3 的计数信号量。
- 创建 5 个车辆线程。
- 车辆进入前申请车位。
- 获得车位后打印进入信息。
- 停留后离开并释放车位。
- 2 秒内没有获得车位则打印等待信息并重新申请。
- 任意时刻停车场内车辆数不能超过 3。

实现思路：

- 定义 `CAR_COUNT = 5`、`PARKING_SPACES = 3`。
- 使用计数信号量 `parking_sem` 表示 3 个车位。
- 使用互斥量 `count_mutex` 保护共享变量 `used_spaces`。
- 5 个车辆线程按 `car_id` 设置 50ms 启动间隔，降低同时竞争的概率。
- 车辆使用 `rt_sem_take(parking_sem, RT_TICK_PER_SECOND * 2)` 申请车位。
- 获取车位后，在互斥量内完成 `used_spaces++` 和进入信息打印。
- 车辆停留 `2500ms + car_id * 50ms` 后，在互斥量内减少 `used_spaces`，再释放车位。
- 主命令线程通过 `done_sem` 等待所有车辆线程结束后，再删除 IPC 对象。

预期现象：

- 任意时刻 `used spaces` 不会超过 3。
- 没有立即获得车位的车辆会打印 `carX waiting for a space`。
- 有车离开后，等待车辆继续进入。

### 练习二：多窗口售票系统

代码文件：`ticket.c`

对应命令：

```text
ticket_demo
```

对比实验命令：

```text
ticket_demo unsafe
```

作业要求：

- 创建两个售票线程，分别代表窗口 A 和窗口 B。
- 使用全局变量保存剩余票数。
- 售票过程包括检查余票、减 1、记录票号、打印结果。
- 使用互斥量保护完整售票过程。
- 售完后两个线程自动退出。
- 最终 20 张票全部售出。
- 不出现相同票号。
- 剩余票数不能小于 0。

实现思路：

- 定义 `TOTAL_TICKETS = 20`、`WINDOW_COUNT = 2`。
- 安全模式下，每个窗口线程用 `ticket_mutex` 包住“检查余票、减票、打印票号”的完整流程。
- 安全模式售完票后打印 `all tickets sold` 和 `remaining tickets: 0`。
- `unsafe` 模式通过参数关闭互斥量，并在读取 `remaining` 和写回 `remaining` 之间加入 50ms 延时。
- 非安全模式用于演示并发访问共享变量时可能出现的重复售票或负数余票。
- 对比两次运行结果，观察并发访问共享变量的问题。

预期现象：

- 安全模式中票号唯一。
- 最后打印 `all tickets sold`。
- 最后打印 `remaining tickets: 0`。
- 非安全模式可能出现重复票号。

### 练习三：系统启动条件检查

代码文件：`startup.c`

对应命令：

```text
startup_demo
```

作业要求：

- 定义网络、传感器、存储三个事件位。
- 创建三个初始化线程。
- 三个初始化线程分别发送对应事件。
- 主业务线程使用 AND 模式等待三个事件。
- 存储模块初始化时间设置为 5 秒。
- 主业务线程最多等待 3 秒。
- 超时后打印尚未完成的模块并再次等待。

实现思路：

- 定义三个事件位：`EVENT_NET_READY`、`EVENT_SENSOR_READY`、`EVENT_STORAGE_READY`。
- 用 `struct module_info` 统一保存模块名称、事件位和初始化延时。
- 三个初始化线程分别在 1s、2s、5s 后发送就绪事件。
- 使用 `volatile ready_flags` 记录当前已经就绪的模块位。
- 主业务线程使用 `RT_EVENT_FLAG_AND | RT_EVENT_FLAG_CLEAR` 等待全部事件。
- 使用 `RT_TICK_PER_SECOND * 3` 设置 3 秒等待。
- 超时后调用 `print_missing_modules()` 检查并打印未就绪模块，然后继续等待。
- 所有模块就绪后，主业务线程打印 `all modules are ready` 和 `business task started`。

预期现象：

- 网络模块约 1s 后就绪。
- 传感器模块约 2s 后就绪。
- 主业务线程 3 秒超时。
- 提示 `storage is not ready`。
- 存储模块 5 秒后就绪。
- 最终打印 `all modules are ready`。
- 然后打印 `business task started`。

### 练习四：快递分拣中心

代码文件：`package.c`

对应命令：

```text
package_demo
```

作业要求：

- 创建一个消息队列。
- 消息队列容量为 5 条消息。
- 创建两个发件线程。
- 每个发件线程产生 5 条快递消息。
- 快递编号不得重复。
- 分拣线程接收消息。
- 分拣线程按区域分类。
- 统计总数量、各区域数量、总重量。
- 队列满时发送线程不得崩溃。
- 队列满时记录发送失败次数。
- 两个发送线程完成后发送结束消息。
- 分拣线程收到结束消息后打印统计结果并退出。

实现思路：

- 定义 `QUEUE_SIZE = 5`、`SENDER_COUNT = 2`、`PACKAGES_PER_SENDER = 5`。
- 使用消息队列传递 `struct package_msg { id; region; weight; }`。
- 两个发件线程分别生成 `1001...1005` 和 `2001...2005`，保证编号不重复。
- 区域通过 `(index + sender_id) % 3 + 1` 生成，重量按发送线程和序号递增。
- 分拣线程持续接收消息。
- 队列满时使用非阻塞 `rt_mq_send()`，返回 `-RT_EFULL` 后累计 `send_failed` 并延时重试。
- 两个发送线程都完成后，使用 `rt_mq_send_wait()` 发送一条 `region == 0` 的结束消息。
- 收到 `region == 0` 的结束消息后退出。

预期现象：

- 最终统计到 10 条快递。
- 区域分别为华东、华南、华北。
- 打印各区域数量。
- 打印所有快递总重量。
- 打印发送失败次数。
- 每个快递打印格式类似 `package 1001 -> east, weight: 800 g`。

## 七、思考题

### 1. 不要只给单条语句加锁

售票系统中，如果只给 `remaining--` 加锁，检查和修改之间仍然可能发生切换。

必须把“检查、修改、记录、打印”完整流程保护起来。

### 2. 信号量和互斥量的区别

计数信号量适合管理多个同类资源。

互斥量适合保护共享数据，防止多个线程同时修改同一个变量。

### 3. 重复执行命令

重复执行 MSH 命令时，不能因为线程名或 IPC 对象名重复而崩溃。

本次代码中使用了：

- 运行标志防止重复启动。
- 动态名称避免重名冲突。
- `done_sem` 等待所有工作线程退出后再清理 IPC 对象。
- 任务结束后删除 IPC 对象。

### 4. 创建结果必须检查

所有线程和 IPC 对象创建后，都应该检查返回值。

常见检查对象包括：

- `rt_thread_create()`
- `rt_sem_create()`
- `rt_mutex_create()`
- `rt_event_create()`
- `rt_mq_create()`
