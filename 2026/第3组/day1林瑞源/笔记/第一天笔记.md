## 一、Git基础环境配置与核心指令

### 1. 环境初始化与身份配置

- **Git安装与汉化**：安装Git后可尝试配置中文语言包，汉化失败则使用英文版本。
- **全局身份设置**：配置全局用户名和邮箱，确保提交记录的身份标识正确。
  ```bash
  git config --global user.name "你的名字"
  git config --global user.email "你的邮箱"
  ```
- **SSH密钥配置**：生成SSH密钥对（公钥与私钥），将公钥添加到Git平台账户设置中，实现免密认证。
  ```bash
  ssh-keygen -t rsa -C "你的邮箱"
  ```

### 2. 核心操作指令

| 指令 | 作用 |
|------|------|
| `git init` | 初始化本地仓库 |
| `git clone <url>` | 克隆远端仓库到本地 |
| `git pull` | 拉取远端最新代码 |
| `git add <file>` | 将文件加入暂存区 |
| `git commit -m "消息"` | 提交变更到本地仓库 |
| `git push` | 推送本地提交到远端仓库 |
| `git checkout -b <分支名>` | 创建并切换到新分支 |

**要点**：日常开发应在独立分支进行，避免直接操作受保护的 master 分支。

## 二、开源协作流程与PR提交规范

### 1. Fork模式下的协作机制

- **仓库复刻（Fork）**：将上游仓库 Fork 到个人账户，形成独立的开发副本。
- **分支策略**：在个人 Fork 仓库中创建功能分支（如 `day1`、`day2`）进行开发，严禁直接修改 master 分支。
- **变更同步**：添加上游仓库地址并同步最新代码，避免冲突。
  ```bash
  git remote add upstream <上游仓库地址>
  git fetch upstream
  git pull upstream master
  ```

### 2. Pull Request（PR）提交与审核

- **PR创建流程**：本地修改 → 推送至个人 Fork → 通过平台界面创建 PR，将功能分支合并至上游仓库。
- **审核流程**：提交 PR 时需指定对应的组长作为审查人员（Reviewer），审查通过后方可合并。
- **冲突解决**：当本地分支落后于上游分支时会产生冲突，通过合并上游代码或手动解决冲突来修复。

## 三、作业提交与组织管理

### 1. 目录结构与命名规范

- **层级结构**：按「组别/学员姓名/日期」的层级创建目录，分别存放笔记和作业。
- **分支命名**：使用 `day1`、`day2` 等命名分支，避免覆盖模板文件。

### 2. 审核职责分工

- **小组长**：拥有合并 PR 的权限，负责审核组员提交的代码结构、命名规范及内容质量。
- **导师**：负责审核小组长的 PR，并处理跨组的复杂问题。
