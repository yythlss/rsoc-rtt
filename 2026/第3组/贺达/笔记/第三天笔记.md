# 第三天学习笔记：RT-Thread 线程间同步与通信

## 1. 同步与通信的区别

多线程并发带来两个基本问题：一是多个线程何时可以继续执行，二是数据如何在线程之间传递。

- **同步**关注执行条件与访问次序，典型对象包括信号量、互斥量和事件集；
- **通信**关注数据交付，典型对象包括邮箱和消息队列；
- 两者并非完全割裂，例如消息到达本身也会唤醒等待线程。

IPC 对象可以按 FIFO 或优先级管理等待队列。对实时性敏感的任务通常选择 `RT_IPC_FLAG_PRIO`，使高优先级等待线程优先获得资源。

## 2. 信号量

信号量内部包含非负计数和等待线程队列。线程执行 `rt_sem_take` 时：

1. 计数大于 0，则计数减 1 并立即返回；
2. 计数等于 0，则根据超时参数阻塞或立即失败；
3. 其他线程执行 `rt_sem_release` 后，等待线程获得继续运行的机会。

常用接口：

```c
rt_sem_create();
rt_sem_take();
rt_sem_trytake();
rt_sem_release();
rt_sem_delete();
```

初值为 0 的信号量常用于完成通知；初值大于 1 的计数信号量适合管理缓冲区槽位、连接数、停车位等同类有限资源。信号量没有线程所有权，因此不能直接替代互斥量保护复杂共享状态。

## 3. 互斥量

互斥量用于确保同一时刻只有一个线程进入临界区。它与二值信号量的关键区别包括：

- 互斥量具有所有者，原则上由获取它的线程释放；
- 支持递归持有计数；
- RT-Thread 通过优先级继承缓解优先级反转。

优先级反转发生在高优先级线程等待低优先级线程持有的锁，同时低优先级线程又被中优先级线程抢占。优先级继承会临时提高锁持有者的优先级，使其尽快完成临界区并释放锁。

互斥保护的边界应由数据一致性决定，而不是由某一条 C 语句决定。例如售票过程中的“检查、读取、扣减、记录”共同构成一个事务，只保护 `count--` 无法避免两个线程基于同一个旧值作出决定。

使用互斥量时应注意：

- 尽量缩短持锁时间；
- 不在持锁期间执行不确定时长的阻塞操作；
- 所有退出分支都要释放已经获得的锁；
- 删除互斥量前确认没有线程仍在持有或等待。

## 4. 事件集

事件集用一个无符号整数的不同位表示多个状态。发送方通过 `rt_event_send` 置位，接收方通过 `rt_event_recv` 指定关注的事件掩码。

接收模式包括：

- `RT_EVENT_FLAG_OR`：任意目标位到达即可满足；
- `RT_EVENT_FLAG_AND`：全部目标位到达才满足；
- `RT_EVENT_FLAG_CLEAR`：接收成功后清除已匹配事件位。

事件集适合模块初始化汇合、多个告警源、状态组合等场景。事件位只表达“是否发生/是否就绪”，不携带复杂数据；需要传输内容时，应改用邮箱或消息队列。

超时后再次等待时，需要考虑事件位是否应当保留。如果第一次等待可能超时，但后续仍需复用已到达状态，就不应在第一次等待中清除事件位。

## 5. 邮箱与消息队列

邮箱中的每封邮件固定为一个机器字，适合传递数值、状态或指针。消息队列则按创建时指定的消息大小复制数据，可以直接传递结构体，接收方不依赖发送方缓冲区的后续生命周期。

消息队列的容量有限。生产者快于消费者时，队列可能填满，应用必须明确选择处理策略：

- 立即失败并记录；
- 延时后重试；
- 使用可等待的发送接口；
- 按业务规则丢弃或覆盖低价值消息。

接口返回值也需要按当前内核版本核对。RT-Thread 5.3 的 `rt_mq_recv()` 返回类型为 `rt_ssize_t`：成功时返回实际复制的消息字节数，失败时返回负错误码。接收固定结构体时，应检查返回值是否等于结构体大小，不能沿用旧示例中“等于 `RT_EOK` 才算成功”的判断。

结束协议同样重要。多个生产者共享队列时，如果每个生产者任意发送结束标记，消费者可能过早退出。更可靠的方式是由管理线程等待所有生产者完成，再把唯一结束消息排到普通消息之后。

## 6. 动态对象的生命周期

通过 `create` 创建的线程与 IPC 对象占用动态内存。一个可重复执行的 MSH 实验应形成完整生命周期：

```text
命令检查运行状态
    ↓
管理线程创建 IPC 对象
    ↓
创建并启动工作线程
    ↓
完成信号量汇集退出通知
    ↓
管理线程删除 IPC 对象
    ↓
清除运行状态
```

创建失败必须立即检查，且清理顺序应与依赖关系相反。工作线程仍可能访问 IPC 对象时，管理线程不能提前删除对象。单独依赖固定延时判断线程是否结束不可靠，完成信号量或明确的结束消息更适合建立退出时序。

## 7. 四类机制的选择

| 需求 | 合适机制 | 原因 |
| --- | --- | --- |
| 管理 N 个相同资源 | 计数信号量 | 计数直接表示可用数量 |
| 保护共享数据事务 | 互斥量 | 所有权与优先级继承 |
| 等待多个布尔条件 | 事件集 | 支持位组合及 AND/OR |
| 在线程间传递结构体 | 消息队列 | 按值复制、缓冲多条消息 |
| 传递一个机器字 | 邮箱 | 开销较小、接口简单 |

## 8. 调试观察方法

并发日志的先后顺序可能因线程调度发生变化，MSH 提示符也可能与工作线程输出交错。因此不能只比较固定文本顺序，而应检查不变量：

- 停车场同时占用数是否始终不超过 3；
- 安全售票阶段是否恰好售出 20 张且没有重复；
- 业务线程是否在三个事件全部到达后才启动；
- 分拣统计总数与各区域数量之和是否一致；
- 重复执行命令时是否被拒绝或能在上一次清理后重新运行。

调试的重点是验证并发约束，而不是要求每次运行产生完全相同的线程交错顺序。
