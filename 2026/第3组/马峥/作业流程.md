## 二、作业开发流程

### 第 1 步：确认需求

阅读课程材料（`C:\Users\79186\Desktop\RT\设备驱动\`），
明确作业要求：驱动层 + 应用层 + 课堂笔记。

### 第 2 步：在 RT-Thread Studio 中编写源码

- **驱动层**：`01_kernel\applications\test_drv.c`
  - `rt_device_create()` + `rt_device_register()`
  - 绑定 6 个回调函数：`init / open / close / read / write / control`
  - `INIT_DEVICE_EXPORT()` 自动初始化
  - 防重复注册检查

- **应用层**：`01_kernel\applications\test_dev.c`
  - `rt_device_find()` → `rt_device_open()` → `read/write/control` → `close`
  - `MSH_CMD_EXPORT()` 导出命令

- **课堂笔记**：`rsoc-rtt\2026\第3组\马峥\day4\README.md`
  - 框架分析（PIN/I2C/SPI）
  - 源码结构说明
  - 运行说明

### 第 3 步：本地编译验证

```powershell
# 设置环境变量
$env:RTT_ROOT = 'D:\stm32\RT-ThreadStudio\workspace\01_kernel\rt-thread'
$env:PATH = 'D:\stm32\RT-ThreadStudio\platform\env_released\env-new\tools\gnu_gcc\arm_gcc\mingw\bin;' + $env:PATH

# 切换到项目目录
Set-Location 'D:\stm32\RT-ThreadStudio\workspace\01_kernel'

# 编译（-j8 并行加速）
scons -j8
```

**预期输出**：
```
scons: done building targets.
text=92920, data=1564, bss=33912  rt-thread.elf
```

> ⚠️ 常见编译错误：
> - `rt_ssize_t` → 改为 `rt_size_t`（部分 RT-Thread 版本无 ssize_t）
> - `RT_DEVICE_CTRL_USER_ALLOC` → 直接用 `0x100`（部分版本无此宏）
> - finsh.h 找不到 → 加上 `-ID:\...\rt-thread\components\finsh` 路径

### 第 5 步：Git 提交

```powershell
Set-Location 'C:\Users\79186\Desktop\RT\rsoc-rtt'

# 添加文件到暂存区
git add '2026/第3组/马峥/day4/'

# 提交（commit message 以 dayX: 开头）
git commit -m 'day4: 设备驱动框架 - 虚拟设备test_dev + PIN设备分析笔记'

# 推送到云端
git push
```

### 第 6 步：打 Git Tag（可选，便于管理）

```powershell
# 查看最新 commit
git log --oneline -1

# 创建 tag 指向最新 commit
git tag -a 'day4' -m 'day4 设备驱动框架笔记' <commit-hash>

# 推送 tag 到云端
git push origin 'refs/tags/day4:refs/tags/day4'
```

> ⚠️ 注意：如果本地已有同名 tag，需用完整 refspec 推送：
> `git push origin 'refs/tags/day4:refs/tags/day4'`

## 三、关键注意事项

### 1. 文件位置要记清

| 操作 | 路径 |
|------|------|
| 写代码（编译验证用） | `D:\stm32\RT-ThreadStudio\workspace\01_kernel\applications\` |
| 存作业（同步到 Git） | `C:\Users\79186\Desktop\RT\rsoc-rtt\2026\第3组\马峥\dayN\` |

### 2. 每次都要 git add

`git add` 只暂存当前工作区的变更，如果文件没 add 就 commit，push 后云端看不到。

### 3. commit message 规范

以 `dayN:` 开头，方便从 log 中快速定位：
```
day1: ...
day3: ...
day4: ...
```

### 4. 编译前先 clean

如果遇到奇怪的编译错误（特别是删了代码还报错），先清理再重新编译：
```powershell
scons -c
scons -j8
```

### 5. Git Tag 推送

本地 tag 不自动推送到远程，每次都需要单独 push：
```powershell
git push origin 'refs/tags/dayX:refs/tags/dayX'
```
