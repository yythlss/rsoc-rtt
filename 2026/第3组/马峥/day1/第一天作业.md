# 第一天作业：Git 的 push / pull / PR

## 一、三个核心概念

### 1. git push（推送）
把本地提交**上传到云端仓库**。

```bash
git push origin day1
```
- `origin`：云端远程仓库的名字
- `day1`：要推的分支名

### 2. git pull（拉取）
把云端**最新内容下载到本地**。

```bash
git pull origin master
```
作用：别人（或上游）更新了仓库，你先拉下来，再改自己的，避免冲突。

### 3. PR / Pull Request（合并请求）
自己**没有权限直接改**目标仓库时，先改自己的副本（fork），然后**请求对方同意把改动合并进去**。

本质：不是"我直接改你的仓库"，而是"我改好了，请你审核，同意就并进去"。

## 二、标准 PR 工作流（给官方/上游仓库提交）

```
上游仓库（别人的，无写权限）
   ↑ 4. 发起 PR 请求合并
fork 仓库（自己账号下的副本，有写权限） ← 1. 浏览器点 Fork 复制
   ↑ 3. push
本地仓库（自己电脑）
```

### 8 步流程

1. **浏览器 fork 并同步上游**：打开上游仓库 → Fork 到自己的账号 → 点「同步」更新到最新
2. **`git switch master` + `git pull origin master`**：本地切回主分支，拉取云端 fork 的最新内容
3. **`git checkout -b day2`**：新建分支并切换过去（**day2 是分支名，自己起**，如 day1/day2/fix-xxx）
4. **修改/新增/删除文件**：干活
5. **`git add .`**：把所有改动放进暂存区
6. **`git commit -m "提交说明"`**：打快照并写说明
7. **`git push origin day2`**：推到云端 fork 的 day2 分支
8. **创建 PR**：在 Gitee 网页 day2 分支下点「创建 Pull Request」，选择从 `你的fork:day2` → 到 `上游:master`

### 下一轮怎么办
一模一样重复 1-8，只把 `day2` 换成 `day3`、`day4`……这就是迭代开发的循环。

## 三、自己的仓库（无上游）简化流程

如果仓库是**自己的**（比如 mazheng233/rsoc-rtt），不需要 fork 和 PR，直接：

```bash
git switch master        # 回主分支
git pull origin master   # 拉最新
git checkout -b day2     # 新分支
# ……改文件……
git add .
git commit -m "说明"
git push origin day2     # 推上去
```

## 四、记忆口诀

- `add` = 收拾行李（暂存）
- `commit` = 拍照存档（提交）
- `push` = 寄出去（推送）
- `pull` = 取回来（拉取）
- 分支 = 独立的工位，一个任务一个分支，互不干扰
- PR = 递交申请单，请求合并

## 五、今天实际踩过的坑

1. 命令要以 `git` 开头（`git commit`，不是 `commit`）
2. `checkout` 不要拼成 `chatout`
3. 空文件夹 git 不跟踪，需要放文件或 `.gitkeep`
4. `git push` 提示 `Everything up-to-date` 说明没有新提交，先 add 再 commit
5. 私有仓库需要令牌认证（Gitee 私人令牌）
