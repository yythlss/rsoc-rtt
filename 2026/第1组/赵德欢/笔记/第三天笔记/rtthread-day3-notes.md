# RT-Thread 线程间同步与通信 学习笔记

> 涵盖多线程协作中为什么需要同步、进入/退出临界区的四种方式、核心三件套（信号量 / 互斥量 / 事件集）、线程间通信（邮箱 / 消息队列），以及重点速记。

---

## 一、为什么需要线程间同步

多线程系统中，多个线程协作时，若不加保护地访问共享资源，会导致数据错乱或损坏。

- **临界区（Critical Section）**：被多个线程同时访问、必须通过互斥保护的代码段或资源。
- **全局变量不能直接当作 IPC 媒介**：无法解决竞态条件（race condition）、缓存一致性、原子性问题。

**同步 vs 互斥**

| 概念 | 含义 | 例子 |
| :-- | :-- | :-- |
| 同步 Synchronization | 线程按预定先后次序运行 | A 先采集，B 再处理 |
| 互斥 Mutual Exclusion | 任意时刻最多一个线程访问临界区 | 共享内存只能被一人写 |

> 互斥可以看作一种特殊的同步。

## 二、进入/退出临界区的四种方式（从重到轻）

| 方式 | 说明 | 关键 API |
| :-- | :-- | :-- |
| 1. 关闭全局中断 | 最重，屏蔽所有中断，仅适合**极短**临界区 | `rt_base_t level = rt_hw_interrupt_disable(); ... rt_hw_interrupt_enable(level);` |
| 2. 调度器锁 | 较重，阻止线程调度但中断仍可响应；**可嵌套**（嵌套深度用 `rt_critical_level()` 查询） | `rt_enter_critical()` / `rt_exit_critical()` |
| 3. 信号量 Semaphore | 轻量级内核对象，见第三节 | `rt_sem_take()` / `rt_sem_release()` |
| 4. 互斥量 Mutex | 特殊的二值信号量，解决优先级反转，见第三节 | `rt_mutex_take()` / `rt_mutex_release()` |

> 方式 1、2 属于**底层（硬件 / 调度器级）**的临界区保护：屏蔽或暂停的是"执行权"本身，系统基本不为线程服务。方式 3、4 属于**软件级（内核 IPC 对象）**的资源保护：线程只是被挂起等待，系统仍在正常调度运行。前者最"重"、开销与风险最大，后者更轻量、可控，是日常多用的方案。

## 三、核心三件套：信号量 / 互斥量 / 事件集

### 3.1 信号量（Semaphore）

- **本质**：基于计数器的同步机制，每个对象有一个计数值 `value` 和一个线程等待队列。
- **特性**
  - 计数值范围：**0 ~ 65535**
  - 支持阻塞 / 非阻塞获取
  - 等待模式：`RT_IPC_FLAG_FIFO`（先进先出）、`RT_IPC_FLAG_PRIO`（按优先级）
  - **允许在中断上下文释放**（与互斥量的关键区别）
- **停车场模型**
  - `value = N` → 有 N 个空位，线程可进入
  - `value = 0` → 已满，新线程挂起到等待队列
  - 线程离开（释放）→ `value++`，唤醒等待队列中的一个线程
- **核心 API**

  ```c
  rt_sem_t rt_sem_create(const char *name, rt_uint32_t value, rt_uint8_t flag);

  rt_err_t rt_sem_take(rt_sem_t sem, rt_int32_t time);
  /* time: RT_WAITING_FOREVER 永久阻塞 / RT_WAITING_NO 非阻塞立即返回 / N 等待 N 个 tick */

  rt_err_t rt_sem_release(rt_sem_t sem);
  ```

- **四大应用场景**
  1. **线程同步** — 线程 A 完成工作后 `release`，线程 B `take` 等待。
  2. **锁** — 二值信号量（`value=0/1`）保护临界区（不推荐，优先用互斥量）。
  3. **中断与线程同步** — ISR 中 `rt_sem_release()`，线程中 `rt_sem_take()`。
  4. **资源计数** — `value=N` 表示 N 个同类资源可用。

### 3.2 互斥量（Mutex）—— 解决优先级反转

- **本质**：一种特殊的二值信号量，但有三个关键差异：

| 特性 | 信号量 | 互斥量 |
| :-- | :-- | :-- |
| 计数值 | 0 ~ 65535 | 仅 0 或 1 |
| 释放者 | 任何线程都可释放 | 必须由持有线程释放 |
| 递归获取 | 不支持（会死锁） | 支持（持有线程可重复获取） |
| 优先级反转 | 存在此问题 | 有优先级继承机制解决 |

- **优先级继承原理**
  1. 低优先级线程 A 持有锁。
  2. 高优先级线程 C 请求锁 → 被挂起。
  3. 系统临时将 A 的优先级提升到 C 的级别 → 防止中优先级线程 B 抢占 A。
  4. A 尽快执行完临界区并释放锁 → 恢复原始优先级，C 获得锁。
- **核心 API**

  ```c
  rt_mutex_t rt_mutex_create(const char *name, rt_uint8_t flag);

  rt_err_t rt_mutex_take(rt_mutex_t mutex, rt_int32_t time);

  rt_err_t rt_mutex_release(rt_mutex_t mutex);  /* 必须由持有者调用 */
  ```

- **使用原则**：保护临界区、防止优先级反转 → 用互斥量；资源计数、ISR 通知线程 → 用信号量。

### 3.3 事件集（Event）

- **本质**：一个 32 位无符号整数，每一位代表一个事件，可实现**一对多、多对多**的同步。
- **特性**
  - 一个线程可以等"任意一个事件"（逻辑**或**）或"全部事件都到达"（逻辑**与**）。
  - 一个事件可以唤醒多个等待线程。
  - 适合多事件组合触发场景。
- **核心 API**

  ```c
  rt_err_t rt_event_send(rt_event_t event, rt_uint32_t set);

  rt_err_t rt_event_recv(rt_event_t event,
                         rt_uint32_t set,
                         rt_uint8_t option,
                         rt_int32_t timeout,
                         rt_uint32_t *recved);
  /* option: RT_EVENT_FLAG_AND / RT_EVENT_FLAG_OR / RT_EVENT_FLAG_CLEAR */
  ```

- **示例（多事件组合）**
  - 线程 3：每计数 10 次发送信号量。
  - 线程 4：收到信号量后对 `number+1`，加到 10 后亮蓝灯并发送**事件 5**。
  - 线程 5：用 `rt_event_recv()` 同时等**事件 3 和事件 5 都到达**，才报告 `"all over"`。

## 四、延伸：线程间通信（传数据）

### 4.1 邮箱（Mailbox）

- 专为传递小规模数据（通常是一个 `unsigned long`）设计。
- 内部由**环形缓冲区 + 等待链表 + 超时定时器**实现。
- **容量由 `rt_mb_create(name, size, flag)` 的 `size` 参数指定**（即邮箱可容纳的邮件封数），并非固定 5 个；每封邮件固定为 4 字节（一个 `unsigned long`）。
- 例：`rt_mb_create("mbox", 5, ...)` 创建 5 封容量的邮箱，也可设为 32 等任意值，看应用需要。

### 4.2 消息队列（Message Queue）

- 由固定数量的**消息块**组成，每块存固定长度数据。
- 维护两个独立等待链表：`Send List`（等写入）和 `Receive List`（等读取）。
- 写操作：写入**队尾**；读操作：从**队首**读取。
- 多线程竞争时支持 **FIFO 或 PRIO** 策略。
- 唤醒机制：写入时唤醒 `Receive List` 队首线程；读出时唤醒 `Send List` 队首线程。

## 五、重点速记

**同步 vs 互斥**

> 同步 = 控制执行顺序；互斥 = 临界区排他访问（互斥是一种特殊同步）。

**三件套选择**

| 机制 | 适用场景 |
| :-- | :-- |
| 信号量 | 资源计数 / 线程同步 / ISR→线程通知 |
| 互斥量 | 保护临界区 / 防优先级反转（支持递归、仅持有者释放） |
| 事件集 | 一对多、多对多同步（32 位事件位图，AND/OR 逻辑） |

**关键数字**

| 项 | 值 |
| :-- | :-- |
| 信号量计数值范围 | 0 ~ 65535 |
| 事件集 | 32 位，每位一个事件 |
| 邮箱 | 每封 4 字节（`unsigned long`）；容量由 `rt_mb_create` 的 `size` 参数指定（非固定 5） |

**等待模式**

- `RT_IPC_FLAG_FIFO` → 先进先出
- `RT_IPC_FLAG_PRIO` → 高优先级线程先获取

**超时参数**

- `RT_WAITING_FOREVER` → 永久阻塞
- `RT_WAITING_NO` → 非阻塞立即返回
- `N` → 等待 N 个 tick

**易错点**

1. 信号量可由**任何线程**释放，互斥量只能由**持有线程**释放。
2. 互斥量支持**递归获取**，信号量不支持（递归获取会死锁）。
3. 信号量可在**中断中释放**，互斥量**不能**。
4. 全局变量**不能**直接用于 IPC——无法解决竞态条件。
