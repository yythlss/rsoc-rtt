## 一、STM32F407 启动流程与 RT-Thread 引导机制

### 1.1 从上电到 `main()` 的完整调用链

STM32F407 上电后，CPU 从**向量表**（默认位于 `0x08000000`，即 Flash 起始地址）开始执行。以下为完整调用链：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 上电复位                                                           │
│   │                                                                │
│   ▼                                                                │
│ 1. CPU 从 0x00000000 读取  MSP（主栈指针）                          │
│ 2. CPU 从 0x00000004 读取  Reset_Handler 地址 → 跳转执行            │
│   │                                                                │
│   ▼                                                                │
│ 3. Reset_Handler (startup_stm32f407xx.s)                            │
│    ├─ 调用 SystemInit()     —— 配置系统时钟(HSE→PLL→168MHz)         │
│    ├─ 使能 CCM SRAM 时钟    —— 可选                              │
│    ├─ 初始化 .data 段       —— 从 Load 区复制到 RAM                 │
│    ├─ 清零 .bss 段          —— 初始化为 0                          │
│    └─ 调用 entry()/main()   —— 跳转到 C 世界                       │
│   │                                                                │
│   ▼                                                                │
│ 4. entry() / main()  (RT-Thread 接管)                              │
│    ├─ rtthread_startup()                                          │
│    │   ├─ rt_hw_interrupt_disable()   —— 关闭总中断               │
│    │   ├─ rt_hw_board_init()           —— 板级初始化               │
│    │   │   ├─ 系统节拍定时器 HAL_Init/SysTick_Config               │
│    │   │   ├─ 引脚复用 GPIO/USART 初始化                           │
│    │   │   └─ 动态内存堆初始化(rt_system_heap_init)                │
│    │   ├─ rt_show_version()            —— 打印 RT-Thread 版本      │
│    │   ├─ rt_system_timer_init()       —— 软件定时器初始化         │
│    │   ├─ rt_system_scheduler_init()   —— 调度器初始化             │
│    │   ├─ [自动初始化: INIT_BOARD_EXPORT]                          │
│    │   ├─ rt_application_init()        —— 创建主线程(main thread)  │
│    │   │   └─ 创建线程: main_thread，入口 main_thread_entry        │
│    │   ├─ [自动初始化: INIT_PREV_EXPORT → INIT_DEVICE_EXPORT]      │
│    │   ├─ rt_system_timer_thread_init() —— 定时器线程初始化        │
│    │   ├─ rt_thread_idle_init()         —— 空闲线程初始化          │
│    │   ├─ [自动初始化: INIT_COMPONENT_EXPORT → INIT_ENV_EXPORT]    │
│    │   ├─ rt_system_scheduler_start()  —— 启动调度器               │
│    │   │   └─ 触发 PendSV → 切换到最高优先级线程                   │
│    │   └─ (永不返回)                                               │
│   │                                                                │
│   ▼                                                                │
│ 5. main_thread_entry 中调用 main()  (应用层 main 函数)              │
│    └─ [自动初始化: INIT_APP_EXPORT] 在此之后执行                    │
└─────────────────────────────────────────────────────────────────────┘
```

#### 关键汇编启动文件说明

文件 `startup_stm32f407xx.s` 中定义了向量表：

```assembly
; 向量表起始地址
__Vectors       DCD     __initial_sp          ; 0x00000000: 栈顶指针
                DCD     Reset_Handler          ; 0x00000004: 复位入口
                DCD     NMI_Handler            ; 不可屏蔽中断
                DCD     HardFault_Handler      ; 硬 fault
                ...                            ; 其他中断向量
```

`Reset_Handler` 简化的伪代码逻辑：

```c
void Reset_Handler(void)
{
    SystemInit();                      // 设置时钟: HSE 8MHz → PLL → SYSCLK 168MHz
    /* 复制 .data 段 */
    for (src = _sidata, dst = _sdata; dst < _edata;)
        *dst++ = *src++;
    /* 清零 .bss 段 */
    for (dst = _sbss; dst < _ebss;)
        *dst++ = 0;
    /* 调用 C 运行时入口 */
    entry();  // 或直接跳 main()
}
```

### 1.2 自动初始化机制原理

RT-Thread 的自动初始化通过**链接器段（section）放置** + **宏定义封装** 实现，无需手动逐一调用初始化函数。

#### 宏定义层级

| 宏 | 初始化阶段 | 调用顺序 | 典型用途 |
|---|---|---|---|
| `INIT_BOARD_EXPORT(fn)` | 板级初始化 | 第 1 阶段 | 时钟、GPIO、UART |
| `INIT_PREV_EXPORT(fn)` | 纯内核组件 | 第 2 阶段 | 内核数据结构 |
| `INIT_DEVICE_EXPORT(fn)` | 设备驱动 | 第 3 阶段 | 外设驱动注册 |
| `INIT_COMPONENT_EXPORT(fn)` | 组件初始化 | 第 4 阶段 | 文件系统、网络协议栈 |
| `INIT_ENV_EXPORT(fn)` | 环境初始化 | 第 5 阶段 | 系统服务 |
| `INIT_APP_EXPORT(fn)` | 应用初始化 | 第 6 阶段 | 用户应用入口 |

#### 底层实现原理

以 `INIT_BOARD_EXPORT` 为例，宏展开过程如下：

```c
// 定义宏
#define INIT_BOARD_EXPORT(fn)                                           \
    RT_USED const init_fn_t __rt_init_##fn RT_SECTION(".rti_fn." #fn) = fn

// 用户写一行:
INIT_BOARD_EXPORT(hw_usart_init);

// 预处理器展开为:
RT_USED const init_fn_t __rt_init_hw_usart_init 
    __attribute__((section(".rti_fn.0"))) = hw_usart_init;
```

关键点：

- `RT_SECTION(".rti_fn.0")` 将该函数指针放入 ELF 文件的一个**自定义段** `.rti_fn.0`。
- 数字后缀 `0`~`5` 控制链接时的**段排列顺序**（`0` = BOARD，`5` = APP）。
- 链接器将所有 `.rti_fn.X` 段连续排列在内存中，形成一张**函数指针表**。
- 启动时 `rt_components_board_init()` 遍历该表，依次调用每个函数指针：

```c
// 组件初始化入口
static int rti_start(void)     { return 0; }
static int rti_board_start(void)   { return 0; }
static int rti_board_end(void)     { return 0; }
static int rti_end(void)       { return 0; }

INIT_EXPORT(rti_start, "0");           // 段起始标记
INIT_BOARD_EXPORT(rti_board_start);   // 板级起始
INIT_BOARD_EXPORT(rti_board_end);     // 板级结束
INIT_EXPORT(rti_end, "5");           // 段结束标记
```

遍历函数：

```c
void rt_components_board_init(void)
{
    const init_fn_t *fn_ptr;
    // 从 .rti_fn.0 段的起始 → 结束遍历
    for (fn_ptr = &__rt_init_rti_board_start;
         fn_ptr < &__rt_init_rti_board_end;
         fn_ptr++)
    {
        (*fn_ptr)();  // 依次调用每个初始化函数
    }
}
```

**优点**：开发者只需一行宏，函数自动在正确阶段被调用，无需手动维护初始化列表。
**段名数字对应关系**：`0`→BOARD, `1`→PREV, `2`→DEVICE, `3`→COMPONENT, `4`→ENV, `5`→APP。

## 二、内核基础与对象模型

### 2.1 面向对象的设计思想

RT-Thread 内核使用**面向对象（OOP）** 思想设计，但通过 C 语言实现。核心概念：

- **对象（Object）**：所有内核实体（线程、信号量、互斥锁、消息队列、事件、定时器、内存池等）的抽象基类。
- **对象容器（Object Container）**：一个全局链表数组，按对象类型分类管理所有对象。
- **对象控制块（Object Control Block）**：`struct rt_object`，每个内核对象的"头部"。

```
对象容器结构示意:

rt_object_container[8]         每个容器管理一种类型
┌──────────────────┐
│ RT_Object_Class_Thread  │──→ 线程链表
│ RT_Object_Class_Semaphore│──→ 信号量链表
│ RT_Object_Class_Mutex    │──→ 互斥锁链表
│ RT_Object_Class_Event    │──→ 事件链表
│ RT_Object_Class_MsgQueue │──→ 消息队列链表
│ RT_Object_Class_Timer    │──→ 定时器链表
│ RT_Object_Class_MemPool  │──→ 内存池链表
│ RT_Object_Class_Device   │──→ 设备链表
└──────────────────┘

每个对象继承自:
struct rt_object {
    char       name[RT_NAME_MAX];   // 对象名称
    rt_uint8_t type;                // 对象类型
    rt_uint8_t flag;                // 标志位(静态/动态)
    rt_list_t  list;                // 挂入容器的链表节点
};
```

### 2.2 线程控制块 `struct rt_thread`

每个线程由一个线程控制块（TCB）描述，其关键成员及作用：

```c
struct rt_thread {
    /* 继承自 rt_object */
    char       name[RT_NAME_MAX];   // 线程名称
    rt_uint8_t type;                // 对象类型 = RT_Object_Class_Thread
    rt_uint8_t flags;               // 标志位
    rt_list_t  list;                // 全局对象链表节点

    /* 栈相关信息 */
    rt_uint8_t *stack_addr;         // 栈起始地址（静态分配时指向用户提供的栈空间）
    rt_uint32_t stack_size;         // 栈大小（字节）

    /* 状态与优先级 */
    rt_uint8_t  stat;               // 线程当前状态（RT_THREAD_INIT/READY/RUNNING/SUSPEND/CLOSE）
    rt_uint8_t  current_priority;   // 当前优先级（可能因优先级继承而临时提升）
    rt_uint8_t  init_priority;      // 初始优先级（创建时设定的原始优先级）
    rt_uint32_t number_mask;        // 位图掩码，用于快速查找就绪线程

    /* 时间相关 */
    rt_tick_t   init_tick;          // 每次挂起时的超时期限（tick 数）
    rt_tick_t   remaining_tick;     // 时间片轮转剩余 tick

    /* 寄存器上下文 */
    rt_ubase_t  sp;                 // 栈指针（保存线程被切换出时的 CPU 寄存器现场）
    void        *entry;             // 线程入口函数地址
    void        *parameter;         // 入口参数

    /* 内核对象链表 */
    rt_list_t   tlist;              // 就绪/挂起链表节点
};
```

**关键成员详解**：

| 成员 | 作用 |
|---|---|
| `stat` | 线程的五态标志（`RT_THREAD_INIT` / `READY` / `RUNNING` / `SUSPEND` / `CLOSE`）。调度器通过此字段判断线程是否可参与调度。 |
| `current_priority` | 当前优先级。一般情况下等于 `init_priority`，但当互斥锁发生**优先级继承**时，此值会被临时提升，避免优先级反转。 |
| `init_priority` | 创建线程时设定的原始优先级，不随优先级继承而改变。 |
| `init_tick` | 线程主动挂起时指定的超时时间（单位：系统 tick）。当线程调用 `rt_thread_delay()` 或 `rt_sem_take()` 等阻塞 API 时，此值决定最长等待时间。 |
| `sp` | 栈指针。保存了线程被切换出 CPU 时，所有需要恢复的寄存器值（R4-R11, PC, LR, xPSR 等）。这是**上下文切换**的核心数据。 |

### 2.3 静态对象 vs 动态对象

| 对比维度 | 静态对象 | 动态对象 |
|---|---|---|
| **分配位置** | `.bss` / `.data` 段（编译时已确定地址） | 堆（Heap）区域（运行时动态分配） |
| **分配方式** | 定义全局变量，宏 `rt_thread_t` 传入栈和控制块 | 调用 `rt_thread_create()` 等 API |
| **生命周期** | 与程序共存亡，不能手动释放 | 可调用 `rt_thread_delete()` 动态释放 |
| **释放机制** | 不需要（也不能）释放 | 释放后内存归还堆 |
| **创建速度** | 极快（编译期已完成） | 较慢（需 malloc/free） |
| **内存碎片** | 不产生碎片 | 高频创建/销毁可能产生碎片 |

**示例对比**：

```c
/* 静态线程 —— 内存由编译器分配 */
static rt_uint8_t stack_static[1024];      // 栈空间在 .bss 段
static struct rt_thread tcb_static;        // 控制块在 .bss 段

rt_thread_init(&tcb_static, "static",      // 传入已存在的控制块和栈
               thread_entry, NULL,
               stack_static, sizeof(stack_static),
               20, 10);

/* 动态线程 —— 运行时从堆分配 */
rt_thread_t tcb_dynamic = rt_thread_create("dynamic",
    thread_entry, NULL,
    1024,           // 栈大小
    20,             // 优先级
    10);            // 时间片
```

#### 高可靠场景为何强制使用静态线程？

在以下场景中，必须使用静态线程（`rt_thread_init`）：

1. **航空/航天/车规级系统**：不允许动态内存分配（MISRA-C 规则），避免 malloc 失败或碎片导致系统不可预测。
2. **中断上下文**：中断中不能阻塞（不能调用 malloc），因此只能在初始化阶段预先分配好所有线程。
3. **硬实时系统**：动态分配的时间不确定（首次分配可能慢，碎片时更慢），静态分配可保证 O(1) 确定性。
4. **无堆配置**：Nano 版本或精简配置可能关闭堆，动态对象无法工作。
5. **安全关键系统**：需要证明内存使用不会超过上限，静态分配使内存占用在编译期即可计算。

## 三、线程状态机与调度算法

### 3.1 五态模型

RT-Thread 线程的生命周期分为五个状态，状态转换如下图所示：

```
                          ┌─────────────┐
                          │  初始态(INIT) │
                          └──────┬──────┘
                                 │ rt_thread_startup()
                                 ▼
  ┌─────────────────────────────────────────────────┐
  │                    就绪态(READY)                  │
  │  (已具备运行条件，等待调度器选中)                    │
  └──┬──────────────┬──────────────┬────────────────┘
     │              │              │
     │调度器选中     │ 抢占         │ 主动让出 CPU
     ▼              │              │
  ┌──────────┐      │              │
  │ 运行态    │──────┘              │
  │ (RUNNING) │                    │
  └──┬───────┘                     │
     │                             │
     │ 阻塞事件(等待信号量/消息队列等) │
     │ 或主动延时                    │
     ▼                             │
  ┌──────────────┐                 │
  │  挂起态(SUSPEND) │◄────────────┘
  │  (等待资源或超时) │
  └──────┬───────┘
         │ 超时结束 / 资源就绪 / 事件到达
         │ (rt_sem_release / rt_event_send / rt_mb_send)
         ▼
  ┌──────────────┐
  │  就绪态(READY) │  (重新进入调度)
  └──────────────┘

  ┌──────────────┐
  │  关闭态(CLOSE) │  ← 线程结束 / rt_thread_delete
  │  (资源待回收)  │
  └──────────────┘
```

#### 状态转换触发 API 一览

| 当前状态 | 目标状态 | 触发 API | 说明 |
|---|---|---|---|
| — | 初始态 | `rt_thread_init()` / `rt_thread_create()` | 创建线程对象，分配栈和控制块 |
| 初始态 | 就绪态 | `rt_thread_startup()` | 将线程插入就绪队列 |
| 就绪态 | 运行态 | 调度器选择 | PendSV 中切换上下文 |
| 运行态 | 就绪态 | `rt_thread_yield()` | 主动让出 CPU |
| 运行态 | 就绪态 | 时间片耗尽 | 被动让出 CPU |
| 运行态 | 就绪态 | 被更高优先级线程抢占 | 调度器剥夺当前线程 |
| 运行态 | 挂起态 | `rt_thread_delay()` / `rt_sem_take()` / `rt_mq_recv()` / `rt_event_recv()` | 等待资源或超时 |
| 挂起态 | 就绪态 | `rt_sem_release()` / `rt_mq_send()` / `rt_event_send()` / 超时到达 | 资源就绪或等待超时 |
| 挂起态 | 就绪态 | `rt_thread_resume()` | 强制唤醒 |
| 运行态 | 关闭态 | `rt_thread_exit()` / 入口函数返回 | 线程自然结束 |
| 就绪/挂起态 | 关闭态 | `rt_thread_delete()` / `rt_thread_detach()` | 主动删除线程 |

### 3.2 调度机制剖析

#### 3.2.1 抢占式调度（Preemptive Scheduling）

**定义**：当系统中出现一个优先级**更高**的线程进入就绪态时，调度器立即**剥夺**当前正在运行线程的 CPU 使用权，切换给更高优先级的线程。

**实现原理**：

```
时间轴 ──────────────────────────────────────────────────►
        低优先级线程 A(prio=20)  高优先级线程 B(prio=5)

  A 运行 ──┬─────────────────────────────────────────────
           │
           │  B 就绪事件发生
           │  (例如中断中释放了 B 等待的信号量)
           │
           ▼ 调度器触发 PendSV
  A 抢占 ──┼──── 挂起 A ──→ 恢复 B ─────────────────────
           │
           │  B 运行中（可能主动挂起或完成工作）
           │
           ▼ 调度器再次触发 PendSV
  A 恢复 ──┼──────────────────── 恢复 A ─────────────────
           │
```

**关键代码路径**（`scheduler.c` 核心逻辑）：

```c
void rt_schedule(void)
{
    struct rt_thread *to_thread;
    struct rt_thread *from_thread;

    // 1. 找到就绪队列中优先级最高的线程
    to_thread = rt_list_entry(rt_thread_priority_table[highest_ready_priority].next,
                              struct rt_thread, tlist);

    // 2. 如果当前不是最高优先级线程，则切换
    if (to_thread != rt_current_thread)
    {
        rt_current_thread = to_thread;

        // 3. 触发 PendSV 异常，在异常处理中完成上下文切换
        rt_hw_context_switch((rt_ubase_t)&from_thread->sp,
                             (rt_ubase_t)&to_thread->sp);
    }
}
```

**PendSV 中的上下文切换**（简化汇编）：

```assembly
; PendSV_Handler — 切换线程上下文
rt_hw_context_switch:
    ; 保存当前线程的寄存器到栈
    MRS     r0, PSP                    ; 获取当前栈指针
    STMFD   r0!, {r4-r11}             ; 保存 R4~R11
    STR     r0, [r2]                   ; 更新线程控制块的 sp 成员

    ; 恢复目标线程的寄存器
    LDR     r0, [r3]                   ; 读取目标线程的 sp
    LDMFD   r0!, {r4-r11}             ; 恢复 R4~R11
    MSR     PSP, r0                    ; 更新栈指针

    ; 异常返回时自动恢复 PC, xPSR, LR 等
    BX      LR
```

**特点**：
- 实时性高：高优先级任务能**立即**响应外部事件。
- 保障确定性：最高优先级任务的响应时间只受中断延迟影响，不受其他任务影响。
- 但需注意：不合理的优先级分配可能导致**低优先级任务饿死**（starvation）。

#### 3.2.2 时间片轮转（Round-Robin）

**定义**：**相同优先级**的多个线程，按照时间片轮流占用 CPU。每个线程运行一个时间片长度后，调度器强制切换到同优先级的下一个就绪线程。

**时间片单位**：系统 tick（通常由 SysTick 定时器产生，STM32F407 上配置为 1000Hz，即 1 tick = 1 ms）。

**实现原理**：

```
时间轴 ──────────────────────────────────────────────────►
        线程 A (prio=20, timeslice=10 ticks)
        线程 B (prio=20, timeslice=10 ticks)
        线程 C (prio=20, timeslice=10 ticks)

  A 运行 ──┬──────────────────────┬──────────────────────
           │  A 运行中             │  A 时间片耗尽
           │                      ▼  SysTick 中断中处理
           │                      调度器选到 B
  B 运行 ──┼──────────────────────┬──────────────────────
           │                      │  B 时间片耗尽
           │                      ▼  调度器选到 C
  C 运行 ──┼──────────────────────┬──────────────────────
           │                      │  C 时间片耗尽
           │                      ▼  调度器选到 A(循环)
```

**SysTick 中断中时间片处理**：

```c
void rt_tick_increase(void)
{
    struct rt_thread *thread;

    ++rt_tick;                       // 系统 tick 计数 +1

    thread = rt_current_thread;

    // 仅对当前线程递减时间片
    if (thread->remaining_tick > 0)
        --thread->remaining_tick;    // 时间片递减

    // 时间片耗尽，且就绪队列中还有同优先级线程
    if (thread->remaining_tick == 0)
    {
        // 重置时间片
        thread->remaining_tick = thread->init_tick;

        // 将当前线程移到就绪队列末尾
        rt_schedule();               // 触发调度
    }
}
```

**关键规则**：

| 规则 | 说明 |
|---|---|
| 仅相同优先级生效 | 如果当前线程是最高优先级 & 唯一就绪，时间片耗尽后原地继续运行 |
| 时间片重置 | 每次切换到某线程时，`remaining_tick` 重新赋值为 `init_tick` |
| 抢占打断时间片 | 若高优先级线程抢占，当前线程被挂起，恢复后**剩余时间片不变**（不重置） |
| 0 表示无限 | 如果创建线程时时间片 = 0，则该线程不限时运行（直到被抢占或主动挂起） |

#### 3.2.3 就绪优先级位图算法（核心优化）

RT-Thread 的调度器使用**位图（bitmap）** 算法实现 O(1) 时间复杂度的优先级查找，这是 RT-Thread 调度性能的核心优势。

```c
#define RT_THREAD_PRIORITY_MAX  32   // 32 优先级

rt_uint32_t rt_thread_ready_priority_group;  // 32 位位图，每位代表一个优先级
rt_list_t rt_thread_priority_table[32];      // 每个优先级对应一个就绪链表

// 将线程加入就绪队列
void rt_schedule_insert_thread(struct rt_thread *thread)
{
    // 在优先级位图中置位
    rt_thread_ready_priority_group |= thread->number_mask;

    // 将线程链入对应优先级的就绪链表末尾
    rt_list_insert_before(&(rt_thread_priority_table[thread->current_priority]),
                          &(thread->tlist));
}

// 从就绪队列移除线程
void rt_schedule_remove_thread(struct rt_thread *thread)
{
    // 从链表中移除
    rt_list_remove(&(thread->tlist));

    // 如果该优先级链表为空，清除位图对应位
    if (rt_list_isempty(&(rt_thread_priority_table[thread->current_priority])))
    {
        rt_thread_ready_priority_group &= ~thread->number_mask;
    }
}

// 查找最高优先级就绪线程（O(1) 核心）
rt_uint8_t rt_schedule_get_highest_priority(void)
{
    // 使用 __builtin_clz (Count Leading Zeros) 快速找到最高位
    return __rt_ffs(rt_thread_ready_priority_group) - 1;
    // 等效于: 31 - __builtin_clz(rt_thread_ready_priority_group)
}
```

**位图查找原理**：

```
rt_thread_ready_priority_group (32-bit)

bit: 31 ... 5 4 3 2 1 0
     ┌─────────────────────┐
     │ ... 0 1 0 1 0 0 1 0 │  (= 0x...0016)
     └─────────────────────┘
              ↑     ↑
              │     └── 优先级 1 有线程就绪
              └──────── 优先级 3 有线程就绪

__rt_ffs(0x0016) = 2 → 最高优先级 = 2-1 = 1
```

**为什么要用 `__rt_ffs` 减 1**：`__rt_ffs` 返回最低位 1 的位置（从 1 开始计数），所以减 1 得到实际的优先级编号。

### 3.3 调度器工作流程总结

```
由事件触发调度
─────────────────────────────────────────────────
        │
        ▼
   rt_schedule()
        │
        ├─ 关中断 (rt_hw_interrupt_disable)
        ├─ 从位图找到最高优先级线程
        ├─ 与当前线程比较
        │   ├─ 相同 → 不变，开中断返回
        │   └─ 不同 → 触发 PendSV
        └─ 开中断 (rt_hw_interrupt_enable)

PendSV_Handler (异常上下文)
─────────────────────────────────────────────────
        │
        ▼
   rt_hw_context_switch()
        │
        ├─ 保存当前线程寄存器 (R4~R11, PSP)
        ├─ 更新 sp 到线程控制块
        ├─ 从目标线程控制块加载 sp
        ├─ 恢复目标线程寄存器 (R4~R11, PSP)
        └─ 异常返回，切换到新线程
```

> **小结**：RT-Thread 的调度器采用**基于优先级的全抢占式 + 同优先级时间片轮转**策略。就绪队列通过位图算法实现 O(1) 查找，确保系统在任意负载下都有确定的调度延迟。理解启动流程、对象模型和调度机制，是后续深入学习 RT-Thread 驱动开发、中断管理和同步机制的基础。
