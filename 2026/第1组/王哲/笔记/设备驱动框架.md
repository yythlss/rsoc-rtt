# 设备驱动框架

## RT-Thread 设备驱动框架分层

RT-Thread 的设备驱动框架可以理解成一套**统一设备模型**。

上层应用程序不直接关心 STM32、NXP、GD32 等具体芯片的寄存器和外设差异，而是通过 RT-Thread 提供的统一设备接口访问硬件。

![image-20260820220149251](E:\笔记\rtthread\设备驱动框架.assets\image-20260820220149251.png)

整体结构如下：

```text
应用程序
  ↓
I/O 设备管理层：rt_object / rt_device
  ↓
设备驱动框架层：rt_serial_device / rt_adc_device / rt_xxx_device
  ↓
设备驱动层：drv_usart.c / drv_adc.c / drv_xxx.c
  ↓
SDK / HAL / LL
  ↓
硬件
```

---

## 1. 应用程序层

应用程序层是最上层，负责真正使用设备。

应用程序一般不会直接操作寄存器，也不会直接调用具体芯片的 HAL 接口，而是使用 RT-Thread 的标准设备 API。

常见接口有：

```c
rt_device_find();
rt_device_open();
rt_device_read();
rt_device_write();
rt_device_control();
rt_device_close();
```

例如应用程序要使用串口，只需要通过设备名找到 `"uart1"`，然后调用 `rt_device_write()` 发送数据。

应用层不需要关心底层到底是 STM32 UART、GD32 UART，还是其他芯片的 UART。

这一层的作用：

- 使用设备。
- 通过统一 API 访问不同硬件。
- 屏蔽具体芯片和外设实现差异。

---

## 2. I/O 设备管理层

I/O 设备管理层是 RT-Thread 设备模型的核心。

图中主要对应：

```text
rt_object
  ↓
rt_device
```

`rt_object` 是 RT-Thread 内核对象的基类。线程、信号量、定时器、设备等都可以看作 RT-Thread 的对象。

`rt_device` 是所有设备的基类，所有具体设备最终都要抽象成一个 `rt_device`。

不管是串口、ADC、SPI、I2C、PWM、CAN，最终都可以通过 `rt_device` 统一管理。

`rt_device` 中通常包含：

- 设备名称。
- 设备类型。
- 设备状态。
- 引用计数。
- 设备操作函数，例如 `open`、`close`、`read`、`write`、`control`。
- 设备注册、查找、管理机制。

这一层的作用：

- 管理系统中的所有设备对象。
- 提供统一的设备访问接口。
- 支持设备注册、查找、打开、关闭、读写、控制。
- 向上屏蔽不同设备类型的差异。

---

## 3. 设备驱动框架层

设备驱动框架层是在 `rt_device` 基础上，针对某一类设备做进一步封装。

图中对应：

```text
rt_serial_device
rt_adc_device
rt_xxx_device
```

这些结构体代表不同类型的设备类。

例如：

- `rt_serial_device`：串口设备类，对应 `serial.c`。
- `rt_adc_device`：ADC 设备类，对应 `adc.c`。
- `rt_xxx_device`：其他类型设备类，对应 `xxx.c`。

以串口为例，`rt_serial_device` 会在 `rt_device` 的基础上增加串口专用内容，例如：

- 波特率。
- 数据位。
- 停止位。
- 校验位。
- 接收缓冲区。
- 发送接口。
- 中断接收。
- DMA 发送或接收。

ADC 设备类则会封装 ADC 通道读取、使能、配置等通用逻辑。

这一层的作用：

- 定义某一类设备的统一驱动模型。
- 提供该类设备的通用处理逻辑。
- 把上层统一设备接口和下层具体硬件驱动连接起来。
- 让不同芯片的同类外设遵循同一套 RT-Thread 框架。

例如 STM32 UART 和其他芯片 UART 的硬件实现不同，但它们都可以接入 `rt_serial_device` 框架。

这样应用层使用串口时，代码基本保持一致。

---

## 4. 设备驱动层

设备驱动层是真正和具体芯片、具体外设相关的代码。

图中对应：

```text
bsp/stm32/drv_usart.c
bsp/stm32/drv_adc.c
bsp/stm32/drv_xxx.c

bsp/xxx/drv_usart.c
bsp/xxx/drv_adc.c
bsp/xxx/drv_xxx.c
```

这一层负责把具体芯片外设适配到 RT-Thread 的设备驱动框架中。

例如 STM32 的串口驱动 `drv_usart.c` 通常会做这些事情：

- 配置 UART 引脚复用。
- 初始化 UART 外设。
- 配置串口中断。
- 配置 DMA。
- 调用 STM32 HAL / LL 接口发送和接收数据。
- 实现 RT-Thread 串口框架要求的底层操作函数。
- 把具体串口注册为 RT-Thread 设备，例如 `"uart1"`。

串口驱动一般会提供类似这些底层操作：

```c
configure
control
putc
getc
dma_transmit
```

然后 RT-Thread 的 `serial.c` 会通过这些函数操作具体硬件。

这一层的作用：

- 适配具体芯片。
- 调用厂商 SDK / HAL / LL。
- 实现具体外设的初始化和操作。
- 把硬件外设注册成 RT-Thread 标准设备。

---

## 5. SDK / HAL / LL 层

SDK / HAL / LL 层通常由芯片厂商提供。

例如 STM32 中常见的：

```text
标准外设库
HAL 库
LL 库
```

这些库对底层寄存器进行了封装。

常见接口如：

```c
HAL_UART_Init();
HAL_UART_Transmit();
HAL_ADC_Start();
HAL_ADC_GetValue();
```

RT-Thread 的 BSP 驱动层可以调用这些接口完成硬件操作，而不一定要自己直接写寄存器。

这一层的作用：

- 封装芯片寄存器。
- 提供厂商标准外设接口。
- 降低驱动开发难度。
- 提高不同项目之间的代码复用性。

---

## 6. 硬件层

硬件层就是实际 MCU 内部或外部的硬件资源。

例如：

- UART
- ADC
- SPI
- I2C
- PWM
- GPIO
- CAN
- Ethernet

这一层是真正产生电平、采样模拟信号、发送数据、接收数据的物理硬件。

---

## 串口调用链示例

以串口发送数据为例，调用过程大致如下：

```text
应用程序调用 rt_device_write(uart1, ...)
        ↓
RT-Thread 根据设备名找到 uart1 对应的 rt_device
        ↓
进入 serial.c 串口设备框架
        ↓
调用 stm32 drv_usart.c 提供的 putc / dma_transmit 等底层函数
        ↓
drv_usart.c 调用 STM32 HAL / LL 接口，或者直接操作寄存器
        ↓
UART 硬件真正发送数据
```

---

## 总结

RT-Thread 设备驱动框架的核心思想是：

```text
应用层只认 rt_device，
设备框架层负责统一模型，
BSP 驱动层负责适配具体芯片，
HAL / LL 层负责操作寄存器，
硬件层负责真正执行。
```

这样做的好处是：

- 应用程序和具体硬件解耦。
- 同一类设备具有统一访问方式。
- 更容易移植到不同芯片平台。
- BSP 驱动只需要适配底层硬件，上层应用基本不用改。

一句话总结：

> RT-Thread 用 `rt_device` 把各种硬件统一抽象成设备，上层通过统一 API 使用设备，下层由具体 BSP 驱动负责适配真实硬件。

## PDF 补充

PDF 的核心思路是：**驱动框架是为了解决驱动开发碎片化和代码复用问题**。

如果没有统一驱动框架，不同厂商 MCU 的外设 API 完全不同。

例如同样是 SPI 发送：

```text
GD:  spi_i2s_data_transmit
ST:  HAL_SPI_Transmit
NXP: LPSPI_MasterTransferBlocking
LPC: SPI_MasterTransferBlocking
```

如果应用和外设芯片驱动直接依赖这些厂商 API，那么换 MCU 时，W25Q128、RW007、SHT30 等设备驱动很可能要重写。

RT-Thread 设备框架的设计目标就是：

- 把 MCU 外设驱动和外部设备驱动分离。
- 对同一类外设提供统一 API。
- MCU 更换时，只替换 BSP 对接驱动。
- 外部设备驱动可以复用成软件包 Package。
- 应用层不用直接关心底层 HAL / LL / 寄存器。

简单理解：

```text
没有框架：
应用 / 设备驱动 直接调用 STM32 HAL、LPC SDK、NXP SDK
换芯片时容易重写

有框架：
应用 / 设备驱动 调用 RT-Thread 统一 API
底层由不同 BSP 驱动适配具体芯片
```

## 设备分类

RT-Thread 会对 I/O 设备分类，不同设备类型适合不同上层组件使用。

常见设备类型：

```text
RT_Device_Class_Char       字符设备
RT_Device_Class_Block      块设备
RT_Device_Class_NetIf      网络接口设备
RT_Device_Class_MTD        MTD 存储设备
RT_Device_Class_CAN        CAN 设备
RT_Device_Class_RTC        RTC 设备
RT_Device_Class_Sound      声卡 / 音频设备
RT_Device_Class_Graphic    图形显示设备
RT_Device_Class_I2CBUS     I2C 总线设备
RT_Device_Class_USBDevice  USB Device
RT_Device_Class_USBHost    USB Host
RT_Device_Class_SPIBUS     SPI 总线设备
RT_Device_Class_SPIDevice  SPI 从设备
RT_Device_Class_SDIO       SDIO 设备
RT_Device_Class_PM         电源管理设备
RT_Device_Class_Pin        GPIO / Pin 设备
```

### 字符设备和块设备

字符设备：

- 提供连续数据流。
- 一般按字节读写。
- 通常不支持随机访问。
- 典型例子：串口、键盘、调制解调器。

块设备：

- 可以随机访问指定位置的数据。
- 通常按块读写，例如 512 字节。
- 典型例子：SD 卡、Flash、硬盘。
- 文件系统通常依赖块设备，例如 FatFS。

区别：

```text
字符设备：顺序访问，按字节流处理。
块设备：随机访问，按块处理。
```

### 为什么要分类

设备分类的作用：

- MSH 可以重定向到字符设备，比如串口、LCD 模拟字符设备、空字符设备。
- FatFS 依赖块设备，因此 SD 卡、Flash、RAM Disk 都可以按块设备接入。
- 上层组件可以面向一类设备编程，而不是面向具体硬件编程。
- 统一管理后，设备可以通过 `list_device` 查看和调试。

## I/O 设备 API 速记

RT-Thread 的 I/O 设备访问可以分为两类：

- 驱动开发者使用：创建设备、注册设备、实现设备操作函数。
- 应用开发者使用：查找设备、打开设备、读写设备、控制设备、关闭设备。

### 1. 创建和销毁设备

```c
rt_device_t rt_device_create(int type, int attach_size);
void rt_device_destroy(rt_device_t device);
```

作用：

- `rt_device_create()` 用来创建一个设备对象。
- `type` 表示设备类型，例如 `RT_Device_Class_Char`。
- `attach_size` 表示额外附加数据大小。
- `rt_device_destroy()` 用来销毁设备对象。

示例：

```c
rt_device_t test_dev;

test_dev = rt_device_create(RT_Device_Class_Char, 0);
if (test_dev == RT_NULL)
{
    return -RT_ERROR;
}
```

### 2. 注册和注销设备

```c
rt_err_t rt_device_register(rt_device_t dev,
                            const char *name,
                            rt_uint16_t flags);

rt_err_t rt_device_unregister(rt_device_t dev);
```

作用：

- `rt_device_register()` 把设备注册到 RT-Thread 设备管理器。
- 注册后可以通过 `rt_device_find()` 按名称查找。
- `name` 是设备名，例如 `"uart1"`、`"i2c2"`、`"spi20"`、`"test_drv"`。
- `flags` 表示设备支持的访问能力。

常见注册 flags：

```c
RT_DEVICE_FLAG_RDONLY
RT_DEVICE_FLAG_WRONLY
RT_DEVICE_FLAG_RDWR
RT_DEVICE_FLAG_INT_RX
RT_DEVICE_FLAG_DMA_RX
RT_DEVICE_FLAG_INT_TX
RT_DEVICE_FLAG_DMA_TX
RT_DEVICE_FLAG_STREAM
RT_DEVICE_FLAG_REMOVABLE
```

示例：

```c
rt_device_register(test_dev, "test_drv", RT_DEVICE_FLAG_RDWR);
```

### 3. 查找和初始化设备

```c
rt_device_t rt_device_find(const char *name);
rt_err_t rt_device_init(rt_device_t dev);
```

作用：

- `rt_device_find()` 根据设备名查找设备句柄。
- `rt_device_init()` 调用设备底层初始化接口。

示例：

```c
rt_device_t dev;

dev = rt_device_find("test_drv");
if (dev == RT_NULL)
{
    rt_kprintf("can not find device\n");
}
```

### 4. 打开和关闭设备

```c
rt_err_t rt_device_open(rt_device_t dev, rt_uint16_t oflags);
rt_err_t rt_device_close(rt_device_t dev);
```

常见打开标志：

```c
RT_DEVICE_OFLAG_RDONLY
RT_DEVICE_OFLAG_WRONLY
RT_DEVICE_OFLAG_RDWR
RT_DEVICE_OFLAG_INT_RX
RT_DEVICE_OFLAG_DMA_RX
RT_DEVICE_OFLAG_INT_TX
RT_DEVICE_OFLAG_DMA_TX
```

示例：

```c
rt_device_open(dev, RT_DEVICE_OFLAG_RDWR);
rt_device_close(dev);
```

### 5. 读写和控制设备

```c
rt_ssize_t rt_device_read(rt_device_t dev,
                          rt_off_t pos,
                          void *buffer,
                          rt_size_t size);

rt_ssize_t rt_device_write(rt_device_t dev,
                           rt_off_t pos,
                           const void *buffer,
                           rt_size_t size);

rt_err_t rt_device_control(rt_device_t dev,
                           int cmd,
                           void *arg);
```

说明：

- `pos` 对字符设备通常意义不大，对块设备表示偏移位置。
- `buffer` 是读写缓冲区。
- `size` 是读写大小。
- `control` 用于发送设备相关控制命令，例如配置参数。

示例：

```c
rt_device_control(dev, RT_DEVICE_CTRL_CONFIG, RT_NULL);
rt_device_write(dev, 100, RT_NULL, 1024);
rt_device_read(dev, 20, RT_NULL, 128);
```

### 6. 接收和发送完成回调

接收回调：

```c
rt_err_t rt_device_set_rx_indicate(
    rt_device_t dev,
    rt_err_t (*rx_ind)(rt_device_t dev, rt_size_t size));
```

作用：

- 硬件接收到数据时，驱动通知上层应用。
- 常用于串口中断接收、DMA 接收等场景。

发送完成回调：

```c
rt_err_t rt_device_set_tx_complete(
    rt_device_t dev,
    rt_err_t (*tx_done)(rt_device_t dev, void *buffer));
```

作用：

- 底层硬件发送完成后通知上层。
- 常用于 DMA 发送完成、FIFO 发送完成等场景。

## 自定义 test 字符设备流程

课程示例里有一个 `test_drv` 字符设备，适合用来理解 I/O 框架调用关系。

### 驱动侧

驱动侧要做的事情：

1. 创建 `rt_device`。
2. 填充设备操作函数。
3. 注册设备名。
4. 通过自动初始化宏加入系统初始化流程。

示例结构：

```c
static rt_err_t drv_test_init(rt_device_t dev)
{
    return RT_EOK;
}

static rt_err_t drv_test_open(rt_device_t dev, rt_uint16_t oflag)
{
    return RT_EOK;
}

static rt_err_t drv_test_close(rt_device_t dev)
{
    return RT_EOK;
}

static rt_ssize_t drv_test_read(rt_device_t dev,
                                rt_off_t pos,
                                void *buffer,
                                rt_size_t size)
{
    return size;
}

static rt_ssize_t drv_test_write(rt_device_t dev,
                                 rt_off_t pos,
                                 const void *buffer,
                                 rt_size_t size)
{
    return size;
}

static rt_err_t drv_test_control(rt_device_t dev, int cmd, void *args)
{
    return RT_EOK;
}
```

注册设备：

```c
int rt_drv_test_init(void)
{
    rt_device_t test_dev;

    test_dev = rt_device_create(RT_Device_Class_Char, 0);
    if (test_dev == RT_NULL)
    {
        return -RT_ERROR;
    }

    test_dev->init    = drv_test_init;
    test_dev->open    = drv_test_open;
    test_dev->close   = drv_test_close;
    test_dev->read    = drv_test_read;
    test_dev->write   = drv_test_write;
    test_dev->control = drv_test_control;

    return rt_device_register(test_dev, "test_drv", RT_DEVICE_FLAG_RDWR);
}
INIT_BOARD_EXPORT(rt_drv_test_init);
```

### 应用侧

应用侧只需要根据设备名使用标准 I/O API：

```c
static int drv_test_app(void)
{
    rt_device_t dev;

    dev = rt_device_find("test_drv");
    if (dev == RT_NULL)
    {
        return -RT_ERROR;
    }

    rt_device_open(dev, RT_DEVICE_OFLAG_RDWR);
    rt_device_control(dev, RT_DEVICE_CTRL_CONFIG, RT_NULL);
    rt_device_write(dev, 100, RT_NULL, 1024);
    rt_device_read(dev, 20, RT_NULL, 128);
    rt_device_close(dev);

    return RT_EOK;
}
MSH_CMD_EXPORT(drv_test_app, enable test drv app);
```

这个例子说明：

```text
应用调用 rt_device_xxx()
        ↓
I/O 管理层根据 rt_device 找到对应操作函数
        ↓
调用驱动中实现的 init/open/read/write/control
```

## GPIO / PIN 设备开发

RT-Thread 中 GPIO 通过 PIN 设备接口访问。

常用接口：

```c
rt_pin_mode();        /* 设置引脚模式 */
rt_pin_write();       /* 设置输出电平 */
rt_pin_read();        /* 读取输入电平 */
rt_pin_attach_irq();  /* 绑定中断回调 */
rt_pin_irq_enable();  /* 使能或关闭中断 */
rt_pin_detach_irq();  /* 解绑中断回调 */
```

### 常见引脚模式

```c
PIN_MODE_OUTPUT
PIN_MODE_INPUT
PIN_MODE_INPUT_PULLUP
PIN_MODE_INPUT_PULLDOWN
PIN_MODE_OUTPUT_OD
```

### 输出和读取电平

```c
rt_pin_mode(pin, PIN_MODE_OUTPUT);
rt_pin_write(pin, PIN_HIGH);
rt_pin_write(pin, PIN_LOW);

rt_pin_mode(pin, PIN_MODE_INPUT_PULLUP);
value = rt_pin_read(pin);
```

电平值：

```c
PIN_LOW
PIN_HIGH
```

### 外部中断

常见中断触发方式：

```c
PIN_IRQ_MODE_RISING
PIN_IRQ_MODE_FALLING
PIN_IRQ_MODE_RISING_FALLING
PIN_IRQ_MODE_HIGH_LEVEL
PIN_IRQ_MODE_LOW_LEVEL
```

按键中断示例：

```c
#define KEY_UP  GET_PIN(C, 5)

static void key_up_callback(void *args)
{
    int value = rt_pin_read(KEY_UP);
    rt_kprintf("key up: %d\n", value);
}

void irq_key_enable(void)
{
    rt_pin_mode(KEY_UP, PIN_MODE_INPUT_PULLUP);
    rt_pin_attach_irq(KEY_UP,
                      PIN_IRQ_MODE_FALLING,
                      key_up_callback,
                      RT_NULL);
    rt_pin_irq_enable(KEY_UP, PIN_IRQ_ENABLE);
}
```

GPIO 使用套路：

```text
确定引脚编号 GET_PIN()
  ↓
配置输入/输出模式 rt_pin_mode()
  ↓
普通 GPIO：rt_pin_write() / rt_pin_read()
  ↓
中断 GPIO：attach_irq() + irq_enable()
```

## I2C 设备开发

RT-Thread 中 I2C 以总线设备形式使用。

应用开发不是直接操作 I2C 寄存器，而是：

```text
查找 I2C 总线设备
  ↓
构造 rt_i2c_msg 消息
  ↓
调用 rt_i2c_transfer()
  ↓
判断返回值
```

### I2C 基础协议

I2C 常见速率：

```text
低速模式：10 Kbit/s
标准模式：100 Kbit/s
快速模式：400 Kbit/s
高速模式：3.4 Mbit/s
```

起始位和停止位：

```text
起始位 S：SCL 为高电平时，SDA 从高变低。
停止位 P：SCL 为高电平时，SDA 从低变高。
```

ACK / NACK：

```text
ACK：接收方拉低 SDA，表示应答。
NACK：接收方不拉低 SDA，SDA 保持高电平，表示不应答。
```

### 查找 I2C 总线

```c
struct rt_i2c_bus_device *i2c_bus;

i2c_bus = (struct rt_i2c_bus_device *)rt_device_find("i2c2");
if (i2c_bus == RT_NULL)
{
    rt_kprintf("can't find i2c device\n");
}
```

可以用 MSH 查看和探测：

```text
list_device
i2c scan i2c3
```

### I2C 消息结构

```c
struct rt_i2c_msg
{
    rt_uint16_t addr;
    rt_uint16_t flags;
    rt_uint16_t len;
    rt_uint8_t *buf;
};
```

字段含义：

- `addr`：从机地址，支持 7 位或 10 位地址。
- `flags`：读写标志。
- `len`：数据长度。
- `buf`：数据缓冲区。

注意：

> RT-Thread I2C 接口中的从机地址不包含读写位，读写方向由 `flags` 控制。

常用 flags：

```c
RT_I2C_WR
RT_I2C_RD
RT_I2C_ADDR_10BIT
RT_I2C_NO_START
RT_I2C_IGNORE_NACK
RT_I2C_NO_READ_ACK
```

### 写 1 个字节

```c
struct rt_i2c_msg msg;
rt_uint8_t buf[1];

buf[0] = 0x6B;

msg.addr  = 0x68;
msg.flags = RT_I2C_WR;
msg.buf   = buf;
msg.len   = 1;

if (rt_i2c_transfer(i2c_bus, &msg, 1) == 1)
{
    rt_kprintf("single byte write success\n");
}
```

### 写多个字节

```c
struct rt_i2c_msg msg;
rt_uint8_t buf[3] = {0x01, 0x02, 0x03};

msg.addr  = 0x68;
msg.flags = RT_I2C_WR;
msg.buf   = buf;
msg.len   = 3;

rt_i2c_transfer(i2c_bus, &msg, 1);
```

### 先写寄存器地址，再读 1 个字节

```c
struct rt_i2c_msg msgs[2];
rt_uint8_t reg = 0x6B;
rt_uint8_t value = 0;

msgs[0].addr  = 0x68;
msgs[0].flags = RT_I2C_WR;
msgs[0].buf   = &reg;
msgs[0].len   = 1;

msgs[1].addr  = 0x68;
msgs[1].flags = RT_I2C_RD;
msgs[1].buf   = &value;
msgs[1].len   = 1;

if (rt_i2c_transfer(i2c_bus, msgs, 2) == 2)
{
    rt_kprintf("read value: 0x%02x\n", value);
}
```

### I2C 常见问题

#### 1. 单个设备导致总线死锁

典型原因：

- 主机通信过程中复位。
- 从机正准备 ACK，把 SDA 拉低。
- 主机复位后发现 SDA 一直为低。
- 从机又在等待 SCL 变化。
- 双方互相等待，导致总线卡死。

解锁思路：

```text
主机启动 I2C 传输前，先用 GPIO 方式控制 SCL 输出 9 个时钟脉冲。
这样从机可以完成被挂起的 8 bit 数据 + ACK 流程，然后释放 SDA。
```

#### 2. rt_i2c_transfer() 返回 -5

常见原因：

- 从机地址错误。
- 7 位地址和 8 位地址混用。
- 设备没有上电或接线错误。
- SDA / SCL 没有上拉。
- 总线被某个从机拉死。
- 读写方向 flags 配错。

排查顺序：

```text
确认设备供电和接线
  ↓
确认 SDA / SCL 上拉
  ↓
用 i2c scan 扫描地址
  ↓
确认 addr 不包含读写位
  ↓
确认 RT_I2C_WR / RT_I2C_RD 使用正确
```

## SPI 设备开发

RT-Thread 中 SPI 分成两类：

```text
SPI 总线：对应 MCU 的 SPI 控制器，例如 spi1、spi2。
SPI 设备：对应挂在某个 SPI 总线上的从设备，例如 spi10、spi20。
```

SPI 使用前通常要先注册 SPI 总线，再把 SPI 从设备挂载到总线上。

开发流程：

```text
打开 SPI 框架
  ↓
编写或启用 SPI BUS 驱动
  ↓
注册 SPI Device
  ↓
查找 SPI Device
  ↓
配置 SPI 参数
  ↓
调用 SPI API 传输数据
```

### 挂载 SPI 设备

STM32 BSP 中常见写法：

```c
#include "drv_spi.h"
#include "drv_gpio.h"

static int spi_attach(void)
{
    return rt_hw_spi_device_attach("spi2", "spi20", GET_PIN(B, 12));
}
INIT_DEVICE_EXPORT(spi_attach);
```

含义：

- `"spi2"`：SPI 总线名。
- `"spi20"`：挂载后的 SPI 设备名。
- `GET_PIN(B, 12)`：片选 CS 引脚。

命名习惯：

```text
spix  ：SPI 总线，例如 spi1、spi2。
spixy ：SPI 设备，例如 spi10 表示 spi1 总线上的 0 号设备。
```

### 查找和配置 SPI 设备

```c
struct rt_spi_device *spi20;
struct rt_spi_configuration cfg;

spi20 = (struct rt_spi_device *)rt_device_find("spi20");

cfg.data_width = 8;
cfg.mode = RT_SPI_MASTER | RT_SPI_MODE_0 | RT_SPI_MSB;
cfg.max_hz = 1 * 1000 * 1000;

rt_spi_configure(spi20, &cfg);
```

常见配置点：

- `data_width`：数据宽度，常用 8 bit。
- `mode`：主从模式、CPOL/CPHA、大小端。
- `max_hz`：最大通信频率。

常见 mode：

```c
RT_SPI_MASTER
RT_SPI_SLAVE
RT_SPI_MODE_0
RT_SPI_MODE_1
RT_SPI_MODE_2
RT_SPI_MODE_3
RT_SPI_MSB
RT_SPI_LSB
```

### SPI 常用 API

```c
rt_device_find();              /* 查找 SPI 设备 */
rt_spi_configure();            /* 配置 SPI 设备 */
rt_spi_transfer();             /* 同时发送和接收一次数据 */
rt_spi_send();                 /* 只发送 */
rt_spi_recv();                 /* 只接收 */
rt_spi_send_then_send();       /* 连续发送两段数据，中间不释放 CS */
rt_spi_send_then_recv();       /* 先发送命令/地址，再接收数据 */
rt_spi_transfer_message();     /* 自定义消息链表传输 */
```

### 发送并接收一次数据

```c
rt_uint8_t tx = 0xDA;
rt_uint8_t rx = 0x00;

rt_spi_transfer(spi20, &tx, &rx, 1);
```

特点：

- SPI 是全双工，总线发送时也会同时接收。
- 此接口会自动处理一次片选过程。

### 只发送数据

```c
rt_uint8_t tx = 0x1A;

rt_spi_send(spi20, &tx, 1);
```

### 只接收数据

```c
rt_uint8_t rx = 0;

rt_spi_recv(spi20, &rx, 1);
```

### 连续两次发送

```c
rt_uint8_t tx1[2] = {0x1A, 0x99};
rt_uint8_t tx2[2] = {0x12, 0x39};

rt_spi_send_then_send(spi20, tx1, 2, tx2, 2);
```

适用场景：

```text
先发送寄存器地址，再发送数据；
中间不能释放 CS。
```

### 先发送后接收

```c
rt_uint8_t cmd[2] = {0x1A, 0x99};
rt_uint8_t data[2] = {0};

rt_spi_send_then_recv(spi20, cmd, 2, data, 2);
```

适用场景：

```text
读取 SPI 从设备数据；
先发命令或地址，再保持 CS 有效并读取返回数据。
```

例如读取 Flash、传感器寄存器时经常使用这种模式。

## 驱动框架复习重点

### 应用开发者视角

应用开发者重点掌握：

```text
rt_device_find()
rt_device_open()
rt_device_read()
rt_device_write()
rt_device_control()
rt_device_close()
```

以及某类设备的专用 API：

```text
GPIO: rt_pin_xxx()
I2C : rt_i2c_transfer()
SPI : rt_spi_xxx()
```

### 驱动开发者视角

驱动开发者重点掌握：

```text
rt_device_create()
rt_device_register()
填充 init/open/close/read/write/control
对接底层 HAL / LL / 寄存器
使用 INIT_BOARD_EXPORT / INIT_DEVICE_EXPORT 自动注册
```

### 移植时要想清楚的问题

移植一个设备驱动时，要分清楚：

```text
外部设备驱动是否能复用？
总线框架 API 是否一致？
当前芯片 BSP 是否已经提供对应 bus 驱动？
设备名是否一致？
片选、中断、复位等 GPIO 是否正确？
menuconfig 是否打开对应框架和 BSP 驱动？
```

### 调试常用命令

```text
list_device        查看已注册设备
i2c scan i2cX      扫描 I2C 总线设备
```

### 最重要的一句话

```text
RT-Thread 设备框架的价值，不只是封装硬件接口，
更重要的是把“具体 MCU 驱动”和“外部设备驱动 / 应用代码”解耦。
```
