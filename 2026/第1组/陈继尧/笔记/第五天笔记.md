## 2. RT-Thread 软件包生态与索引

### 2.1 软件包索引的作用

RT-Thread 软件包索引保存软件包的名称、版本、下载地址、依赖项和 Kconfig 配置入口。Studio 或 Env 读取索引后，才能在图形化配置或 `menuconfig` 中展示软件包，并根据选项拉取对应源码。

典型路径可以概括为：

```text
RT-Thread Studio 安装目录
  -> env
  -> packages
  -> 软件包 Kconfig 与索引信息
```

软件包源码并不是内核源码的一部分。开发者通常在 RT-Thread 官方软件包仓库中提交 PR，并更新对应的 `package.json`，完成软件包版本、下载地址和依赖信息的维护。

### 2.2 内核与 Env 版本兼容

Studio 针对不同内核版本维护不同的 Env 配置。旧内核不能直接套用新版本 Env 的全部索引和构建规则。本次工程使用 RT-Thread 4.1.1，应使用 Env 1.5.x 对应的软件包环境。

遇到 Kconfig 选项缺失、软件包无法拉取或配置保存后编译异常时，应先检查：

- RT-Thread 内核版本；
- Studio/Env 版本；
- 软件包索引是否更新；
- 软件包版本是否支持当前内核；
- 工程的 `.config`、`rtconfig.h` 和软件包目录是否一致。

### 2.3 软件包集成流程

```text
menuconfig 或 RT-Thread Settings 使能软件包
  -> Kconfig 检查依赖
  -> pkgs 拉取软件包源码
  -> SConscript/Studio 构建系统加入源码
  -> rtconfig.h 生成配置宏
  -> 编译、链接并在目标板验证
```

软件包的“下载成功”不等于底层硬件已经可用。例如 AHT10 软件包仍需要存在正确名称的 I2C 总线，RW007 软件包仍需要正确的 SPI、CS、BOOT 和 IRQ 引脚。

## 3. AHT10 温湿度传感器

### 3.1 软件包 API

AHT10 软件包的基本调用流程为：

```c
aht10_device_t dev;
float temp;
float humi;

dev = aht10_init("i2c3");
temp = aht10_read_temperature(dev);
humi = aht10_read_humidity(dev);
```

`aht10_init()` 根据总线名称查找 I2C 设备并返回传感器句柄。应用必须检查返回值，初始化失败时不能继续读取。

### 3.2 本次硬件配置

本次开发板实测使用软件 I2C3：

| 信号 | 配置 |
| --- | --- |
| I2C 总线名 | `i2c3` |
| SCL | `PE0` |
| SDA | `PE1` |

对应 BSP 配置为：

```c
#define BSP_USING_I2C3
#define BSP_I2C3_SCL_PIN GET_PIN(E, 0)
#define BSP_I2C3_SDA_PIN GET_PIN(E, 1)
```

最初照搬其他 STM32F407 板卡的 PA8/PC9 配置时，虽然能够注册 `i2c3`，但 AHT10 返回异常状态和 `-50.00 C`。这说明“总线注册成功”只能证明软件对象存在，不能证明板级引脚连接正确。最终应以开发板原理图、官方例程和实测数据为准。

### 3.3 浮点数输出

精简 libc 环境中的 `printf` 可能不支持 `%f`。本次工程使能 `rt_vsnprintf_full` 软件包，使以下输出能够正确显示：

```c
rt_kprintf("Temp: %.2f C ; Humi: %.2f %%\n", temp, humi);
```

在 MQTT JSON 和文件内容生成中，还可以先把浮点数放大 100 倍转为整数，再组合整数部分和小数部分。这样能减小对格式化浮点功能的依赖，并固定保留两位小数。

### 3.4 线程访问纪律

综合应用由 `ka_mqtt` 创建一个线程统一访问 AHT10。启动综合应用后，不应再同时执行 `aht10_thread_init`，否则两个线程会竞争同一个传感器，可能再次出现异常状态或无效数据。

## 4. RW007 WiFi 与网络验证

### 4.1 BSP 引脚必须匹配原理图

RW007 软件包示例中的默认引脚不一定适用于当前开发板。移植时需要逐项核对：

- SPI 总线和片选 CS；
- BOOT0、BOOT1；
- 中断 IRQ；
- 复位和电源控制；
- SPI 时钟频率和模式。

只使能软件包而不修正板级引脚，可能出现 `rw007 transfer failed`、`wlan init failed` 或 `wifi scan error:-10`。

### 4.2 常用网络命令

```text
list_device
wifi scan
wifi join <SSID> <password>
ifconfig
ping <host>
```

测试顺序应为：

```text
确认 wlan0 注册
  -> 扫描 2.4 GHz 热点
  -> 连接热点
  -> ifconfig 确认获得 IP
  -> ping 验证 IP 链路
  -> 再启动 MQTT
```

网络接口出现在 `list_device` 中不代表已经联网，还必须确认 `wlan0` 已获得有效 IP。

## 5. MQTT 通信

### 5.1 发布与订阅

本次应用连接 EMQX 公共 Broker：

| 参数 | 配置 |
| --- | --- |
| Broker | `broker.emqx.io` |
| Port | `1883` |
| 温湿度发布主题 | `rttttttt-pubbbb9` |
| LED 控制订阅主题 | `rttttttsubbb9` |
| QoS | `0` |

发布和订阅主题职责不同：

```text
开发板 -> rttttttt-pubbbb9 -> MQTT 客户端查看温湿度
MQTT 客户端 -> rttttttsubbb9 -> 开发板接收 LED 指令
```

如果把 `toggle` 发到发布主题，MQTT 客户端会看到自己发出的消息，但开发板不会触发订阅回调。

### 5.2 温湿度数据格式

每 5 秒发布一次 JSON：

```json
{"temp":28.38,"humi":39.83,"count":13}
```

`count` 表示自本次上电启动综合线程以来成功采集的数据次数。读取结果必须先做范围检查，无效数据不增加计数，也不上传或写入文件。

课程示例可以使用 cJSON 构造 JSON。本次数据结构固定且字段很少，实际代码使用 `rt_snprintf` 生成 JSON，没有额外引入 cJSON。两种方案都可行：cJSON 更适合复杂或动态对象，固定格式字符串占用更小、依赖更少。

### 5.3 LED 控制回调

云端发送纯文本：

```text
toggle
```

订阅回调检查载荷长度和内容：

```c
if (payload_len == 6 && memcmp(payload, "toggle", 6) == 0)
{
    led_on = !led_on;
    rt_pin_write(GET_PIN(F, 12), led_on ? PIN_LOW : PIN_HIGH);
}
```

PF12 红色 LED 为低电平点亮。MQTT 客户端的 Client ID 必须与开发板不同，否则后连接的客户端会将前一个同 ID 客户端踢下线。

## 6. DFS、FAL、SFUD 与 W25Q64

### 6.1 分层关系

```text
应用层 open/write/close
  -> DFS POSIX 接口
  -> Elm-FatFS
  -> FAL font 块设备
  -> FAL 分区映射
  -> SFUD 通用 SPI Flash 驱动
  -> RT-Thread SPI2 设备 spi20
  -> W25Q64
```

- DFS：提供统一文件系统框架和 POSIX 文件接口；
- Elm-FatFS：提供 FAT 文件系统实现；
- FAL：统一管理 Flash 设备和分区；
- SFUD：识别不同 SPI NOR Flash，并提供统一读写擦除接口；
- SPI 驱动：完成 MCU 与 W25Q64 之间的物理传输。

### 6.2 分区配置

W25Q64 容量为 8 MiB。本次将 5 MiB 到 8 MiB 的区域定义为 `font`：

```c
{FAL_PART_MAGIC_WORD, "font", "W25Q64",
 5 * 1024 * 1024,
 3 * 1024 * 1024,
 0}
```

文件系统只使用该 3 MiB 分区，不访问前 5 MiB 区域。

### 6.3 挂载流程

本工程启动时没有其他根文件系统，不能直接把 `font` 挂载到尚不存在的 `/font` 目录，因此最终把 `font` 直接挂载到根目录 `/`：

```text
探测 W25Q64
  -> fal_init
  -> 创建 font 块设备
  -> 尝试挂载 font 到 /
  -> 首次空白 Flash 挂载失败
  -> mkfs 格式化一次
  -> 重新挂载到 /
  -> 创建并追加 /Data.txt
```

首次格式化期间不能断电。后续上电检测到有效 FAT 文件系统后直接挂载，不再格式化，历史数据继续保留。

### 6.4 POSIX 文件写入

```c
fd = open("/Data.txt", O_WRONLY | O_CREAT | O_APPEND, 0);
write(fd, line, len);
close(fd);
```

`O_CREAT` 在文件不存在时创建文件，`O_APPEND` 保证每条数据追加到末尾。文件内容示例：

```text
Temp: 28.30 ; Humi: 41.59 ; Count: 1
Temp: 28.30 ; Humi: 41.59 ; Count: 2
Temp: 28.34 ; Humi: 41.75 ; Count: 3
```

## 8. 本次问题与排查经验

### 8.1 AHT10 返回异常值

现象：初始化后出现 abnormal status，温度固定为 `-50.00 C`。

原因：照搬其他 F407 板卡的 I2C3 引脚，软件总线存在但没有连接到板上 AHT10。

解决：改为本板实际的 PE0/PE1。

### 8.2 RW007 能注册但不能扫描

现象：存在 `wlan0`，但 `wifi scan` 返回 `-10`。

原因：RW007 的 SPI 传输阶段失败，软件对象注册不代表硬件初始化成功。

解决：核对软件包头文件、SPI 驱动类型以及 CS、BOOT、IRQ 引脚。

### 8.3 MQTT LED 无响应

现象：MQTT 客户端能看到 `toggle`，LED 不变化。

原因：指令发到了温湿度发布主题。

解决：向开发板订阅主题 `rttttttsubbb9` 发送纯文本 `toggle`。

### 8.4 Data.txt 不存在

现象：

```text
mount font at /font failed: -1
ls /font -> No such directory
```

原因：系统没有根文件系统，`/font` 挂载点目录不存在；同时 RT-Thread 4.1.1 的 `dfs_mount()` 对外返回 `-1`，原先只判断 `-ENOENT` 的格式化分支不会执行。

解决：将 `font` 挂载到 `/`，第一次挂载失败时只格式化一次，然后重新挂载，文件路径改为 `/Data.txt`。

## 9. 本日总结

第五天把传感器、网络、协议和文件系统连接成一条完整数据链：

```text
AHT10 采集
  -> MQTT 上传 EMQX
  -> Elm-FatFS 追加 Data.txt
  -> MQTT 订阅接收 toggle
  -> PF12 LED 翻转
```

本次最重要的认识是：配置项、设备注册和软件包下载都只是软件链路的一部分。只有结合正确的 BSP 引脚、真实总线通信、网络 IP、MQTT 回调日志和文件系统读回结果，才能证明整个功能真正完成。
