# RT-Thread 设备驱动框架

## 一、驱动开发问题与框架演进

### 1.1 驱动开发痛点

| 问题             | 说明                                                        |
| ---------------- | ----------------------------------------------------------- |
| **学习成本高**   | 不同厂商的MCU外设API各不相同（如GD、ST、NXP、LPC的SPI接口） |
| **代码复用率低** | 不同厂家的SPI驱动无法复用，换芯片基本需要重写               |
| **碎片化开发**   | 驱动代码与设备代码耦合，难以沉淀复用                        |

### 1.2 框架演进思路

**核心思想**：将驱动分为**设备驱动**（上层）和**对接驱动**（底层），提供统一API。

更换MCU只需改动对接驱动层
同一API接口，学习成本低
设备驱动可入库复用

### 1.3 RT-Thread I/O设备框架分层

```
应用层
  ↓
I/O设备管理层（open/write/read/control/close）
  ↓
设备驱动框架层（serial.c、adc.c等）
  ↓
设备驱动层（bsp/stm32/drv_usart.c等）
  ↓
SDK（HAL库/LL库等）
  ↓
硬件
```

### 1.4 设备分类

| 设备类型     | 特点                                                |
| ------------ | --------------------------------------------------- |
| **字符设备** | 顺序读取，按字节/字符读写，如键盘、串口             |
| **块设备**   | 随机访问，以块（通常512B）为单位读写，如硬盘、Flash |

**分类的好处**：
- MSH可以重定向到任意字符设备
- FATFS文件系统依赖块设备驱动

| `rt_device_init()`    | 初始化设备 |                                    |

### 2.3 设备打开模式标志

```c
#define RT_DEVICE_OFLAG_RDONLY    0x001  /* 只读 */
#define RT_DEVICE_OFLAG_WRONLY    0x002  /* 只写 */
#define RT_DEVICE_OFLAG_RDWR      0x003  /* 读写 */
#define RT_DEVICE_FLAG_STREAM     0x040  /* 流模式 */
#define RT_DEVICE_FLAG_INT_RX     0x100  /* 中断接收 */

```

> **注意**：如需设置接收回调函数，必须以 `RT_DEVICE_FLAG_INT_RX` 或 `RT_DEVICE_FLAG_DMA_RX` 方式打开设备。

### 2.4 数据接收/发送完成回调

```c

rt_err_t rt_device_set_tx_complete(rt_device_t dev, rt_err_t (*tx_done)(rt_device_t dev, void *buffer));
```

### 2.5 IO框架调用关系

```
rt_device_init()    → ops->init
rt_device_open()    → ops->init(未初始化时) → ops->open → ref_count++
rt_device_close()   → ref_count-- → ops->close(当ref_count==0)
rt_device_read()    → ops->read
rt_device_write()   → ops->write
rt_device_control() → ops->control
```

## 三、Pin设备

### 3.1核心对接过程
定义操作函数集 (rt_pin_ops)：驱动层需实现一组回调函数，这些函数在 struct rt_pin_ops 结构体中定义。包含：
配置与访问：pin_mode、pin_write、pin_read。
中断管理：pin_attach_irq、pin_detach_irq、pin_irq_enable。
引脚映射（可选）：pin_get，用于获取引脚编号。
注册 Pin 设备：在驱动初始化函数中，调用 rt_device_pin_register("pin", &pin_ops, RT_NULL) 将上述操作集注册到设备框架中。
底层实现：回调函数示例
驱动层需要填充一个 _stm32_pin_ops 结构体实例，其中每一项都指向具体的硬件操作函数：
```c
const static struct rt_pin_ops _stm32_pin_ops = {
    stm32_pin_mode,           // 设置引脚模式
    stm32_pin_write,          // 设置引脚电平
    stm32_pin_read,           // 读取引脚电平
    stm32_pin_attach_irq,     // 绑定引脚中断回调
    stm32_pin_dettach_irq,    // 脱离引脚中断回调
    stm32_pin_irq_enable      // 使能/关闭引脚中断
};
```
引脚编号约定：驱动层会将芯片的 GPIO 端口（如 GPIOA、GPIOB）和引脚号（如 PIN_0、PIN_1）统一映射为一个全局唯一的线性编号，这样应用层就能直接使用 GET_PIN(A, 5) 这样的宏来指定引脚。

中断对接机制：三级跳架构
当某个引脚（如按键 KEY0）触发中断时，实际上是这样的流程：
硬件中断触发：按键按下，产生一个下降沿信号，触发对应 GPIO 端口的硬件中断。
框架统一分发：硬件中断处理函数会进入驱动层预先挂载的中断分发器（rt_pin_irq_handler）。它会读取中断状态寄存器，识别出具体是哪个引脚（例如 PIN_KEY0）发生了中断。
执行用户回调：中断分发器根据引脚号，在内部维护的回调表（pin_irq_hdr_tab[]）中查找用户通过 rt_pin_attach_irq 注册的回调函数，并最终执行它。
```c
// 应用层绑定中断示例
rt_pin_attach_irq(KEY0_PIN, PIN_IRQ_MODE_FALLING, hdr_callback, (void*)"按键触发");
rt_pin_irq_enable(KEY0_PIN, PIN_IRQ_ENABLE);
```
总结:PIN 设备的对接本质是向上层提供一套统一的 Pin 操作接口，向下层硬件提供一套标准的回调函数接口。开发者只需在驱动层实现好 rt_pin_ops 中的函数，所有基于 RT-Thread 的应用代码就能通过 rt_pin_* API 轻松实现 GPIO 的读写与中断控制。

## 四、I2C外设开发

### 4.1 I2C总线简介

| 模式     | 速率       |
| -------- | ---------- |
| 低速模式 | 10 Kbit/s  |
| 标准模式 | 100 Kbit/s |
| 快速模式 | 400 Kbit/s |
| 高速模式 | 3.4 Mbit/s |

### 4.2 I2C协议要点

**起始位(S)**：SCL为高时，SDA由高变低
**停止位(P)**：SCL为高时，SDA由低变高
**ACK**：从机拉低SDA应答
**NACK**：从机不拉低SDA（SDA保持高）

**写数据流程**：S → 从机地址+W → ACK → 数据 → ACK → ... → P

**读数据流程**：S → 从机地址+W → ACK → 寄存器地址 → ACK → S(重复起始) → 从机地址+R → ACK → 数据 → NACK → P

### 4.3 I2C常用API

```c
struct rt_i2c_bus_device *i2c_bus = (struct rt_i2c_bus_device *)rt_device_find("i2c3");

struct rt_i2c_msg {
    rt_uint16_t addr;   /* 从机地址(不含读写位) */
    rt_uint16_t flags;  /* 读写标志 */
    rt_uint16_t len;    /* 数据长度 */
    rt_uint8_t *buf;    /* 数据缓冲区 */
};

rt_size_t rt_i2c_transfer(struct rt_i2c_bus_device *bus, struct rt_i2c_msg msg[], rt_uint32_t num);
```

### 4.4 flags标志位

```c
#define RT_I2C_WR        0x0000  /* 写 */
#define RT_I2C_RD        (1u << 0) /* 读 */
#define RT_I2C_ADDR_10BIT (1u << 2) /* 10位地址 */
#define RT_I2C_NO_START  (1u << 4)
#define RT_I2C_IGNORE_NACK (1u << 5)
#define RT_I2C_NO_READ_ACK (1u << 6)
#define RT_I2C_NO_STOP   (1u << 7)
```

> **注意**：`rt_i2c_transfer()` 会调用 `rt_mutex_take()`，不能在中断服务程序中调用。

### 4.5 I2C使用步骤

1. 查找I2C总线设备：`rt_device_find()`
2. 构造msgs消息结构体
3. 调用`rt_i2c_transfer()`启动传输
4. 处理结果

### 4.6 单字节写入示例

```c
void i2c_sample_single_byte_write(void)
{
    struct rt_i2c_bus_device *i2c_bus;
    struct rt_i2c_msg msgs;
    rt_uint8_t buf[2];
    
    i2c_bus = (struct rt_i2c_bus_device *)rt_device_find("i2c2");
    
    buf[0] = 0x6B;
    msgs.addr = 0x68;
    msgs.flags = RT_I2C_WR;
    msgs.buf = buf;
    msgs.len = 1;
    
    if (rt_i2c_transfer(i2c_bus, &msgs, 1) == 1)
        rt_kprintf("single byte write success!\n");
}
```

### 4.7 I2C总线死锁问题

**死锁原因**：主机复位时SCL未变低，从机等待SCL变低释放SDA，互相等待。

**解锁思路**：控制SCL产生9个时钟脉冲，让从机完成挂起操作。

```c
static rt_err_t stm32_i2c_bus_unlock(const struct stm32_soft_i2c_config *cfg)
{
    rt_int32_t i = 0;
    if (PIN_LOW == rt_pin_read(cfg->sda)) {
        while (i++ < 9) {
            rt_pin_write(cfg->scl, PIN_HIGH);
            stm32_udelay(100);
            rt_pin_write(cfg->scl, PIN_LOW);
            stm32_udelay(100);
        }
        if (PIN_LOW == rt_pin_read(cfg->sda))
            return -RT_ERROR;
    }
    return RT_EOK;
}
```

### 4.8 错误返回-5

**原因**：设备地址错误。从机没有正确应答。

### 4.9 软件I2C驱动编写

```c
static const struct rt_i2c_bit_ops bit_ops = {
    RT_NULL,
    set_sda, set_scl,
    get_sda, get_scl,
    udelay, 20, 50
};

int rt_sw_i2c_init(void)
{
    i2c_bus.priv = (void *)&bit_ops;
    rt_i2c_bit_add_bus(&i2c_bus, "i2c_sim");
    return RT_EOK;
}
INIT_DEVICE_EXPORT(rt_sw_i2c_init);
```

## 五、SPI外设开发

### 5.1 SPI总线概念

**4根线**：SCLK（时钟）、MOSI（主机输出从机输入）、MISO（主机输入从机输出）、CS（片选）

**全双工、同步**通信，常用于EEPROM、FLASH、RTC等

### 5.2 RT-Thread SPI设备模型

**SPI总线**：对应SPI控制器（如spi1, spi2）

**SPI设备**：对应不同CS连接的从设备（如spi10, spi20）

### 5.3 SPI开发模式

1. 编写SPI BUS驱动
2. 注册SPI Device设备（挂载到总线）
3. 打开SPI Device设备
4. 使用API编程发送接收数据
5. 关闭SPI Device设备

### 5.4 SPI常用API

| API                       | 功能                                    |
| ------------------------- | --------------------------------------- |
| `rt_spi_configure()`      | 配置SPI设备（数据宽度、模式、最大频率） |
| `rt_spi_transfer()`       | 传输一次数据（同时发送和接收）          |
| `rt_spi_send()`           | 发送数据，忽略接收                      |
| `rt_spi_recv()`           | 接收数据                                |
| `rt_spi_send_then_send()` | 连续两次发送，中间不释放片选            |
| `rt_spi_send_then_recv()` | 先发送后接收，中间不释放片选            |

### 5.5 SPI配置结构体

```c
struct rt_spi_configuration {
    rt_uint8_t data_width;   /* 数据宽度，8/16/32位 */
    rt_uint8_t mode;         /* SPI模式 */
    rt_uint32_t max_hz;      /* 最大频率 */
};

cfg.mode = RT_SPI_MASTER | RT_SPI_MODE_0 | RT_SPI_MSB;
cfg.max_hz = 1 * 1000 * 1000; /* 1MHz */
cfg.data_width = 8;
rt_spi_configure(spi_dev, &cfg);
```

### 5.6 SPI设备挂载（STM32 BSP）

```c
rt_err_t rt_hw_spi_device_attach(const char *bus_name, const char *device_name,
                                 GPIO_TypeDef *cs_gpiox, uint16_t cs_gpio_pin);
```

示例：
```c
rt_hw_spi_device_attach("spi2", "spi20", GET_PIN(B, 12));
```

### 5.7 SPI传输示例

```c
rt_uint8_t sendBuff = 0xDA;
rt_uint8_t recvBuff = 0xF1;
ret = rt_spi_transfer(spi20, &sendBuff, &recvBuff, 1);
```

### 5.8 先发送后接收（读Flash等场景）

```c
rt_err_t rt_spi_send_then_recv(struct rt_spi_device *device,
                               const void *send_buf, rt_size_t send_length,
                               void *recv_buf, rt_size_t recv_length);
```

**适用场景**：向从设备发送命令和地址后，再读取数据，中间保持片选信号有效。
