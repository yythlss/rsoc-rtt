## 一、RT-Thread 生态与产品线

RT-Thread 是国产自研 RTOS，经历近 20 年发展，国内开源社区活跃，内核已迭代至 **V5.3.0**

| 产品线 | 定位 | 特点 |
| :----: | :--: | ---- |
| **Nano** | 极简内核 | 实时内核 + 线程同步通信机制，最小实体（线程、时钟、中断、内存管理）；Apache 协议开源 |
| **标准版** | 功能完整 | 基于标准 POSIX API，提供日志、网络协议栈、IoT 协议等组件与中间件，生态完整、高度可定制 |
| **Smart** | 带 MMU 设备 | 混合微内核架构，内核态与用户态分离，提升安全性 |

## 二、开发环境搭建

1. 安装 RT-Thread Studio。

2. 通过 SDK Manager 下载 RT-Thread 源码（版本统一 **4.1.1**）及 STM32F4 芯片支持包。

3. 在设备管理器中确认 ST-Link 驱动识别正常，保证硬件连接可用。

## 三、工程文件说明

新建工程后，RT-Thread Studio 的工程目录：

```
工程名/
├── .config           # menuconfig 图形化配置结果
├── rtconfig.h        # 由 .config 生成的配置头文件（功能裁剪开关）
├── rtconfig.py       # 编译器与编译选项配置
├── Kconfig           # 配置项描述文件（menuconfig 界面依据）
├── SConstruct        # scons 构建入口（Studio 内部调用 scons 编译）
├── SConscript        # 各子目录的构建脚本
├── applications/     # 用户应用代码，main.c 位于此
├── board/            # 板级支持：系统时钟/外设初始化、链接脚本
├── libraries/        # 芯片厂商外设库（如 STM32 HAL 库）
├── rt-thread/        # RT-Thread 内核与组件源码
│   ├── src/          # 内核核心：调度、线程、IPC、时钟、内存管理
│   ├── include/      # 内核头文件（rtthread.h 等）
│   ├── components/   # 组件：FinSH 命令行、设备驱动框架、协议栈等
│   └── libcpu/       # CPU 架构移植层（Cortex-M4 等）
├── packages/         # 通过 SDK Manager 拉取的第三方软件包
├── Debug/            # 编译输出：rtthread.elf、rtthread.bin、.map
└── .cproject 等      # Eclipse 工程元文件
```

| 文件/目录               | 作用                                                         |
| ----------------------- | ------------------------------------------------------------ |
| `rtconfig.h`            | 配置头文件，`RT_USING_xxx` 宏决定裁剪哪些功能；修改 menuconfig 后由 `.config` 重新生成 |
| `applications/main.c`   | 用户程序入口，系统启动后创建 main 线程执行                   |
| `board/`                | 板级初始化（系统时钟、Tick、外设）与链接脚本                 |
| `libraries/`            | 芯片厂商提供的 HAL/标准外设库                                |
| `rt-thread/src/`        | 内核核心源码（线程调度、IPC、时钟、内存管理）                |
| `rt-thread/components/` | 组件层（FinSH、设备驱动框架、网络协议栈），配置开启后才编译链接 |
| `rt-thread/libcpu/`     | 架构移植层，向上给内核提供统一接口                           |
| `packages/`             | 第三方软件包                                                 |
| `Debug/`                | 编译产物：`rtthread.elf`、`rtthread.bin` 及 map 文件         |

> 编译过程：Studio 内部调用 scons（构建脚本为 `SConstruct`/`SConscript`），工具链为 gcc，最终在 `Debug/` 下生成 `rtthread.elf` 与 `rtthread.bin`。

## 四、系统启动流程

![](D:\HuaweiMoveData\Users\z'x\Desktop\day1\figures\微信图片_20260817213103_622_46.jpg)

上电后程序依次经过「汇编启动 → 内核初始化 → 用户 main」三个阶段：

```
上电复位
  → 启动文件 startup_xxx.s：设置堆栈、拷贝 .data 段、清零 .bss
  → SystemInit()：CMSIS 系统时钟初始化
  → entry()：libcpu 汇编入口
  → rtthread_startup()：内核启动
  → main 线程：rt_components_init() 初始化组件 → 执行用户 main()
```

内核启动函数（`rt-thread/src/components.c`）依次完成：

```c
int rtthread_startup(void)
{
    rt_hw_interrupt_disable();       /* 1. 关闭中断 */
    rt_hw_board_init();              /* 2. 板级初始化：时钟、SysTick、内存堆 */
    rt_show_version();               /* 3. 打印版本号（终端里的 logo） */
    rt_system_timer_init();          /* 4. 系统定时器初始化 */
    rt_system_scheduler_init();      /* 5. 调度器初始化 */
    rt_system_signal_init();         /* 6. 信号初始化 */
    rt_application_init();           /* 7. 创建 main 线程 */
    rt_system_timer_thread_init();   /* 8. 定时器线程初始化 */
    rt_thread_idle_init();           /* 9. 空闲线程初始化 */
    rt_system_scheduler_start();     /* 10. 启动调度器，交出 CPU 控制权 */
    return 0;
}
```

- 第 2 步 `rt_hw_board_init()` 里完成系统时钟、SysTick 节拍配置和内存堆初始化；串口初始化在板级外设初始化中完成，所以 logo 能通过串口打印出来。
- 第 7 步创建的 **main 线程**入口先调用 `rt_components_init()` 依次初始化各组件（如 FinSH），最后才进入用户编写的 `main()`。
- 第 9 步的**空闲线程**（idle）优先级最低，没有就绪线程时运行；SysTick 每触发一次就完成一次调度节拍。

## 五、Git 的使用

Git 是一个**开源的分布式版本控制系统**，由 Linus Torvalds 为管理 Linux 内核开发而创建，用于敏捷高效地处理任何或小或大的项目。

### 1. Git 与 SVN 的区别

| 对比项 | Git | SVN |
| :----: | --- | --- |
| 架构 | **分布式**：每个开发者本地都有完整版本库，不必依赖服务器端软件 | 集中式：所有代码托管在中央服务器 |
| 存储方式 | 内容按**元数据**方式存储 | 按文件存储 |
| 版本号 | 无全局递增版本号 | 有全局版本号 |
| 内容完整性 | 使用 SHA-1 哈希算法保证内容完整，降低磁盘故障、网络问题对版本库的破坏 | 较弱 |

### 2. 核心概念：工作区、暂存区与本地仓库

Git 的文件流经四个区域，理解它们是掌握一切 Git 操作的基础：

| 区域 | 英文 | 说明 |
| ---- | ---- | ---- |
| **工作区** | Workspace | 本地磁盘上实际看到的项目文件，编辑、新建、删除都发生在这里 |
| **暂存区** | Staging Area（Index） | 临时存放“即将提交的更改”，由 `git add` 放入，可以只暂存部分文件 |
| **本地仓库** | Local Repository | 隐藏在 `.git` 目录中的数据库，保存全部提交历史，由 `git commit` 写入 |
| **远程仓库** | Remote Repository | GitHub/Gitee 上的仓库，`git push` 上传，`git pull`/`git fetch` 下载 |

```
工作区 ──git add──▶ 暂存区 ──git commit──▶ 本地仓库 ──git push──▶ 远程仓库
  ▲                                                              │
  └──────────────────────── git pull / git fetch ◀───────────────┘
```

- 简单总结：修改代码 → `git add`（放进篮子）→ `git commit`（存入保险箱）→ `git push`（寄给远程）
- 注意：**暂存区 ≠ 本地仓库**，暂存区只是提交前的“中转站”，真正的版本历史存在 `.git` 目录里

文件在 Git 中的状态转换（可用 `git status` 随时查看）：

```
未跟踪 Untracked ──git add──▶ 已暂存 Staged ──git commit──▶ 已提交 Committed
                                ▲                             │
                                └───────── 修改文件 ◀──────────┘
                                       （已修改 Modified）
```

### 3. 常用命令

| 命令 | 说明 |
| ---- | ---- |
| `git init` | 初始化当前目录为 Git 仓库 |
| `git clone <url>` | 拷贝（下载）一个远程仓库到本地 |
| `git add <file/path>` | 将指定文件/文件夹加入暂存区；`git add .` 添加当前目录全部更改 |
| `git commit -m "message"` | 将暂存区内容提交到本地仓库，本次提交日志为 message |
| `git status` | 查看仓库当前状态，显示有变更、未跟踪的文件 |
| `git diff` | 比较暂存区与工作区的差异 |
| `git log` | 查看历史提交记录（`--oneline` 简洁模式，`--decorate --graph` 图形化显示分支与合并） |
| `git reset` | 回退版本 |
| `git rm` / `git mv` | 从暂存区和工作区删除文件 / 移动或重命名文件 |
| `git restore` | 恢复、撤销文件的更改（Git 2.23 引入） |
| `git stash` | 把未提交的修改“藏”进贮藏区，工作区恢复干净；`git stash pop` 取出继续写 |

首次使用需先配置提交身份（否则无法 commit）：

```
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

去掉 `--global` 参数则只对当前仓库生效。

本地 <--> 远端同步：

| 命令 | 方向 | 说明 |
| ---- | :--: | ---- |
| `git pull origin master` | 远端 → 本地 | 拉取远程 master 分支并自动合并（= fetch + merge） |
| `git fetch origin master` | 远端 → 本地 | 只同步远端分支到本地，**不自动合并**，确认无误后再自行 merge |
| `git push origin master` | 本地 → 远端 | 将本地 master 分支最新内容同步/推送到远端 |

`git push` 完整格式：`git push <远程主机名> <本地分支名>:<远程分支名>`，本地与远程分支同名时可省略冒号。

### 4. 分支管理

- `git checkout -b test`：基于当前分支切出一个名为 test 的新分支
- `git switch <branch>`：切换到已存在的分支（Git 2.23 引入，职责更清晰；`git checkout` 既能切分支又能恢复文件，推荐用 switch 切分支）
- `git branch`：列出本地分支；`git branch -r` 查看远程分支；`git branch -a` 查看全部
- `git merge <branch>`：将指定分支合并到**当前**分支
- `git branch -d <branch>`：删除已合并的分支；`git branch -D` 强制删除未合并的分支

> 切换分支时，Git 会用该分支最后一次提交的快照替换工作目录内容，所以多个分支不需要多个目录。

### 5. 远程仓库管理

| 命令 | 说明 |
| ---- | ---- |
| `git remote -v` | 查看仓库远端分支情况（及对应 URL） |
| `git remote add <name> <url>` | 添加远程仓库，通常命名为 origin |
| `git remote set-url origin <url>` | 修改远程仓库 URL（如改成自己的 Gitee 仓库地址） |
| `git remote rename <旧名> <新名>` | 重命名远程仓库 |
| `git remote remove <name>` | 删除远程仓库 |

origin 只是远程地址的别名（clone 时自动生成，指向克隆来源）。

### 6. 标签（Tag）

发布重要版本时给特定提交打标记：

```
git tag v1.0               # 轻量标签
git tag -a v1.0 -m "说明"  # 附注标签：记录打标签人和时间，推荐
git tag                    # 查看所有标签
git push origin --tags     # 推送所有标签（默认 push 不推送标签）
git tag -d v1.0            # 本地删除标签
```

### 7. 如何解决 git 冲突

1. 同步上游
2. 切到产生冲突的分支，执行 `git merge`/`git rebase`，将最新远端的修改同步到产生冲突的分支，此时会让你解决冲突（自行选择保留旧时间线还是新时间线的修改）

合并冲突时，Git 会在冲突文件中用标记标出两边内容：

```
<<<<<<< HEAD
本分支（当前）的修改
=======
对方分支（被合并进来）的修改
>>>>>>> change_site
```

手动编辑文件，保留需要的代码、删除冲突标记后：

```
git add <冲突文件>   # 告诉 Git 冲突已解决
git commit           # 提交合并结果
```

### 8. 推送第一次 PR 后如何进行下一次代码推送和 PR 创建

1. 浏览器 fork 仓库同步上游
2. 本地仓库打开 git bash，依次执行：

   ```
   git switch master
   git pull origin master
   ```

   （执行第 2 步前确保第 1 步已完成，即 origin master 已是同步后的最新上游仓库）

3. `git checkout -b day2`
4. （修改/新增/删除对应的文档/内容）
5. `git add .`（将当前目录下的所有修改加入暂存区）
6. `git commit -m "第二次提交信息"`
7. `git push origin day2`：将最新修改同步到远端 day2 分支
8. 到 day2 分支下创建 PR
