# Markdown 语法

**教程：**[Markdown 教程 | 菜鸟教程](https://www.runoob.com/markdown/md-tutorial.html)

- Markdown 是轻量级标记语言，文件后缀为 `.md` 或 `.markdown`。
- Markdown 可用于记录学习笔记和编写项目文档。

### **标题**

```markdown
# 一级标题
## 二级标题
### 三级标题
```

### **代码**

行内代码：

```markdown
`代码`
```

代码块：

````markdown
```c
int main(void)
{
}
```
````

代码块开头可以标注 `c`、`cpp`、`python` 等语言，实现对应的语法高亮。

### **表格、加粗和图片**

```markdown
| 特性一 | 特性二 |
| --- | --- |
| 内容一 | 内容二 |

**加粗文字**

![图片说明](图片路径)
```

- 图片可直接从剪贴板粘贴到 Markdown 文档。
- 图片保存位置可设置为当前目录下的 `figures` 文件夹。
- 使用相对路径可避免移动文档后图片丢失。

## git命令

1. 克隆远程仓库：

   ```bash
   git clone <仓库 URL>
   ```

   将远程仓库下载到本地，可以使用 HTTPS 或 SSH 地址。

2. 配置用户名：

   ```bash
   git config --global user.name "用户名"
   ```

3. 配置邮箱：

   ```
   git config --global user.email "邮箱"
   ```

4. 查看 Git 配置：

   ```
   git config --list
   ```

5. 初始化当前目录：

   ```
   git init
   ```

   将当前目录初始化为 Git 仓库。

6. 拉取远程主分支：

   ```
   git pull origin master
   ```

   将远程 `master` 分支同步到本地。

7. 查看文件状态：

   ```
   git status
   ```

   查看文件修改情况及暂存区状态。

8. 添加文件到暂存区：

   ```
   git add README.md
   git add <文件或目录>
   git add .
   ```

   `git add .` 表示添加当前目录下的全部修改。

9. 创建本地提交：

   ```
   git commit -m "first commit"
   ```

   `-m` 后面填写本次提交说明。

10. 推送到远程主分支：

    ```
    git push origin master
    ```

    `pull` 表示远程到本地，`push` 表示本地到远程。

11. 修改远程仓库地址：

    ```
    git remote set-url origin <SSH 仓库地址>
    ```

12. 获取远程分支信息：

    ```
    git fetch origin master
    ```

13. 查看远程仓库地址：

    ```
    git remote -v
    ```

14. 创建并切换到新分支：

    ```
    git checkout -b test
    ```

15. 将开发分支推送到远程：

    ```
    git push origin test
    ```

    此时远程 `master` 不会改变，后续通过 PR 合并。

16. 生成 SSH 密钥：

    ```
    ssh-keygen -t rsa
    ```

17. 查看并复制 SSH 公钥：

    ```
    cat ~/.ssh/id_rsa.pub
    ```

18. 测试 Gitee SSH 连接：

    ```
    ssh -T git@gitee.com
    ```

    第一次连接时输入 `yes`，出现成功提示表示配置完成。

## 提交流程

```txt
fork仓库
    ↓
git clone
    ↓
git config
    ↓
配置 SSH
    ↓
git pull origin master
    ↓
git checkout -b test
    ↓
修改文件
    ↓
git add .
    ↓
git commit -m "提交说明"
    ↓
git push origin test
    ↓
创建 PR
```


## 解决git冲突

1. fork repo：同步上游
2. 切到产生冲突的分支，执行git merge/rebase，将最新远端的修改同步到产生冲突的分支，此时会让你解决冲突（自行选择旧的时间线还是新的时间线的修改）
