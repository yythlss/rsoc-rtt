## 一、线程的本质：一个 `struct rt_thread`

### 1.1 结构体全貌

`struct rt_thread` 定义在 `rtdef.h` 中，是内核对"线程"这一抽象的全部承载：

```c
struct rt_thread {
    char        name[RT_NAME_MAX];       /* 8 字节，超出截断 */
    rt_list_t   list;                    /* 就绪队列挂载点 */
    rt_list_t   tlist;                   /* 调试 / list_thread 用 */
    void       *sp;                      /* 栈顶指针，切换时被 r0-r12/lr/pc/xpsr 覆盖 */
    void       *entry;                   /* 线程函数入口地址 */
    void       *parameter;               /* 传给 entry 的参数 */
    void       *stack_addr;              /* 栈底（高地址） */
    rt_uint32_t stack_size;              /* 栈大小（字节） */

    rt_ubase_t  number_mask;             /* SMP 用，单核编译为保留字段 */
    rt_uint8_t  stat;                    /* 状态 + 属性，紧凑编码 */
    rt_uint8_t  current_priority;        /* 当前优先级 0~31，0 最高 */
    rt_uint8_t  number;                  /* SMP 用 */
    rt_uint8_t  high_mask;               /* SMP 用 */

#if RT_THREAD_PRIORITY_MAX > 32
    rt_uint16_t number_mask;             /* 超过 32 级时扩展为 256 级 */
    rt_uint8_t  high_mask;              /* O(1) 查找需两层 */
    rt_uint8_t  low_mask[4];            /*         */
#endif

    rt_uint32_t init_tick;              /* 阻塞时初始 tick 计数 */
    rt_uint32_t remaining_tick;          /* 剩余 tick */

    struct rt_timer thread_timer;        /* 内嵌定时器，用于阻塞超时 / 时间片 */

    void (*cleanup)(struct rt_thread *); /* 线程退出清理回调 */
    rt_ubase_t  user_data;              /* 用户自定义 */
};
```

### 1.2 两个 `list`，两种用途

| 字段 | 用途 | 挂在哪 |
|---|---|---|
| `list` | 就绪队列 / 挂起队列 | `rt_thread_ready_table[]` 或 `rt_thread_defunct` |
| `tlist` | 调试枚举（`list_thread` 命令） | 不参与调度，仅遍历 |

> **关键**：调度器操作的是 `list`。`tlist` 是内核运行时维护的双向链表，`list_thread` 遍历它输出状态——因此即使一个线程既不在就绪队列也不在挂起队列（比如已 `delete` 但还没被回收），只要它没从 `tlist` 摘下，`list_thread` 照样能显示它。

## 二、线程状态：`stat` 字段的紧凑编码

`stat` 是一个 `rt_uint8_t`，同时携带 **运行状态** 和 **附加属性**：

```c
#define RT_THREAD_INIT      0x00   /* 已初始化但未启动 */
#define RT_THREAD_READY     0x01   /* 就绪，在就绪队列中 */
#define RT_THREAD_SUSPEND   0x02   /* 挂起，主动让出 */
#define RT_THREAD_RUNNING   0x03   /* 正在运行（仅当前线程此值有意义） */
#define RT_THREAD_CLOSE     0x04   /* 已关闭 / 已删除 */
#define RT_THREAD_STAT_MASK 0x07   /* 取状态的三位掩码 */
#define RT_THREAD_STAT_YIELD 0x08  /* 发生过主动让位 */
```

### 2.1 `stat` 不是简单的枚举

- `READY` 和 `RUNNING` 可以同时存在于一帧之间：调度器上下文切换时，先写 `RUNNING`，旧线程的 `stat` 同时改了。
- `YIELD` 是**附加位**，不冲突——一个线程可以 `READY | YIELD`。
- 读状态必须用 `thread->stat & RT_THREAD_STAT_MASK`，直接比较等于 `READY` 会漏掉 `RUNNING`（值为 3）。

### 2.2 状态流转

```
INIT ──startup()──▶ READY ──调度──▶ RUNNING ──yield()──▶ READY|YIELD
                                                    ├─sleep()──▶ SUSPEND
                                                    └─delete()──▶ CLOSE
SUSPEND ──resume()──▶ READY
CLOSE  ──回收完成──▶ （内存归还）
```

## 三、调度器：O(1) 优先级就绪表

### 3.1 数据结构

```c
/* scheduler.c */
rt_uint32_t rt_thread_ready_priority_group;  /* 32 位，每位代表一组优先级有人就绪 */
rt_uint8_t  rt_thread_ready_table[32];       /* index = 优先级，bitmap of threads at that prio */
```

32 级优先级时，`rt_thread_ready_priority_group` 每一位直接对应一个优先级（bit 0 = prio 0），`__rt_ffs()` 找到最低有效位 = 最高优先级。

### 3.2 `__rt_ffs`：找最低置位

```c
static int __rt_ffs(int value)
{
    if (value == 0) return 0;
    if (value & 0xff) {
        return __rt_ffs8(value & 0xff);
    }
    value >>= 8;
    if (value & 0xff) {
        return __rt_ffs8(value & 0xff) + 8;
    }
    value >>= 8;
    if (value & 0xff) {
        return __rt_ffs8(value & 0xff) + 16;
    }
    return __rt_ffs8(value >> 24) + 24;
}
```

> 此函数只查到最低有效位，返回值 = **最高优先级编号**。整个过程不超过几次 lookup，不依赖优先级数量。

### 3.3 同一优先级内的时间片轮转

同一个优先级可以有多个线程，调度器用 `thread_timer` 实现时间片。当一个线程的时间片耗尽时：

1. 调度器清零该线程的时间片位
2. 插入队尾
3. 让出给同优先级下一个线程

> 跨优先级调度时，时间片概念不发生作用——高优先级抢占是瞬时的。

## 四、栈：从 `'#'` 填充到溢出检测

### 4.1 栈的初始化

`rt_thread_init` 中用到以下代码：

```c
rt_memset(thread->stack_addr, '#', thread->stack_size);
```

栈初始化后每个字节都是 `0x23`（`'#'` 的 ASCII 码）。这不是什么魔法值——它让内核能在运行时计算**栈水印**（实际用了多少）。

### 4.2 栈溢出检测

`scheduler.c` 中的 `_scheduler_stack_check()` 每次调度时检查当前线程的栈：

```c
if (*((rt_uint8_t *)thread->stack_addr) != '#' ||
    sp <= thread->stack_addr ||
    sp > thread->stack_addr + stack_size)
{
    rt_kprintf("thread:%s stack overflow\n", thread->name);
    rt_base_t level;
    level = rt_hw_interrupt_disable();
    while (level);   /* 死循环——中断关闭后不会恢复 */
}
else if (sp <= stack_addr + 32)
{
    rt_kprintf("warning: %s stack is close to end.\n", thread->name);
}
```

**三个判定**：

| 条件 | 含义 | 后果 |
|---|---|---|
| `*stack_addr != '#'` | 栈底 `'#'` 被覆写 → **确实溢出** | 关中断 + 死循环（不是 reset，不是 fault handler） |
| `sp <= stack_addr` | SP 跑到了栈底以下 | 同上 |
| `sp > stack_addr + stack_size` | SP 越过了栈顶（栈反了？） | 同上 |
| `sp <= stack_addr + 32` | 剩余不足 32 字节 | 输出 warning，不中断 |

**关键陷阱**：溢出检测只在**调度点**做。如果一个线程不停写栈但从不被挂起/让出，检测永远不会触发——栈可能已经挖穿了别人，调度器甚至都没"看到"。

### 4.3 水印计算方法

```c
watermark = (rt_uint8_t *)thread->stack_addr + thread->stack_size - (rt_uint8_t *)thread->sp;
```

这句就是"最高 SP 到栈底"的距离，单位字节。`list_thread` 和 MSH 的 `thread` 命令在启用 `RT_USING_HEAP` + 调试信息时可以输出。

## 五、线程创建与销毁：两条路径

### 5.1 静态初始化：`rt_thread_init`

适合**栈在编译期就确定**的线程（如 idle、system）：

```c
rt_err_t rt_thread_init(struct rt_thread *thread,
                        const char *name,
                        void (*entry)(void *),
                        void *parameter,
                        void *stack_start,
                        rt_uint32_t stack_size,
                        rt_uint8_t priority,
                        rt_uint32_t tick);
```

- 不分配内存，`thread` 和 `stack_start` 都是外部传入
- 调用后线程处于 `INIT` 状态，需额外 `rt_thread_startup()` 才进入 `READY`
- 适合内核内部线程（idle、timer）等必须在 BSS 段提前声明的场景

### 5.2 动态创建：`rt_thread_create`

适合**应用层线程**：

```c
rt_thread_t rt_thread_create(const char *name,
                             void (*entry)(void *),
                             void *parameter,
                             rt_uint32_t stack_size,
                             rt_uint8_t priority,
                             rt_uint32_t tick);
```

- 在堆上分配 `struct rt_thread` + 栈空间
- 创建后线程处于 `INIT` 状态，同样需 `rt_thread_startup()` 启动
- 创建失败返回 `RT_NULL`

### 5.3 销毁与 "延迟回收"

线程调用 `rt_thread_delete(rt_thread_self())` 时，**不会立刻释放内存**：

1. 线程状态改为 `CLOSE`
2. 自身挂到 `_rt_thread_defunct` 链表上（`idle.c` 行 147）
3. **主动让出**（`rt_schedule()`）

真正的 `rt_memset(thread, 0, sizeof(struct rt_thread))` + `rt_free(thread->stack_addr)` 由 **idle 线程**执行：

```c
static void rt_thread_defunct_execute(void)
{
    struct rt_thread *thread;

    while (1) {
        thread = rt_list_entry(_rt_thread_defunct.next, struct rt_thread, tlist);

        if (&thread->tlist == &_rt_thread_defunct) break;

        rt_list_remove(&thread->tlist);

        if (rt_object_is_systemobject((rt_object_t)thread))
            rt_memset(thread, 0, sizeof(struct rt_thread));
        else
            rt_free(thread->stack_addr);
        ...
    }
}
```

**这就是一个有趣的陷阱**：如果有一个高优先级线程永远不主动让出 CPU，idle 线程永远获得不到时间片，defunct 队列上的线程永远不回收，堆内存会慢慢耗尽。

## 六、阻塞与唤醒：定时器驱动的超时机制

### 6.1 三种阻塞方式

| 函数 | 触发条件 | 唤醒方式 |
|---|---|---|
| `rt_thread_yield()` | 同优先级时间片用尽 / 主动让出 | 下次调度 |
| `rt_thread_sleep(ticks)` | 休眠 N 个 tick | 超时 / `rt_thread_resume()` |
| `rt_thread_delay(ms)` | 休眠 N 毫秒 | 超时（`ms × RT_TICK_PER_SECOND / 1000`） |

### 6.2 超时机制

每个线程内嵌一个 `struct rt_thread_timer`，阻塞时调度器把它挂到软件定时器队列。tick ISR 每 1ms 触发一次，递减所有活跃定时器，到 0 时回调 `rt_timer_timeout_handler`，将阻塞线程重新挂回就绪表。

> `RT_USING_TIMER_SOFT` 未开启时，定时器回调直接在 tick ISR 里做（不是移植到软件 timer 线程），意味着**关闭软 timer 时 tick ISR 增加少量工作但省了一个线程的上下文切换开销**。本机工程未开启，定时器走 ISR 路径。

### 6.3 `remaining_tick` 的递减

线程被阻塞时 `init_tick` 保存原始值，`remaining_tick` 每 tick 减 1。异步 `resume()` 直接把线程挂回就绪表——不检查 `remaining_tick`，所以即使提前被唤醒，计时器仍然在跑，但不会再阻塞同一个线程（状态已经是 READY）。

## 七、挂起与恢复：只允许挂起自己

```c
rt_err_t rt_thread_suspend(rt_thread_t thread)
```

**4.1.1 中的硬性断言**：

```c
RT_ASSERT(thread == rt_thread_self());
```

这意味着：

- ✅ `rt_thread_suspend(rt_thread_self())` —— 合法
- ❌ `rt_thread_suspend(other_thread)` —— **断言失败**
- 此行为在 RT-Thread 5.x 之后有所放宽，但 4.1.1 中编译不通过

恢复用 `rt_thread_resume(thread)`，无此限制——**任何线程**（包括 ISR）都可以恢复一个被挂起的线程。

## 八、钩子：在线程生命周期中注入自定义代码

`rtdef.h` 声明：

```c
struct rt_thread {
    /* ... */
    void (*cleanup)(struct rt_thread *thread);  /* 线程退出清理 */
};

/* 全局钩子指针 */
void (*rt_thread_suspend_hook)(rt_thread_t thread);
void (*rt_thread_resume_hook)(rt_thread_t thread);
void (*rt_heap_hook)(void);
```

可以在 `rtconfig.h` 中开启：`RT_USING_HOOK`。

| 钩子 | 触发时机 | 典型用途 |
|---|---|---|
| `cleanup` | 线程函数返回时 | 释放线程私有资源 |
| `suspend_hook` | 线程被挂起时 | 调试日志 / 功耗管理 |
| `resume_hook` | 线程被恢复时 | 恢复外设时钟 |

> 钩子在 ISR 上下文中执行——不能调用阻塞型 API。

## 九、本机活跃线程全景

从 `rtconfig.h` 配置 + `components.c` 推导本工程启动后的完整线程表：

| 线程名 | 优先级 | 栈大小 | 时间片 | 来源 | 状态 |
|---|---|---|---|---|---|
| `tidle0` | **31** (最低) | 1024 B | 32 tick | `idle.c` 内核创建 | 永久运行 |
| `main` | 10 | 2048 B | 20 tick | `components.c` | 用户主线程 |
| `tshell` | 20 | 4096 B | — | finsh 组件 | MSH 命令行 |

### 9.1 `tidle0` — 最忙的"闲人"

- 在 `rt_system_server_init()` 中创建
- 永远是就绪的最后一个馅饼（`PRIORITY_MAX - 1 = 31`）
- 有 32 tick 的时间片，但永远跑不满——任何优先级更低的线程不存在
- 执行 `rt_thread_defunct_execute()`，回收已删除的线程
- `RT_USING_IDLE_HOOK` 开启时，还可以挂 4 个 idle hook 回调

### 9.2 `main` — 你的代码入口

```c
tid = rt_thread_create("main", main_thread_entry, RT_NULL,
                       RT_MAIN_THREAD_STACK_SIZE, RT_MAIN_THREAD_PRIORITY, 20);
```

- 优先级 10：高于 `tshell`(20)，低于系统线程
- 用户线程中优先级最高，能抢占 shell 的输入输出
- 本例中 `main_thread_entry` 调用 `main()`，而 `main()` 里是你的 LED 闪烁循环 + `rt_thread_mdelay(500)`

### 9.3 `tshell` — 命令行解释器

- finsh 组件创建，优先级 20
- 等待 UART 输入，解析命令后 fork 一个线程执行（如 `list_thread`）
- 本机 `rtconfig.h` 中 `FINSH_USING_MSH` 已定义（shell 模式），未定义 `FINSH_USING_ASH`（自动脚本模式）

## 十、`list_thread` 输出格式解读

在 MSH 中输入 `list_thread`，内核输出：

```
thread   pri  status      sp     stack size max used left tick  error
tidle0   31    ready       0x...  0x400      0x2c4   0         0x0
tshell   20    ready/suspend  ...  0x1000      0x380   23        0x0
main     10    running     0x...  0x800      0x1b0   15        0x0
```

| 列 | 说明 |
|---|---|
| pri | `current_priority`，数字越小优先级越高 |
| status | `stat & STAT_MASK` 的字面显示，`running` 仅在被查看者自身那一帧 |
| sp | 当前栈指针值 |
| stack size | 初始化时的 `stack_size` |
| max used | 水印：`stack_addr + stack_size - SP`（栈被"淹没"的深度） |
| left tick | `remaining_tick`，负数表示超时了 |

> `max used` 越高说明用栈越多——如果它接近 `stack_size`，就该加栈了。

## 十一、值得记住的坑

| # | 坑 | 原因 | 后果 |
|---|---|---|---|
| 1 | `RT_NAME_MAX = 8` | `char name[8]`，超长自动截断 | `rt_thread_create("very_long_name", ...)` 实际存储为 `very_lo` |
| 2 | 溢出检测是调度时点检 | 非中断 / 非实时 | 溢出可能在两次调度之间就破坏内存了 |
| 3 | 溢出导致关中断死循环 | `rt_hw_interrupt_disable(); while(level);` | 整个系统 hang，不复位，不 fault handler |
| 4 | `delete` 不释放内存 | 等 idle 回收 | 高优先级线程 CPU 饥饿 → 堆泄漏 |
| 5 | `suspend` 只收自己 | `RT_ASSERT(thread == self)` | 老教程里跨线程挂起的写法编译不通过 |
| 6 | `stat & STAT_MASK` | `RUNNING = 3` 不在 `READY(1)` 上 | 不掩码读状态会得到错误结论 |
