## 二、线程同步机制

### 2.1 信号量（Semaphore）

#### 类型与用途

| 类型        | 初始值     | 用途          |
| --------- | ------- | ----------- |
| **二值信号量** | 0       | 线程同步（任务间同步） |
| **计数信号量** | >0（资源数） | 管理多个资源实例    |

#### API接口

**创建方式对比**：

```c
// 动态创建
rt_sem_t rt_sem_create(const char *name, rt_uint32_t value, rt_uint8_t flag);

// 静态初始化
rt_err_t rt_sem_init(rt_sem_t sem, const char *name, rt_uint32_t value, rt_uint8_t flag);

### 2.2 互斥量（Mutex）

#### 所有权与递归访问

对比信号量，互斥量具有以下独特属性：

| 特性       | 信号量        | 互斥量            |
| -------- | ---------- | -------------- |
| **所有权**  | 无（任何线程可释放） | **有**（仅持有者能释放） |
| **递归访问** | 不支持        | **支持**         |
| **死锁风险** | 较高（无主释放）   | 较低（有主释放）       |

>  **互斥量解决了信号量可能导致的死锁问题**

#### 优先级反转解决方案

**问题现象**：

- 低优先级线程持有互斥量 → 中优先级线程抢占CPU → 高优先级线程等待低优先级释放资源

**解决方案——优先级继承协议**：

- 互斥量自动启用**优先级继承协议**
- 临时提升低优先级线程的优先级至高优先级水平
- 阻止中优先级线程抢占CPU
- 释放互斥量后恢复原始优先级

```text
【优先级反转示意】
高优先级线程：准备运行 → 等待互斥量 → 被阻塞
中优先级线程：              → 抢占CPU → 运行中
低优先级线程：持有互斥量 → 被抢占 → 无法释放

【优先级继承解决后】
高优先级线程：准备运行 → 等待互斥量
低优先级线程：持有互斥量 → 临时提升至高优先级 → 释放互斥量 → 恢复原始优先级
高优先级线程：获得互斥量 → 继续运行

### 2.3 事件集（Event）

#### 多事件同步机制

| 特性        | 说明                    |
| --------- | --------------------- |
| **同步模式**  | 一对多、多对多同步             |
| **数据表示**  | 32位无符号整数（每一位代表一个事件标志） |
| **最大事件数** | 32个不同事件（bit0 ~ bit31） |

#### 逻辑与/或控制

`rt_event_recv` 接口中的控制模式：

| 模式                    | 说明       | 唤醒条件                     |
| --------------------- | -------- | ------------------------ |
| `RT_EVENT_FLAG_AND`   | **逻辑与**  | 所有指定事件标志位都置位时才唤醒         |
| `RT_EVENT_FLAG_OR`    | **逻辑或**  | 任一指定事件标志位置位即唤醒           |
| `RT_EVENT_FLAG_CLEAR` | **清除标记** | 接收成功后自动清除已接收的事件标志（可组合使用） |

#### 示例逻辑解析

```text
【线程1执行流程】

步骤1：以"逻辑或"模式等待事件3或事件5
   条件：事件3 或 事件5 任一发生 → 唤醒
   实际：事件3到达 → 唤醒成功 ✅

步骤2：继续以"逻辑与"模式等待事件3和事件5同时发生
   条件：事件3 且 事件5 同时发生 → 唤醒
   过程：事件5先到达 → 继续等待事件3 → 事件3到达 → 唤醒成功 

### 3.1 消息邮箱（Mailbox）

#### 固定大小传输

| 特性       | 说明               |
| -------- | ---------------- |
| **消息大小** | 固定4字节（32位系统指针大小） |
| **传输内容** | 指针或整型数据          |
| **数据结构** | 固定数组（消息队列是链表管理）  |

> 📌 邮箱适合传递指针地址或状态码等轻量级数据

#### 非阻塞发送特性

| 方向     | 阻塞性           | 适用场景        |
| ------ | ------------- | ----------- |
| **发送** | **非阻塞**       | 中断服务程序 → 线程 |
| **接收** | **阻塞**（需设置超时） | 线程主动等待消息    |

#### 示例流程

```c
/* 线程2：交替发送字符串指针 */
rt_mb_send(mb, (rt_uint32_t)"message1");
rt_mb_send(mb, (rt_uint32_t)"message2");
rt_mb_send(mb, (rt_uint32_t)"over");     // 发送终止标志

/* 线程1：接收并打印 */
while(1) {
    rt_mb_recv(mb, &msg_ptr, RT_WAITING_FOREVER);
    if ((char *)msg_ptr == "over") {
        break;    // 收到终止消息，退出循环
    }
    rt_kprintf("Received: %s\n", (char *)msg_ptr);
}



### 3.2 消息队列（Message Queue）

#### 变长数据传输

消息队列是邮箱的扩展，核心差异：

| 特性       | 邮箱    | 消息队列     |
| -------- | ----- | -------- |
| **消息大小** | 固定4字节 | **可变长度** |
| **数据结构** | 固定数组  | **链表管理** |
| **灵活性**  | 较低    | **较高**   |
| **紧急消息** | 不支持   | **支持插队** |

#### 核心API

```c
// 创建消息队列
rt_mq_t rt_mq_create(const char *name, 
                      rt_size_t msg_size,
                      rt_size_t max_msgs,
                      rt_uint8_t flag);

// 发送消息（追加到队列尾部）
rt_err_t rt_mq_send(rt_mq_t mq, const void *buffer, rt_size_t size);

// 紧急发送（插入队列头部）⭐
rt_err_t rt_mq_urgent(rt_mq_t mq, const void *buffer, rt_size_t size);

// 接收消息
rt_err_t rt_mq_recv(rt_mq_t mq, void *buffer, rt_size_t size, rt_int32_t timeout);
