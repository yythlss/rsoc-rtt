## 二、RT-Thread 生态与产品线

- 国产自研 RTOS，发展近 20 年，GitHub **12.2k** stars，国内活跃开源社区
- 内核版本已迭代至 **V5.3.0**
- 三条核心产品线：

| 版本 | 特点 | 协议 / 适用 |
|---|---|---|
| **Nano 版** | 极简内核：实时内核 + 线程同步通信机制 + 最小实体（线程 / 时钟 / 中断 / 内存管理） | Apache 协议开源 |
| **标准版** | 基于标准 POSIX API，丰富组件（日志管理、网络协议栈、IoT 协议）及中间件，高度可定制 | 生态完整 |
| **Smart 版** | 面向带 MMU 设备，混合微内核架构，内核态与用户态分离，提升安全性 | 带 MMU 设备 |

## 三、开发环境搭建（RT-Thread Studio + STM32F407）

1. 安装 **RT-Thread Studio**，替换 `app.asar` 文件完成破解
2. **SDK Manager** 下载 RT-Thread 源码（统一版本 **4.1.0**）+ STM32F4 芯片支持包
3. 确认设备管理器识别到 **ST-Link** 驱动，保证硬件连接正常
4. 基于 **STM32F407** 芯片创建工程：选择标准版内核；配置串口参数（波特率 **115200**）
5. 编译生成 `.elf` 和 `.bin` 文件，通过 ST-Link 下载至开发板
6. 启动终端查看启动日志验证程序运行，并演示断点调试功能

> 实操目标：创建基于 STM32F407 的 Hello World 工程，并完成编译 / 下载 / 调试

### 3.1 实操记录（已完成 ✅）

**工程信息**
- 工程名：`01_hello_rtt`
- 内核版本：**RT-Thread 4.1.0**（`build Aug 17 2026 11:23:12`）
- 芯片：STM32F407

**串口配置**：COM5 / 115200 / 8N1 / UTF-8

**`applications/main.c` 关键代码**：
```c
#include <rtthread.h>

#define DBG_TAG "main"
#define DBG_LVL DBG_LOG
#include <rtdbg.h>

int main(void)
{
    int count = 1;
    rt_kprintf("hello RSOC2026!\n");
    while (count++)
    {
        LOG_D("Hello RT-Thread!");
        rt_thread_mdelay(1000);
    }
    return RT_EOK;
}
```

## 五、Git 与开源协作流程

### 5.1 环境配置

- 安装 Git（可尝试配置中文语言包，汉化失败则默认英文）
- 全局身份设置：`git config --global user.name` / `user.email`
- 生成 **SSH 密钥对**（公钥 + 私钥），将公钥添加到 Git 平台账户 → 实现免密认证

### 5.2 核心指令

```bash
git init              # 初始化仓库
git clone <url>       # 克隆远端仓库
git pull              # 拉取最新代码
git add <file>        # 加入暂存区
git commit -m "..."   # 提交到本地仓库
git push              # 推送到远端仓库
git checkout -b day1  # 创建并切换分支（日常开发禁直接操作 master）
```

### 5.3 Fork 协作模式

1. **Fork** 上游仓库到个人账户，形成独立开发副本
2. 在个人 Fork 中创建功能分支（如 `day1` / `day2`），严禁直接修改 master
3. 推送后通过平台创建 **PR**，指定 Reviewer（组长 / 导师）
4. 同步上游：`git remote add upstream <url>` + `git fetch/pull upstream`
5. 冲突解决：合并上游代码或手动解决

### 5.4 目录与命名规范

- 目录结构：`组别 / 学员姓名 / 日期`，分别存放笔记和作业
- 分支命名：`day1`、`day2` 等，避免覆盖模板文件

### 5.5 角色职责

- **学员**：提交 PR
- **小组长**：审核并合并组员 PR
- **导师**：审核小组长 PR，处理跨组复杂问题
