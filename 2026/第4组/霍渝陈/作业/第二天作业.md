## Part 1 理论知识

### 1. 启动流程

```
Reset_Handler(设栈→拷贝.data→清.bss→SystemInit→bl entry)
  → entry() → rtthread_startup()
  → 关中断→rt_hw_board_init(①级INIT)→版本横幅→timer/scheduler初始化
    →创建"main"线程→idle线程→rt_system_scheduler_start()(永不返回)
  → main线程: rt_components_init(②~⑥级INIT) → main() 用户代码
```

`main()` 跑在 main 线程里，由调度器调度。

### 2. 自动初始化原理

`INIT_xxx_EXPORT(fn)` 把函数指针放入 `.rti_fn.<级别>` 段，启动时按段序遍历调用：

```c
#define INIT_EXPORT(fn, level) \
    RT_USED const init_fn_t __rt_init_##fn RT_SECTION(".rti_fn." level) = fn
#define INIT_BOARD_EXPORT(fn)   INIT_EXPORT(fn, "1")  /* 板级 */
#define INIT_APP_EXPORT(fn)     INIT_EXPORT(fn, "6")  /* 应用 */
```

链接脚本 `KEEP(*(SORT(.rti_fn*)))` 聚成连续数组，`rt_components_board_init()`(①级) / `rt_components_init()`(②~⑥级) 遍历执行。

### 3. 内核对象与内存分配

- 对象模型：线程/信号量等均为对象，基类 `rt_object`，对象容器按类型管理
- 线程控制块关键成员：`stat` / `current_priority` / `init_tick`+`remaining_tick` / `sp`
- 静态 vs 动态：静态=编译期分配、无失败风险、无碎片，高可靠场景强制静态；动态=堆分配、灵活但可能失败

### 4. 五态模型与调度

- 五态：初始→就绪→运行→挂起→关闭
- 调度：优先级抢占（高优先级立即抢占）+ 时间片轮转（同优先级递减轮换）

## Part 2 多线程实验

### 1. 实现

| 线程 | 方式 | 优先级/时间片/栈 | 功能 |
|---|---|---|---|
| th_led1 | 动态 create | 16/5/1024 | 翻转 LED_R，打印 count+tick |
| th_led2 | 静态 init | 16/5/1024 | 翻转 LED_B，打印 count |
| th_monitor | 动态 create | 10/5/1024 | 每2s打印状态+剩余栈；按键挂起/恢复 th_led1 |

`INIT_APP_EXPORT` 自动加载；`MSH_CMD_EXPORT(thread_dump)` 导出命令。

### 2. 运行结果

```
[th_led1] count=177 tick=88569
[th_led2] count=177
[th_led1] count=178 tick=89073
[th_led2] count=178
[th_monitor] tick=90567
  th_led1 : stat=suspend prio=16 剩余栈=780/1024
  th_led2 : stat=suspend prio=16 剩余栈=776/1024
```

- 两工作线程计数同步交替，时间片轮转正常
- monitor 每 2s 准点抢占打印，优先级正常
- 按键可挂起/恢复 th_led1
