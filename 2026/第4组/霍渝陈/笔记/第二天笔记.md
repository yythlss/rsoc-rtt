# 第二天笔记：RT-Thread 启动流程、内核基础与多线程编程

> 目标平台：STM32F407 星火号（stm32f407-rtspark）
> 本笔记基于工程实际代码整理（RT-Thread 4.1.1，Cortex-M4），关键结论均对照真实源码/符号地址，可自行验证。

## 1. STM32F407 启动流程与 RT-Thread 引导机制

### 1.1 从上电复位 Reset_Handler 到进入 main() 的完整调用链

```
上电复位
   │
   ▼
┌─────────────────────────────────────────────────────────────────┐
│ ① Reset_Handler（汇编）                                          │
│    文件：libraries/CMSIS/Device/ST/STM32F4xx/Source/Templates/   │
│          gcc/startup_stm32f407xx.S                               │
│    · ldr sp, =_estack            设置栈指针                       │
│    · 循环拷贝 .data（Flash → RAM）                               │
│    · 循环清零 .bss                                                │
│    · bl SystemInit               时钟等系统初始化（弱符号可覆盖）  │
│    · bl entry                    ★关键：调 entry 而不是 main      │
└─────────────────────────────────────────────────────────────────┘
   │
   ▼
② entry()   （rt-thread/src/components.c，GCC 分支）
   │   int entry(void) { rtthread_startup(); return 0; }
   │   （链接时用 -eentry 指定它为 ELF 入口符号）
   ▼
③ rtthread_startup()   （rt-thread/src/components.c）
   │   按顺序执行：
   │   1. rt_hw_interrupt_disable()        关中断
   │   2. rt_hw_board_init()               板级初始化（时钟/串口/堆）
   │      └─ 内部调用 rt_components_board_init() → 执行 INIT_BOARD_EXPORT 的 ①级函数
   │   3. rt_show_version()                ★打印 RT-Thread 版本横幅
   │   4. rt_system_timer_init()           系统时钟节拍（tick）初始化
   │   5. rt_system_scheduler_init()       调度器初始化（就绪队列等）
   │   6. rt_application_init()            创建名为 "main" 的线程 ★
   │   7. rt_system_timer_thread_init()    定时器线程
   │   8. rt_thread_idle_init()            空闲线程（idle）
   │   9. rt_system_scheduler_start()      ★启动调度器，此函数永不返回
   ▼
④ 调度器切换到 main 线程 → main_thread_entry()   （components.c）
   │   1. rt_components_init()   → 执行 INIT_PREV/DEVICE/COMPONENT/ENV/APP 的 ②~⑥级函数
   │   2. main()                 → 进入用户代码（applications/main.c）
   ▼
⑤ 用户 main() 里创建业务线程（如作业里的 th_led1/th_led2/th_monitor），
   之后所有线程由调度器按优先级/时间片调度
```

**必须理解的三个点：**

1. **你的 `main()` 不是程序起点**。起点是汇编 `Reset_Handler`，它做完整机初始化后调 `entry()` 进内核。
2. **main() 跑在名为 "main" 的线程里**（`rt_application_init()` 创建），由调度器调度执行——RTOS 里没有"裸奔大循环"，只有线程。
3. `rt_system_scheduler_start()` 之后**不再返回**，所有代码都在线程/中断上下文里运行。

> 验证方法（对照自己工程）：编译后对 `rtthread.elf` 执行
> `arm-none-eabi-nm rtthread.elf | grep -E "Reset_Handler|entry|rtthread_startup|main"`
> 实际符号：`Reset_Handler`(弱) → `entry` 0x08000be0 → `rtthread_startup` 0x08000c54 → `main` 0x0800b34c

### 1.2 自动初始化原理：INIT_BOARD_EXPORT 与 INIT_APP_EXPORT

**一句话认知**：`INIT_xxx_EXPORT(函数)` 不是"调用"函数，而是把**函数指针**放到一个特殊段里；系统启动时按段顺序**自动遍历调用**，用户不用改 main。

**① 宏定义**（rt-thread/include/rtdef.h）：

```c
#define INIT_EXPORT(fn, level)                                            \
    RT_USED const init_fn_t __rt_init_##fn RT_SECTION(".rti_fn." level) = fn

#define INIT_BOARD_EXPORT(fn)      INIT_EXPORT(fn, "1")   /* 板级 */
#define INIT_PREV_EXPORT(fn)       INIT_EXPORT(fn, "2")   /* 纯软件预初始化 */
#define INIT_DEVICE_EXPORT(fn)     INIT_EXPORT(fn, "3")   /* 设备 */
#define INIT_COMPONENT_EXPORT(fn)  INIT_EXPORT(fn, "4")   /* 组件(dfs/lwip...) */
#define INIT_ENV_EXPORT(fn)        INIT_EXPORT(fn, "5")   /* 环境(挂载...) */
#define INIT_APP_EXPORT(fn)        INIT_EXPORT(fn, "6")   /* 应用 */
```

展开后等价于：`const init_fn_t __rt_init_my_func RT_SECTION(".rti_fn.6") = my_func;`
即：**一个放在 .rti_fn.6 段里的函数指针**。

**② 链接脚本收集**（linkscripts/STM32F407ZG/link.lds）：

```ld
__rt_init_start = .;
KEEP(*(SORT(.rti_fn*)))      /* 按段名排序，把所有 init 函数指针聚成连续数组 */
__rt_init_end = .;
```

**③ 执行者**（rt-thread/src/components.c）：

| 函数 | 遍历范围 | 谁调用 | 何时 |
|---|---|---|---|
| `rt_components_board_init()` | `__rt_init_rti_board_start` → `__rt_init_rti_board_end`（①级） | `rt_hw_board_init()` | 内核启动早期，中断仍关闭 |
| `rt_components_init()` | `__rt_init_rti_board_end` → `__rt_init_rti_end`（②~⑥级） | main 线程的 `main_thread_entry()` | 调度器启动后 |

**④ 实际例子**（对 01_hello_rtt1 工程 elf 反查符号）：

```
0x0800e4a0  __rt_init_rti_start
0x0800e4a4  __rt_init_rti_board_start
0x0800e4a8  __rt_init_clock_information   ← 时钟初始化（INIT_BOARD_EXPORT）
0x0800e4ac  __rt_init_rti_board_end
0x0800e4b0  __rt_init_finsh_system_init   ← finsh 控制台（INIT_PREV_EXPORT）
0x0800e4b4  __rt_init_rti_end
```

**⑤ 设计意义**：组件自己"报名"、系统统一按序执行 → 模块解耦、增减组件不用改 main、初始化顺序由段名（数字）天然保证。

## 2. 内核基础与对象模型

### 2.1 对象容器与控制块

RT-Thread 用 **C 语言实现面向对象**：所有内核资源（线程、信号量、互斥量、消息队列、事件、定时器、设备…）都是"对象"。

- 基类 `struct rt_object`：`name` / `type` / `flags` / `list`（对象链表节点）
- 派生：`struct rt_thread`、`struct rt_semaphore`、`struct rt_mutex`…（首成员就是基类，可强转）
- 对象容器：`rt_object_container[]`（按 type 分类），`rt_object_find()` 按名字查对象

**线程控制块 `struct rt_thread` 关键成员**（rt-thread/include/rtdef.h）：

| 成员 | 作用 |
|---|---|
| `stat` | 线程状态：INIT/READY/RUNNING/SUSPEND/CLOSE（见第 3 节五态模型） |
| `current_priority` | 当前优先级（0 最高，越小越先调度） |
| `init_tick` | 创建时设定的 tick 数（时间片长度 / 延时基准） |
| `remaining_tick` | 剩余 tick：时间片轮转时每个 tick 递减，减到 0 让出 CPU |
| `sp` | ★栈指针：上下文切换时把寄存器现场压栈保存到这里，恢复时从这里弹栈 |
| `entry` / `parameter` | 线程入口函数及其参数 |
| `stack_addr` / `stack_size` | 线程栈地址与大小（栈溢出检测依据） |
| `tlist` | 就绪队列链表节点（同优先级线程串在一起轮转） |
| `error` | 线程错误码 |

### 2.2 内存分配方式：静态对象 vs 动态对象

| 维度 | 静态（`rt_thread_init` + 全局变量） | 动态（`rt_thread_create`） |
|---|---|---|
| 分配位置 | 编译期定死，TCB 和栈在 `.bss/.data`（全局数组） | 运行时从堆 `rt_malloc` 分配 |
| 生命周期 | 与程序共存亡 | 可 `rt_thread_delete` 随时销毁 |
| 分配失败风险 | **不可能失败** | 堆不足时返回 NULL（要判空！） |
| 内存碎片 | 无 | 反复创建/销毁会产生碎片 |
| 可分析性 | 编译完内存布局完全确定 | 运行期才确定 |
| 使用 | `struct rt_thread t; rt_uint8_t stack[1024]; rt_thread_init(&t, ...)` | `tid = rt_thread_create("name", fn, ...)` |

**为什么高可靠场景强制使用静态线程**：航空航天/汽车/医疗等场景要求**确定性**——不允许 malloc 失败、不允许碎片导致后期分配不出内存、内存使用量必须可静态审计。动态分配在长时间运行 + 频繁创建销毁时可能因碎片化而"悄悄失败"，这在安全关键系统里不可接受。

> 作业对应：`th_led1`（动态，体验 create/delete）、`th_led2`（静态，定义全局 TCB + 栈 + rt_thread_init），正好两种都练到。

## 3. 线程状态机与调度算法

### 3.1 五态模型

```
          rt_thread_init / rt_thread_create
                     │
                     ▼
        ┌────── 初始态 (INIT) ──────┐
        │        │                  │
        │  rt_thread_startup        │
        │        ▼                  │
        │   ┌── 就绪态 (READY) ──┐  │
        │   │    │               │  │
        │   │  调度器选中         │  │ 延时到期 / 信号量释放 /
        │   │    ▼               │  │ rt_thread_resume
        │   │ 运行态 (RUNNING) ──┼──┘
        │   │    │  ▲            │
        │   │    │  └────────────┘ 更高优先级线程抢占
        │   │    │
        │   │    ├─ rt_thread_delay/mdelay
        │   │    ├─ rt_sem_take / rt_mutex_take / rt_mq_recv（资源不可用）
        │   │    └─ rt_thread_suspend
        │   │    ▼
        │   └── 挂起态 (SUSPEND) ────┐
        │                            │ 被唤醒(见上) / resume
        └── rt_thread_delete ────────┼──────────────┐
            / 线程函数返回            │              │
                                     ▼              ▼
                              ┌── 关闭态 (CLOSE) ──┘
                              │ 静态: rt_thread_detach
                              │ 动态: rt_thread_delete(回收内存)
                              └
```

| 状态 | 说明 | 进入 API | 离开 API |
|---|---|---|---|
| 初始态 INIT | 已创建未启动，只占资源不参与调度 | `rt_thread_init/create` | `rt_thread_startup` |
| 就绪态 READY | 排队等 CPU | `startup` / `resume` / 阻塞条件满足 | 被调度选中 → 运行 |
| 运行态 RUNNING | 正在占用 CPU（全局同时只有一个） | 调度器选中 | 时间片耗尽 / 被抢占 / 主动阻塞 |
| 挂起态 SUSPEND | 阻塞等待某条件（延时/资源） | `rt_thread_delay`、`rt_sem_take`、`rt_thread_suspend` | 条件满足 / `rt_thread_resume` |
| 关闭态 CLOSE | 结束，资源待回收 | 线程函数 return、`rt_thread_delete` | `rt_thread_detach`（静态） |

> 作业里 `rt_thread_suspend(th_led1)` 挂起 / `rt_thread_resume(th_led1)` 恢复，就是手动触发 运行态→挂起态→就绪态 的转换。

### 3.2 调度机制剖析

**① 抢占式调度（优先级驱动）**

- 每个线程有优先级（0 ~ RT_THREAD_PRIORITY_MAX-1，默认 32 级，**0 最高**）
- 内核维护按优先级组织的**就绪队列**（位图 `number_mask` 加速查找最高优先级）
- 只要就绪队列里出现比当前线程**更高优先级**的线程，调度器立即切换（抢占点：创建线程、唤醒、释放信号量、延时到期等）
- 低优先级线程只有高优先级线程阻塞/结束时才能运行

> 作业中 `th_monitor` 优先级 10 < 工作线程 16，所以 monitor 一唤醒就**抢占**两个工作线程。

**② 时间片轮转（同优先级轮流）**

- 同优先级的多个就绪线程按 `tlist` 链表排队
- 每个线程拿到 `init_tick` 个 tick 的时间片，每过一个 tick `remaining_tick--`
- 减到 0 → 主动让出，切换到**同优先级下一个**线程，时间片重置为 `init_tick`
- 若该优先级只有 1 个线程，则时间片轮转退化为一直运行（直到被抢占/阻塞）

**③ 调度触发与切换**：所有"可能改变就绪状态"的操作最终都会走到 `rt_schedule()`（src/scheduler.c），选择最高优先级就绪线程；真正切换由汇编 `rt_hw_context_switch`（Cortex-M4 在 libcpu/arm/cortex-m4/context_gcc.S）完成：**保存当前线程 sp 指向的寄存器现场 → 恢复目标线程现场 → 跳转**——这就是 `struct rt_thread.sp` 成员的用武之地。
