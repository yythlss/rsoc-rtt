# 第五天笔记：软件包生态、MQTT 上云与文件系统实战

> 目标平台：STM32F407 星火号（stm32f407-rtspark）
> 内核版本：RT-Thread 4.1.1（Cortex-M4）
> 开发环境：RT-Thread Studio 2.3.1 + 板载 ST-LINK 下载，串口 COM7/115200
> 板载外设：AHT10 温湿度（swi2c3）、RW007 WiFi（SPI2）、W25Q64 SPI Flash（SPI2）
> 本笔记要点均对照官方 BSP `bsp/stm32/stm32f407-rt-spark` 源码与软件包文档整理。

---

## 1. 软件包生态：嵌入式界的"应用商店"

### 1.1 什么是软件包

软件包是 RT-Thread 生态里**可复用的功能模块**：传感器驱动（AHT10、MPU6050）、网络协议（kawaii-mqtt、阿里云 IoT）、系统兼容层（FreeRTOS 兼容）、工具库（rt_vsnprintf_full 浮点打印、cJSON）等，主线已有 800+ 个。**配置即用，不用自己写底层驱动**——类比手机应用商店。

### 1.2 索引与拉取机制

- 软件包的 Kconfig 索引在 **env 工具目录**（`studio安装目录/env/packages`）；
- Studio 按内核版本维护**两份 env**：内核 **5.1.0 以上**用新 env（2.0），**5.1.0 以下**只能用 1.5.x（本工程 4.1.1 → env 1.5.x，换新 env 会报错）；
- 在 Studio「添加软件包」勾选 → 保存 → **自动拉取源码到工程 `packages/` 目录**；
- 软件包仓库独立维护，贡献者提交 PR + **package.json**（记录仓库地址）登记。

### 1.3 依赖管理（关键坑）

部分软件包依赖底层框架，**要手动开启依赖**。典型：AHT10 依赖 **Sensor 设备框架**，未使能会 `undefined reference to sensor ops`。所以配置顺序：先开框架组件，再开软件包。

## 2. AHT10 温湿度传感器（软件包实战）

### 2.1 板载连接

星火号板载 AHT10，通过**软件 I2C3**（swi2c3，注册为总线名 `"i2c3"`）通信。在 RT-Thread Settings 使能 `BSP_USING_AHT21`（选项名叫 AHT21，实际就是板载 AHT10 传感器 + AHT10 软件包），会自动拉取 `aht10` 软件包。

### 2.2 核心 API（软件包封装了 I2C 寄存器操作）

| API | 作用 |
|---|---|
| `aht10_init("i2c3")` | 初始化，返回设备句柄（失败返回 RT_NULL） |
| `aht10_read_temperature(dev)` | 读温度（float，℃） |
| `aht10_read_humidity(dev)` | 读湿度（float，%） |

```c
#include <aht10.h>
aht10_device_t dev = aht10_init("i2c3");
if (dev == RT_NULL) { /* 失败处理 */ }
float temp = aht10_read_temperature(dev);
float humi = aht10_read_humidity(dev);
```

**本质**：软件包内部仍是走 RT-Thread I2C 设备框架读写 AHT10 寄存器，只是封装成易用 API——这就是"复用"的意义。

### 2.3 浮点打印坑

默认 libc **不支持 `%f` 浮点打印**，`rt_kprintf("temp=%.2f")` 会输出异常。解决：使能 **rt_vsnprintf_full** 软件包（浮点数打印支持），重新配置编译。

## 3. MQTT 上云：kawaii-mqtt + EMQX

### 3.1 MQTT 协议要点

- **轻量发布/订阅**：客户端订阅主题，发布者向主题发消息，Broker 中转，松耦合；
- **QoS 等级**：QoS0 最多发一次（开销最小）、QoS1/2 递增（确认/恰好一次）；
- 嵌入式 IoT 的事实标准。

```
发布者 ──发布(主题/数据)──▶ Broker(消息代理) ──推送──▶ 订阅者
```

### 3.2 EMQX 免费公共服务器

- 服务端：EMQX 免费公共 Broker `broker.emqx.io`，TCP 端口 **1883**；
- 免费服务器**不校验用户名密码**（随便填），但**客户端 ID 必须全局唯一**（相同 ID 会互相顶下线）；
- 公共服务器上主题要**错开命名**（如 `rsoc/<姓名拼音>/device/up`），避免互相干扰；
- 电脑端用 **MQTTX** 桌面客户端验证收发。

### 3.3 kawaii-mqtt 软件包核心流程

```c
mqtt_client_t client = mqtt_lease();                  /* 创建客户端实例 */
mqtt_set_host(client, HOST);                          /* Broker 地址 */
mqtt_set_port(client, PORT);                          /* 1883 */
mqtt_set_client_id(client, CLIENT_ID);                /* 全局唯一 */
mqtt_set_user_name(client, USER); mqtt_set_password(client, PASS);
mqtt_connect(client);                                 /* 连接 */
mqtt_subscribe(client, SUB_TOPIC, QOS0, cb);          /* 订阅下行主题+回调 */
mqtt_publish(client, PUB_TOPIC, &msg);                /* 发布上行数据 */
/* 循环里必须周期性调用 mqtt_sleep_ms(500) 让客户端处理收发与心跳保活 */
```

**保活关键**：消息循环若用 `rt_mq_recv(..., RT_WAITING_FOREVER)` 死等，心跳会被饿死、被服务器踢下线。正确做法是 **500ms 短超时**取队列，取完必调 `mqtt_sleep_ms(500)`。

### 3.4 网络底层：RW007 WiFi

- RW007 是 SPI 接口 WiFi 模块（SPI2），使能软件包后对照**原理图修正引脚**（CS=PF10、INT=PG11、RST=PG15、BOOT0/BOOT1 特殊，官方 BSP Kconfig 默认值：CS=90、BOOT0=29、BOOT1=90、INT=107、RST=111）；
- 联网验证：`wifi scan` 扫热点 → `wifi join <SSID> <密码>` 连接 → `ping baidu.com` 通即联网成功；
- **分层收益**：MQTT 应用层不关心底层是哪种网卡，只要有 lwIP/SAL 统一网络接口就能跑。

## 4. DFS 文件系统 + FAL 分区 + SFUD

### 4.1 三个概念

| 组件 | 作用 |
|---|---|
| **DFS** | 虚拟文件系统：统一根目录 `/` + POSIX 接口（open/write/read/close/mkdir...），上层与介质解耦 |
| **FAL** | Flash 抽象层：把 Flash 按**分区表**切成逻辑分区（app/font/filesystem...），分区可独立管理 |
| **SFUD** | 串行 Flash 通用驱动：屏蔽 W25Q64/W25Q128 等型号差异（页大小/时序），统一接口读写 |

### 4.2 文件系统启动流程（梳理）

```
上电
 → rt_hw_board_init：初始化 SPI2 总线
 → SFUD 探测 W25Q64，注册 spi flash 设备
 → FAL 初始化（fal_init）：按分区表登记 flash 设备 + 各分区
 → 把文件系统分区（font/filesystem）创建为块设备（fal_blk_device_create）
 → DFS 挂载：dfs_mount(分区块设备名, 挂载点, "elm", 0, 0)
 → 挂载成功 → ls /font 可见；失败 → 先 dfs_mkfs 格式化再挂
```

### 4.3 星火号官方分区表（W25Q64，8MB）

来自官方 BSP `board/ports/fal/fal_cfg.h`（`FAL_PART_TABLE`）：

| 分区 | 设备 | 偏移 | 大小 |
|---|---|---|---|
| easyflash | W25Q64 | 0 | 512K |
| download | W25Q64 | 512K | 1MB |
| wifi_image | W25Q64 | 1.5MB | 512K |
| **font** | W25Q64 | 2MB | **3MB** |
| filesystem | W25Q64 | 5MB | 3MB |

> 作业要求挂载的 **font 分区**在 W25Q64 上（2MB 偏移 / 3MB 大小），原用途是字库存放。把它当普通文件系统分区格式化挂载即可写入 Data.txt。

### 4.4 挂载命令与 POSIX 读写

```c
/* 创建块设备并挂载（失败先格式化） */
fal_blk_device_create("font");                 /* 把 font 分区变块设备 */
if (dfs_mount("font", "/font", "elm", 0, 0) != 0)
{
    dfs_mkfs("elm", "font");                   /* 首次需格式化 */
    dfs_mount("font", "/font", "elm", 0, 0);
}

/* POSIX 写文件（追加） */
int fd = open("/font/Data.txt", O_WRONLY | O_CREAT | O_APPEND);
write(fd, buf, rt_strlen(buf));
close(fd);                                      /* ★close 触发 flush 才真正落盘 */
```

shell 命令：`list_device` 看设备、`ls /font` 看目录、`cat /font/Data.txt` 看内容。

**踩坑**：
1. **`close(fd)` 才落盘**：DFS 写有缓存，`write()` 只进内存，close 触发 flush 才写进 Flash；循环内每次 open/write/close；
2. **fd 为 0 也是成功**：判断失败看 `fd < 0`；
3. **`ls` 出现 `BAD file` 乱码** = FAT 目录损坏，`mkfs -t elm font` 格式化（注意：mkfs 的目标是**分区设备名 font**，不是挂载点）；
4. **RTC 警告刷屏**：FAT 取时间戳找不到 RTC 设备，在 `ffconf.h` 把 `FF_FS_NORTC` 设为 1；
5. **WiFi 与 Flash 共用 SPI2 总线**：初始化时把 WiFi 片选（PF10）上拉，避免抢总线导致 `w25q64 not found`。

## 5. 综合作业架构：采集 → 上云 → 落盘

作业把 2/3/4 章串成一条链路，两种实现风格：

**方案 A（三线程 + 双消息队列解耦，同组熊自力）**
```
AHT10 采集线程(3s, Count++)
   ├─rt_mq_send──▶ sensor_mqtt_mq ──▶ MQTT 上传线程(500ms短超时+保活) ──▶ EMQX
   └─rt_mq_send──▶ sensor_file_mq ──▶ 文件保存线程(滚动缓存10条) ──▶ /font/Data.txt
```
采集与上传/落盘互不阻塞，谁慢都不影响采集；MQTT 线程用短超时保活心跳。

**方案 B（单线程条件编译，第3组陈相臣）**
主采集线程：读 AHT10 → 拼字符串 → `save_to_file` 追加 → `mqtt_pub_data` 上行；订阅回调里直接翻转 LED。代码用 `#ifdef PKG_USING_AHT10 / PKG_USING_KAWAII_MQTT / RT_USING_DFS` 条件编译，缺哪个组件也能编译，方便逐项联调。

**云端控灯**：订阅下行主题，回调里 `strstr(payload, "led_toggle")` 做包含匹配（兼容 JSON 包裹），匹配到就 `rt_pin_write(GET_PIN(F,12), ...)` 翻转 LED_R。回调短小，不做耗时操作。

**Data.txt 格式**（Count 为自上电起采集次数，追加写）：

```
Temp: 26.35 ; Humi: 58.12 ; Count: 1
Temp: 26.41 ; Humi: 58.03 ; Count: 2
Temp: 26.28 ; Humi: 58.20 ; Count: 3
```
