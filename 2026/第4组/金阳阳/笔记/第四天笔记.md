## 一、为什么需要设备驱动框架

**痛点：外设 API 碎片化**

同样是 SPI 发送数据，不同厂商的函数各不相同：

| 厂商 | SPI 发送 API                   |
| ---- | ------------------------------ |
| GD   | `spi_i2s_data_transmit`        |
| ST   | `HAL_SPI_Transmit`             |
| NXP  | `LPSPI_MasterTransferBlocking` |
| LPC  | `SPI_MasterTransferBlocking`   |

后果：项目换 MCU，驱动基本推倒重写；同事之间代码无法复用；每换一家厂商都要重新学习。

**方案：驱动与设备代码分离**

```
应用层（设备驱动代码：读写 W25Q128、驱动 RW007 …）—— 与硬件无关
        ↕ 一套统一 API
对接驱动（每家 MCU 一套）—— 只负责适配硬件
```

**演进路径**：先为 SPI、I2C 等分别制定统一 API → 再抽象出 **I/O 设备管理层**，用 `open / write / read / control / close` 一套接口操作所有设备；复杂设备（PIN / I2C / SPI / 看门狗…）在其上保留**特定设备框架**接口。

## 二、三层架构

| 应用层          一套标准 API 访问设备（find / open / read / write / control / close） |
| ------------------------------------------------------------ |
| I/O 设备管理层    device.c —— 设备容器：注册 / 注销、按名查找、引用计数、open 时自动 init |
| 设备驱动框架层   components/drivers —— 同类设备抽象 pin / i2c / spi / serial / watchdog / rtc … |
| 设备驱动层      BSP 驱动 —— 具体芯片实现：drv_gpio.c / drv_usart.c / drv_spi.c … |

| 层             | 职责                                         | 谁来写                |
| -------------- | -------------------------------------------- | --------------------- |
| I/O 设备管理层 | 封装驱动、提供标准接口；换驱动不影响应用     | RT-Thread 官方        |
| 设备驱动框架层 | 抽取同类驱动的**公共部分**，差异部分留出接口 | RT-Thread 官方        |
| 设备驱动层     | 驱使硬件工作，创建并注册设备实例             | 芯片厂商 / BSP 工程师 |

**两个视角**：

- **横看成层**：自下而上逐层抽象，屏蔽下层差异；
- **纵看成继承**：`rt_object` → `rt_device` → 各具体设备类，子类实现父类接口 —— 面向对象（面向接口）编程。无论底层是 STM32 还是 GD32，串口驱动都对接到同一个串口框架类。

> 结论：新增一个 BSP 时，通常**只需写设备驱动层**，上面两层官方已写好。

**两条注册路径**（设备进入系统的两种方式）：

| 路径       | 适用设备                               | 流程                                                         |
| ---------- | -------------------------------------- | ------------------------------------------------------------ |
| 直接注册   | 逻辑简单的设备（如课堂 test 字符设备） | create → `rt_device_register` → 应用 `find`                  |
| 经框架注册 | 复杂设备（看门狗 / 串口 / I2C 总线…）  | 按设备模型创建 → `rt_hw_watchdog_register` 等注册到框架 → 框架再注册到 I/O 设备管理器 |

## 三、I/O 设备模型

### 3.1 设备对象：面向对象的继承

设备是内核对象的一种，通过**继承**派生：

```
rt_object（内核对象基类：名字、类型、链表）
  └── rt_device（设备基类）
        ├── 字符设备（串口 / 按键…）
        ├── 块设备（Flash / SD…）
        └── 总线设备（I2C 总线 / SPI 总线…）
```

`rt_device` 关键字段：

| 字段                          | 含义                                        |
| ----------------------------- | ------------------------------------------- |
| `parent`                      | 继承的内核对象（含设备名，`find` 按名查找） |
| `type`                        | 设备类型（分类枚举）                        |
| `flag` / `open_flag`          | 注册标志 / 打开标志                         |
| `ref_count`                   | 引用计数（每 open 一次 +1）                 |
| `rx_indicate` / `tx_complete` | 收发回调函数指针                            |
| `ops`                         | 操作方法集（6 个函数指针）                  |
| `user_data`                   | 驱动私有数据                                |

### 3.2 设备分类：字符设备 vs 块设备

|          | 字符设备             | 块设备                         |
| -------- | -------------------- | ------------------------------ |
| 典型设备 | 串口、键盘、按键     | Flash、SD 卡、硬盘             |
| 访问方式 | 字节流，**顺序**读写 | **随机**寻址，按块（512B）读写 |
| 本质区别 | 不可随机访问         | 可随机访问                     |

其他类型：`NetIf / MTD / RTC / Sound / Graphic / I2CBUS / SPIBUS / SPIDevice / SDIO / USBDevice / USBHost / Miscellaneous`（枚举见 `rtdef.h` 的 `rt_device_class_type`）。

**为什么要分类**：不同组件依赖不同类型的设备，分类后即可**对一类设备统一控制**——

- MSH 可重定向到任意**字符设备**（把 LCD 模拟成字符设备，打印就能输出到屏幕）；
- FatFS 文件系统依赖**块设备**（SD 卡、RAM 都可实现为块设备）。

### 3.3 ops 操作集：上下层对接的核心

设备驱动实现 ops，完成「上层 API ↔ 底层硬件」的对接：

| 方法      | 职责 / 触发时机                                  |
| --------- | ------------------------------------------------ |
| `init`    | 初始化设备，成功后置激活标志，**不会重复初始化** |
| `open`    | 打开设备，建议在此才真正使能硬件                 |
| `close`   | 关闭设备，`ref_count` 减到 0 才真正关闭          |
| `read`    | 读数据，`pos` 为偏移量（字符设备通常忽略）       |
| `write`   | 写数据，`pos` 为偏移量                           |
| `control` | 按 `cmd` 控制设备，命令多由驱动自定义            |

**两条铁律**（课堂实验验证）：

1. `rt_device_open` 时若设备未初始化，会**自动调用 init**；
2. 设备未 open 时，`read / write` **不会执行**。

> 验证方法：单步调试跟踪调用栈，可见上层 API 逐层调用到具体厂商实现（如 STM32 HAL 库），ops 函数指针在此过程中逐层赋值。

## 四、设备访问 API

### 4.1 生命周期

```
驱动侧：rt_device_create ──▶ 挂接 ops ──▶ rt_device_register ──▶ 进入设备管理器链表
应用侧：rt_device_find ──▶ rt_device_open ──▶ read / write / control ──▶ rt_device_close
```

| API                                           | 作用             | 要点                                    |
| --------------------------------------------- | ---------------- | --------------------------------------- |
| `rt_device_create(type, attach_size)`         | 从堆创建控制块   | `attach_size` 为附加私有数据大小        |
| `rt_device_register(dev, name, flags)`        | 注册进设备管理器 | 名字不可重名，长度受 `RT_NAME_MAX` 限制 |
| `rt_device_unregister / destroy`              | 注销 / 销毁      | 注销不释放内存，销毁才释放              |
| `rt_device_find(name)`                        | 按名查找         | 找不到返回 `RT_NULL`                    |
| `rt_device_init(dev)`                         | 初始化           | 已激活则直接返回                        |
| `rt_device_open(dev, oflag)`                  | 打开             | 未初始化先自动 init                     |
| `rt_device_close(dev)`                        | 关闭             | 与 open 配对                            |
| `rt_device_read / write(dev, pos, buf, size)` | 读写             | 返回实际字节数，0 需查 errno            |
| `rt_device_control(dev, cmd, arg)`            | 控制             | 通用命令 + 驱动自定义命令               |

注册后可在 FinSH 执行 `list_device` 查看设备名、类型与引用计数。

### 4.2 标志位速查

- **注册 flags**：`RDONLY / WRONLY / RDWR`、`STANDALONE`（禁止重复打开）、`STREAM`（`\n` 自动补 `\r`）、`INT_RX / DMA_RX / INT_TX / DMA_TX`、`REMOVABLE`、`SUSPENDED`
- **打开 oflags**：`RDONLY / WRONLY / RDWR`，以及 `INT_RX`、`DMA_RX` 等模式

> ⚠️ 要使用接收回调，**必须以 `INT_RX` 或 `DMA_RX` 方式打开**设备，否则回调不生效。

### 4.3 数据收发回调

中断 / DMA 场景下避免应用轮询等待：

| API                                       | 触发时机                                                     |
| ----------------------------------------- | ------------------------------------------------------------ |
| `rt_device_set_rx_indicate(dev, rx_ind)`  | 硬件收到数据，通知上层「有数据到达」（回调携带长度），上层随后 `read` 取数 |
| `rt_device_set_tx_complete(dev, tx_done)` | 底层发送完成（DMA / FIFO 完成中断），回调携带发送 buffer 地址 |

回调链：**硬件中断 → 底层驱动 → 框架层 → 上层应用回调**。

### 4.4 字符设备驱动实例（test_drv.c）

```c
/* —— 驱动侧：创建字符设备并挂接 6 个 ops（各方法内部仅打印日志）—— */
int my_char_dev_init(void)
{
    rt_device_t dev = rt_device_create(RT_Device_Class_Char, 0);
    if (dev == RT_NULL)
        return -RT_ERROR;

    dev->init    = my_char_init;      /* 6 个 ops 均为自实现函数 */
    dev->open    = my_char_open;
    dev->close   = my_char_close;
    dev->read    = my_char_read;
    dev->write   = my_char_write;
    dev->control = my_char_control;

    if (rt_device_register(dev, "my_char", RT_DEVICE_FLAG_RDWR) != RT_EOK)
        return -RT_ERROR;
    return RT_EOK;
}
INIT_BOARD_EXPORT(my_char_dev_init);   /* 系统启动时自动完成设备注册 */

/* —— 应用侧：find → open → control → write → read → close —— */
static int my_char_app(void)
{
    rt_device_t dev = rt_device_find("my_char");   /* 按注册名查找 */
    if (dev == RT_NULL)
        return -RT_ERROR;

    rt_device_open(dev, RT_DEVICE_OFLAG_RDWR);     /* 未初始化会先自动 init */
    rt_device_control(dev, RT_DEVICE_CTRL_CONFIG, RT_NULL);
    rt_device_write(dev, 0, "hello", 5);           /* pos 为偏移量，字符设备常忽略 */
    rt_device_read(dev, 0, rx_buf, 128);
    rt_device_close(dev);
    return RT_EOK;
}
MSH_CMD_EXPORT(my_char_app, run char device demo);
```

## 五、PIN 框架（GPIO）

芯片引脚分 4 类：电源、时钟、控制、通用 I/O（GPIO，可复用为 SPI / I2C / UART 等功能）。

| API                                       | 作用                                                         |
| ----------------------------------------- | ------------------------------------------------------------ |
| `rt_pin_mode(pin, mode)`                  | 配置模式：`OUTPUT` / `INPUT` / `INPUT_PULLUP` / `INPUT_PULLDOWN` / `OUTPUT_OD` |
| `rt_pin_write(pin, value)`                | 输出 `PIN_LOW` / `PIN_HIGH`                                  |
| `rt_pin_read(pin)`                        | 读电平，返回 `PIN_LOW` / `PIN_HIGH`                          |
| `rt_pin_attach_irq(pin, mode, hdr, args)` | 绑定中断回调，5 种触发：上升沿 / 下降沿 / 双边沿 / 高电平 / 低电平 |
| `rt_pin_irq_enable(pin, enabled)`         | 使能 / 失能中断                                              |
| `rt_pin_detach_irq(pin)`                  | 脱离中断回调                                                 |

**按键中断实例**（基于 dev_test.c ，4 个按键：上拉输入 + 下降沿触发）：

```c
#define KEY_0  GET_PIN(C, 5)      /* 4 个可编程按键，映射到 PC5 / PC1 / PC0 / PC4 */
#define KEY_1  GET_PIN(C, 1)
#define KEY_2  GET_PIN(C, 0)
#define KEY_3  GET_PIN(C, 4)

static void key_0_handler(void *args)        /* 中断回调 */
{
    LOG_I("key 0 pressed, level = %d", rt_pin_read(KEY_0));
}
/* key_1 / key_2 / key_3 回调同理 */

void key_irq_setup(void)
{
    rt_pin_mode(KEY_0, PIN_MODE_INPUT_PULLUP);      /* 上拉输入 */
    rt_pin_mode(KEY_1, PIN_MODE_INPUT_PULLUP);
    rt_pin_mode(KEY_2, PIN_MODE_INPUT_PULLUP);
    rt_pin_mode(KEY_3, PIN_MODE_INPUT_PULLUP);

    rt_pin_attach_irq(KEY_0, PIN_IRQ_MODE_FALLING, key_0_handler, RT_NULL);
    rt_pin_attach_irq(KEY_1, PIN_IRQ_MODE_FALLING, key_1_handler, RT_NULL);
    rt_pin_attach_irq(KEY_2, PIN_IRQ_MODE_FALLING, key_2_handler, RT_NULL);
    rt_pin_attach_irq(KEY_3, PIN_IRQ_MODE_FALLING, key_3_handler, RT_NULL);

    rt_pin_irq_enable(KEY_0, PIN_IRQ_ENABLE);       /* 使能中断 */
    rt_pin_irq_enable(KEY_1, PIN_IRQ_ENABLE);
    rt_pin_irq_enable(KEY_2, PIN_IRQ_ENABLE);
    rt_pin_irq_enable(KEY_3, PIN_IRQ_ENABLE);
}
MSH_CMD_EXPORT(key_irq_setup, enable key irq);
```

**经验**：

- 机械按键抖动会触发多次中断 → 延时消抖或使用 **FlexibleButton** 软件包；
- 中断「没反应」先检查 ulog 日志级别（`LOG_LVL`）是否把打印过滤掉了。

## 六、I2C 框架

**协议要点**：

- 两线：SCL（时钟）+ SDA（数据），速率分 10K / 100K / 400K / 3.4M 四档；
- **起始位 S**：SCL 高电平时 SDA 由高变低；**结束位 P**：SCL 高电平时 SDA 由低变高；
- 每传输一个字节，接收方回 **ACK**（拉低 SDA）或 **NACK**；
- 从机地址 7 位，总线上以「7 位地址 + 1 位读写位（0 写 / 1 读）」的 8 位形式出现；也支持 10 位地址。

**使用 4 步**：

1. `rt_device_find("i2c2")` 找到总线（一般名为 `i2c0 / i2c1 …`）；
2. 构造消息 `struct rt_i2c_msg { addr; flags; buf; len; }`，一次可传多条；
3. `rt_i2c_transfer(bus, msgs, n)` 传输，返回成功传输的消息数；
4. 处理结果。

**四种常用模式**（i2c_sample.c 四个示例函数）：

| 模式                  | 消息构造                           |
| --------------------- | ---------------------------------- |
| 写 1 字节（写寄存器） | 1 条写消息                         |
| 写多字节              | 1 条写消息，len 更长               |
| 读 1 字节             | 2 条消息：先写寄存器地址，再读数据 |
| 读多字节              | 同上，读消息 len 更长              |

**读单字节示例**（最能体现「一次传输多条消息」的用法）：

```c
struct rt_i2c_bus_device *bus;
struct rt_i2c_msg msg_list[2];
rt_uint8_t reg_buf[1], data_buf[1];

bus = (struct rt_i2c_bus_device *)rt_device_find("i2c2");

reg_buf[0] = 0x75;                  /* 要读的寄存器地址（WHO_AM_I） */

msg_list[0].addr  = 0x68;           /* 从机 7 位地址 */
msg_list[0].flags = RT_I2C_WR;      /* 第一条：写寄存器地址 */
msg_list[0].buf   = reg_buf;
msg_list[0].len   = 1;

msg_list[1].addr  = 0x68;
msg_list[1].flags = RT_I2C_RD;      /* 第二条：读数据 */
msg_list[1].buf   = data_buf;
msg_list[1].len   = 1;

if (rt_i2c_transfer(bus, msg_list, 2) == 2)     /* 一次传输 2 条消息 */
    rt_kprintf("who am i = 0x%02x\n", data_buf[0]);
```

**三大坑**：

1. **总线死锁**：主机复位时从机正拉低 SDA 等待 SCL → 双方互等。解锁：传输前在 SCL 上发 **9 个时钟脉冲**，让从机完成挂起的传输：

```c
static rt_err_t i2c_bus_recover(const struct stm32_soft_i2c_config *cfg)
{
    rt_int32_t cnt = 0;
    if (PIN_LOW == rt_pin_read(cfg->sda)) {
        while (cnt++ < 9) {                  /* 9 个时钟脉冲恢复总线 */
            rt_pin_write(cfg->scl, PIN_HIGH);
            rt_hw_us_delay(100);
            rt_pin_write(cfg->scl, PIN_LOW);
            rt_hw_us_delay(100);
        }
        if (PIN_LOW == rt_pin_read(cfg->sda))
            return -RT_ERROR;
        return RT_EOK;
    }
}
```

2. **地址错误** → `rt_i2c_transfer` 返回 **-5**：7 位地址写成 8 位，或两条消息地址不一致：

```c
msg_list[0].addr = 0x68;   /* 写消息用 0x68 */
msg_list[1].addr = 0x6D;   /* 读消息却用 0x6D → transfer 返回 -5 */
```

3. **禁止在中断里调用**：`rt_i2c_transfer` 内部会取互斥锁，中断服务函数中调用会 assert 报错。

> 配置：menuconfig 开启 I2C 驱动；无硬件 I2C 的芯片可用 **GPIO 模拟 I2C**（软件 I2C）；调试可用 **i2c-tools** 软件包（`i2c scan i2c3` 扫描从机）。

## 七、SPI 框架

**特点**：高速、全双工、同步，4 线通信（SCLK / MOSI / MISO / CS），常用于 Flash、EEPROM、AD 等。

**总线-设备模型**：

- **SPI 总线** = 控制器，需先注册；
- **SPI 设备** = 挂在总线上、由 CS 引脚区分的从设备，用 `rt_spi_bus_attach_device()` 挂载（STM32 BSP 提供 `rt_hw_spi_device_attach()`）；
- **命名**：总线 `spix`，设备 `spixy`（x = 总线号，y = 设备序号）。如 `spi10` = spi1 总线上 0 号设备（示例见下）。

**配置** `struct rt_spi_configuration`：

| 字段         | 取值                                                         |
| ------------ | ------------------------------------------------------------ |
| `mode`       | `RT_SPI_MASTER / SLAVE` ｜ `RT_SPI_MODE_0~3`（CPOL/CPHA）｜ `RT_SPI_MSB / LSB` ｜ `RT_SPI_CS_HIGH` 等 |
| `data_width` | 8 / 16 / 32 位                                               |
| `max_hz`     | 时钟频率                                                     |

**收发 API**：

| API                           | 说明                                               |
| ----------------------------- | -------------------------------------------------- |
| `rt_spi_transfer`             | 同时收发一次数据                                   |
| `rt_spi_send` / `rt_spi_recv` | 只发送 / 只接收                                    |
| `rt_spi_send_then_send`       | 连发两段，**片选不释放**（典型：先发地址再发数据） |
| `rt_spi_send_then_recv`       | 先发后收，片选不释放；接收阶段主机发送 **0xFF**    |
| `rt_spi_transfer_message`     | 自定义消息传输                                     |

**示例**（spi_sample.c ）：

```c
/* 挂载：spi1 总线上 0 号设备，CS = PA4（INIT_DEVICE_EXPORT 自动执行） */
rt_hw_spi_device_attach("spi1", "spi10", GET_PIN(A, 4));

/* 查找 + 配置 */
struct rt_spi_device *spi_dev = (struct rt_spi_device *)rt_device_find("spi10");
struct rt_spi_configuration cfg;
cfg.data_width = 8;
cfg.mode       = RT_SPI_MASTER | RT_SPI_MODE_0 | RT_SPI_MSB;
cfg.max_hz     = 1 * 1000 * 1000;                    /* 1M */
rt_spi_configure(spi_dev, &cfg);

/* 传输：同时收 / 发 1 字节 */
rt_uint8_t tx_byte = 0x5A, rx_byte = 0;
rt_spi_transfer(spi_dev, &tx_byte, &rx_byte, 1);

/* 连发两段（片选不释放）：先发命令，再发数据 */
rt_uint8_t cmd[2]  = {0x1A, 0x99}, data[2] = {0x12, 0x39};
rt_spi_send_then_send(spi_dev, cmd, 2, data, 2);

/* 先发后收（片选不释放）：发 cmd，收 data */
rt_spi_send_then_recv(spi_dev, cmd, 2, data, 2);
```

## 八、驱动包与自动初始化

### 8.1 设备驱动包（Package）

复杂传感器（如 ICM20608 六轴传感器）已有现成驱动包：包内部基于 I2C 框架完成驱动，应用层只需「初始化 → 校准 → 轮询读取」（基于 icm_20608_sample.c 改编）：

```c
sensor = icm20608_init("i2c2");                /* 基于 I2C 框架初始化传感器 */
icm20608_calib_level(sensor, 10);              /* 采样 10 次求零值校准 */

while (count++ < 100)                          /* 线程内轮询读取 */
{
    icm20608_get_accel(sensor, &ax, &ay, &az); /* 三轴加速度 */
    icm20608_get_gyro(sensor, &gx, &gy, &gz);  /* 三轴陀螺仪 */
    rt_thread_mdelay(1000);
}
```

### 8.2 自动初始化机制

驱动注册无需应用手动调用 —— 通过链接文件生成函数指针表，启动时按阶段自动执行：

| 宏                       | 阶段               | 典型用途         |
| ------------------------ | ------------------ | ---------------- |
| `INIT_BOARD_EXPORT(fn)`  | 板级初始化（最早） | 芯片级外设初始化 |
| `INIT_DEVICE_EXPORT(fn)` | 设备初始化         | 设备驱动注册     |
| `INIT_APP_EXPORT(fn)`    | 应用初始化（最后） | 应用自动启动     |

```c
INIT_BOARD_EXPORT(my_char_dev_init);   /* 板级初始化：最早执行 */
INIT_DEVICE_EXPORT(key_dev_init);      /* 设备初始化：驱动注册 */
INIT_APP_EXPORT(app_auto_start);       /* 应用初始化：最后执行 */
```
