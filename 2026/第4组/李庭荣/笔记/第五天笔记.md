- RT-Thread 内核版本：4.1.1。

## 三、AHT10 采集

源文件：

~~~text
D:\RT-ThreadStudio\workspace\01_KERNEL_1\applications\aht10_explam.c
~~~

关键实现：

- 使用软件 I2C 总线 `i2c3`。
- 通过 `aht10_init()` 获取设备句柄。
- 使用互斥量保护 AHT10 初始化和读取过程。
- `aht10_read_current()` 向 MQTT 应用提供统一读取接口。
- 周期读取线程的采样周期为 2000 ms。
- 输出采用整数缩放，避免依赖 `%f` 浮点格式化。

实测首次采集曾出现 `-50.00 / 0.00`，后续读数稳定在约 `29.97 C / 82.4%`。因此首个缺省值不能单独作为传感器正常工作的结论，应以初始化完成后的连续读数为准。

## 四、RW007 与 MQTT

RW007 使用 SPI2，片选为 PF10；W25Q64 也使用 SPI2，片选为 PB12。两者共用总线时，访问一个设备前必须保证另一个设备的 CS 处于释放状态。本次在 Flash 探测前主动将 RW007 的 PF10 CS 拉高，解决了 SPI 设备互相干扰造成的探测失败。

MQTT 应用源文件：

~~~text
D:\RT-ThreadStudio\workspace\01_KERNEL_1\applications\mqtt_app.c
~~~

当前参数：

~~~text
Broker: broker.emqx.io:1883
Topic: rtt/20260821/test
周期默认值: 2000 ms
文件: /fal/Data.txt
~~~

主要命令：

~~~text
mqtt_start
mqtt_aht10
mqtt_aht10_start 2000
mqtt_aht10_stop
mqtt_publish <message>
~~~

每次采集生成带 `Temp`、`Humi`、`Count` 的 MQTT 消息，同时以追加方式写入 Flash 文件。实测 `Count:1` 至 `Count:10` 均产生，说明采集、计数、发布和线程循环均运行。

MQTT 长连接过程中出现过 Ping 响应超时，随后 Paho 自动重连成功。这是本次运行限制，不能把一次连接成功扩大解释为网络始终稳定。

## 五、DFS/FAL/SFUD 文件系统

相关板级文件：


排查过程中修正了两个板级问题：

1. SPI Flash 探测前释放 RW007 的 PF10 CS。
2. `fal_init()` 成功时返回分区数量，因此改为只判断负值错误，避免把返回值 7 误判成失败。

最终使用 `font` 分区创建块设备并挂载到 `/fal`。格式化和挂载完成后，串口实测结果为：

~~~text
elm    filesy    /fal
Data.txt 381
~~~

切换到任务要求的 `font` 分区并重新格式化后，复位日志确认 `font -> /fal` 挂载成功。恢复 WiFi 后重新运行 MQTT 周期任务，`cat /fal/Data.txt` 读出 4 条新记录：`Count:1` 的初始化缺省值，以及 `Count:2` 至 `Count:4` 的正常温湿度读数。

`df` 无参数执行时返回 `dfs_statfs failed.`，当前不将它作为挂载失败结论；已验证的挂载、读写和文件存在性不受影响。

## 九、具体实现文件与操作

### 1. 文件修改位置

```text
applications/aht10_explam.c
    AHT10 软件包初始化，i2c3 读取，aht10_read_current()

applications/mqtt_app.c
    MQTT broker/topic 配置
    AHT10 数据 JSON 发布
    /fal/Data.txt 追加写入
    toggle -> PF12 LED_R 翻转

libraries/Board_Drivers/drv_filesystem.c
    FS_PARTITION_NAME = "font"
    fal_blk_device_create("font")
    dfs_mount(..., "/fal", "elm", ...)

libraries/Board_Drivers/fal/fal_cfg.h
    FAL 分区表中的 font 分区
```

### 2. 关键代码

```c
#define MQTT_AHT10_DATA_FILE "/fal/Data.txt"
#define MQTT_LED_PIN GET_PIN(F, 12)

if ((payload_len == 6) && (rt_memcmp(payload, "toggle", 6) == 0))
{
    rt_pin_write(MQTT_LED_PIN, !rt_pin_read(MQTT_LED_PIN));
}
```

每次采集先生成 MQTT JSON，再使用 `O_WRONLY | O_CREAT | O_APPEND` 打开 `/fal/Data.txt`，因此同一条采集数据同时上传云端并追加到 Flash。

### 3. 构建、下载和分区初始化

在 RT-Thread Studio Env 旧版环境中构建：

```powershell
$env:RTT_EXEC_PATH = "D:\RT-ThreadStudio\platform\env_released\env\tools\gnu_gcc\arm_gcc\mingw\bin"
$env:Path = "D:\RT-ThreadStudio\platform\env_released\env\tools\Python27;D:\RT-ThreadStudio\platform\env_released\env\tools\Python27\Scripts;$env:Path"
& "D:\RT-ThreadStudio\platform\env_released\env\tools\Python27\Scripts\scons.bat" -j 4
```

使用根目录 ELF 下载，不使用旧的 `Debug\rtthread.elf`：

```powershell
& "D:\RT-ThreadStudio\repo\Extract\Debugger_Support_Packages\STMicroelectronics\ST-LINK_Debugger\2.11.0\tools\bin\STM32_Programmer_CLI.exe" -c port=SWD -d "D:\RT-ThreadStudio\workspace\01_KERNEL_1\rt-thread.elf" -v -rst
```

复位日志必须先出现 `W25Q64 flash device is initialize success`、`spi20 success` 和 `font` 块设备，再执行：

```text
mkfs -t elm font
```

该命令会清除 `font` 分区，只能在确认分区名正确后执行。

### 4. 开发板串口操作顺序

COM21 参数为 `115200 8-N-1`。以下命令按顺序执行：

```text
wifi join LTR <PASSWORD>
ifconfig
mqtt_start
mqtt_aht10
mqtt_aht10_start 2000
mqtt_aht10_stop
mount
ls /fal
cat /fal/Data.txt
```

本次实测关键输出为 `elm font /fal`、`Data.txt 152`，以及 `Count:1` 到 `Count:4` 四条记录。

电脑端 MQTT 客户端连接 `broker.emqx.io:1883`，订阅或发布主题 `rtt/20260821/test`，发布纯文本消息 `toggle`。开发板串口应出现：

```text
received topic=rtt/20260821/test payload=toggle
MQTT command toggle: LED_R changed
```
