# RT-Thread Day1 学习笔记

## 一、RT-Thread 产品线

RT-Thread 的内核与组件可按设备资源和应用复杂度选择：

| 版本 | 定位 | 主要能力 |
| --- | --- | --- |
| Nano | 资源受限设备 | 实时调度、线程同步通信、时钟、中断和内存管理等基础能力 |
| 标准版 | 常规嵌入式应用 | POSIX API、日志、网络协议栈、IoT 协议和可选中间件 |
| Smart | 带 MMU 的复杂设备 | 内核态与用户态隔离，并支持更复杂的应用运行环境 |

本次学习以 RT-Thread 4.1.1 工程为基础，重点理解应用代码、线程调度和日志输出之间的关系。

## 二、QEMU A9 最小应用

QEMU A9 示例可用于观察 RT-Thread 应用入口与终端输出。最小示例代码如下：

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    printf("hello rt-thread\\n");
    return 0;
}
```

`printf()` 输出用于验证应用入口已经被调用。应用 `main()` 返回后，RT-Thread 内核和其他系统线程仍会继续运行。

## 三、STM32F407ZG 周期日志示例

在 STM32F407ZG 的 RT-Thread 工程中，可以使用日志组件和线程延时实现周期输出：

```c
#include <rtthread.h>

#define DBG_TAG "main"
#define DBG_LVL DBG_LOG
#include <rtdbg.h>

int main(void)
{
    int count = 1;

    while (count++)
    {
        LOG_D("Hello RT-Thread!");
        rt_thread_mdelay(1000);
    }

    return RT_EOK;
}
```

代码要点：

- `rtthread.h` 提供 RT-Thread 内核 API。
- `DBG_TAG` 用于标记日志模块，终端日志中的 `[D/main]` 与该标签对应。
- `LOG_D()` 输出调试等级日志。
- `rt_thread_mdelay(1000)` 让当前线程延时约 1 秒。

终端中已观察到 RT-Thread 启动信息、MSH 命令行和连续的 `[D/main] Hello RT-Thread!` 输出。编译、下载、串口输出和实体开发板运行属于不同层级的验证，应分别记录。

## 四、RT-Thread 启动流程

从芯片复位到应用线程运行的核心流程如下：

```text
复位处理函数
    -> 初始化栈、.data 和 .bss
    -> SystemInit()
    -> rtthread_startup()
    -> 板级初始化与内核对象初始化
    -> 创建 main 线程和 idle 线程
    -> 启动调度器
    -> main 线程执行应用 main()
```

启动文件负责建立 C 运行环境。随后 `rtthread_startup()` 初始化板级资源、内核对象、软件定时器和组件。

应用中的 `main()` 并不是复位后的最早裸机入口，而是作为 `main` 线程的入口函数，在调度器启动后运行。`idle` 线程优先级最低，当没有其他就绪线程时运行。

## 五、线程延时、SysTick 和调度

周期日志的运行过程如下：

```text
main 线程运行
    -> 输出日志
    -> 调用 rt_thread_mdelay(1000)
    -> 当前线程进入延时挂起态
    -> 调度其他就绪线程或 idle 线程
    -> 系统节拍到期
    -> 当前线程恢复就绪并再次输出日志
```

`rt_thread_mdelay(1000)` 不是空循环等待。当前线程挂起后，CPU 可以运行其他线程。

系统节拍通常由 SysTick 产生。每次节拍中断到来时，内核会更新 tick 计数、处理到期的延时线程、推进软件定时器，并在需要时触发调度。

RT-Thread 使用基于优先级的抢占式调度：数值越小表示优先级越高；高优先级线程就绪时可以抢占低优先级线程。

## 六、FinSH/MSH 命令行

FinSH/MSH 组件提供交互式命令行。常用命令包括：

| 命令 | 用途 |
| --- | --- |
| `help` | 查看命令帮助 |
| `ps` | 查看线程状态 |
| `free` | 查看动态内存使用情况 |
| `reboot` | 触发系统复位 |

FinSH/MSH 线程与应用 `main` 线程由同一个调度器管理，因此系统可以在周期输出日志时响应终端命令。

## 七、Git 分支与 Pull Request 流程

开始新内容前，先同步目标分支，再创建独立开发分支：

```bash
git switch master
git pull origin master
git switch -c feature-name
```

完成修改并确认变更范围后，执行：

```bash
git add <changed-files>
git commit -m "Describe the code change"
git push -u origin feature-name
```

推送后，从个人 Fork 的 `feature-name` 分支向上游仓库的 `master` 创建 Pull Request。审核通过后，由上游维护者合并；合并完成后再同步本地 `master`。

## 八、小结

Day1 的核心收获是理解 RT-Thread 应用代码在线程上下文中的运行方式，以及日志、线程延时、SysTick、调度器和 FinSH/MSH 组件之间的关系。后续将继续学习线程创建、线程同步、软件定时器、消息队列和常用设备框架。
