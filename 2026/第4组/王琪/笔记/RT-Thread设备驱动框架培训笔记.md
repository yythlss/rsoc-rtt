# RT-Thread 设备驱动框架与 IO 外设开发培训笔记

> **主题**：RT-Thread设备驱动框架的分层架构与API调用机制，通过GPIO、I2C及SPI实操演示，阐述从底层驱动到上层应用的完整对接流程及代码复用策略。

---

## 一、整体架构总览

```
─────────────────────────────────────────────────────────────────
│                    RT-Thread 设备驱动框架                        │
──────────────────────────────────────────────────────────────
│  上层应用层  │  统一API层    │  设备管理层   │   底层硬件驱动层    │
│  (Application)│  (open/read │ (rt_device  │  (STM32 HAL / BSP) │
│             │  /write/close) │  register)  │                    │
──────────────────────────────────────────────────────────────
│  GPIO按键   │  rt_pin_*    │  字符设备    │  GPIO寄存器操作     │
│  I2C通信    │  rt_i2c_*    │  块设备      │  I2C寄存器操作      │
│  SPI通信    │  rt_spi_*    │  设备链表管理  │  SPI寄存器操作      │
──────────────────────────────────────────────────────────────
```

**核心设计理念**：硬件抽象层 → 统一API → 驱动与应用的分离 → 代码可跨MCU迁移

---

## 二、分层架构与抽象优势

### 2.1 架构演进路线

| 阶段 | 描述 | 关键改进 |
|------|------|---------|
| 初期 | SPI统一API | 统一SPI接口，解决碎片化 |
| 中期 | 统一IO设备管理层 | 扩展至所有外设类型 |
| 现在 | 完整设备框架 | open/write/read/close 标准接口 |

### 2.2 分层设计优势

| 维度 | 说明 |
|------|------|
| **硬件抽象** | SPI/I2C等设备抽象为一层，上层使用统一API，底层对接具体硬件 |
| **代码复用** | 上层应用代码可在不同MCU间无缝迁移，仅需适配底层驱动 |
| **降低碎片化** | 统一接口减少各厂商API差异带来的开发成本 |
| **学习成本** | 掌握一套API即可操作多种硬件，大幅降低学习曲线 |

## 三、设备分类与核心结构

### 3.1 设备类型划分

```
                    rt_device
                        │
            ──────────────────────
            │                       │
      字符设备 (Char)          块设备 (Block)
            │                       │
    ──────────────       ──────────────
    │       │       │       │       │       │
  串口    键盘   按键   硬盘   Flash    SD卡
  (字节流) (字节流) (字节流) (随机寻址)
```

### 3.2 核心数据结构：rt_device

```
──────────────────────────────────────────────────────
│                  rt_device 结构体                      │
─────────────────────────────────────────────────────
│  字段/成员    │  说明                                  │
─────────────────────────────────────────────────────
│  type        │  设备类型（字符设备/块设备）             │
│  flag        │  参数标志位                             │
│  open_flag   │  打开标志（引用计数管理）               │
│  ref_count   │  引用计数，管理设备打开次数             │
│  ops         │  操作函数集（面向对象继承机制）         │
─────────────────────────────────────────────────────
```

### 3.3 设备管理机制

```
rt_device_create  →  rt_device_register  →  加入IO管理系统链表
        │                                        │
        ────────────────────────────────────────
                                         │
                    rt_device_find ─────
                         │
                    rt_device_open
                         │
                    rt_device_init / read / write / close
```

## 四、IO设备管理与API调用流程

### 4.1 设备生命周期

```
──────────    ──────────────    ────────────
│ 创建设备  │───→│  注册到系统   │───→│  初始化设备  │
│ rt_device│    │rt_device_    │    │rt_device_  │
│_create   │    │ register     │    │ init       │
──────────    ──────────────    ───────────
                                           │
                    ──────────────────────
                    │
         ────────────────────
         │  正常工作状态        │
         │  read/write/control   │
         ────────────────────
                    │
         ────────────────────
         │  rt_device_close    │
         │  (引用计数-1, 为0时  │
         │   才真正释放)        │
         ─────────────────────
```

### 4.2 API调用流程（以GPIO为例）

```
应用层                    框架层                    硬件层
  │                        │                        │
  │  rt_pin_write(1)      │                        │
  │───────────────────────→│                        │
  │                        │  pin->ops->write(1)    │
  │                        │───────────────────────→│
  │                        │                        │  写GPIO寄存器
  │                        │───────────────────────│
  │───────────────────────│                        │
  │  (电平设置完成)         │                        │
```

### 4.3 回调机制与中断处理

```
硬件中断触发
    │
    ▼
底层驱动回调 (HAL层)
    │
    ▼
RT-Thread框架层回调
    │
    ▼
上层应用回调函数 (通过 rt_device_set_rx_indicate 等注册)
    │
    ▼
应用得到通知，执行处理逻辑
```

**关键API**：

| API | 作用 |
|-----|------|
| `rt_device_set_rx_indicate` | 设置接收回调函数（中断/DMA模式通知上层） |
| `rt_device_set_tx_complete` | 设置发送完成回调函数 |
| `rt_device_init` | 初始化设备 |
| `rt_device_close` | 关闭设备（引用计数管理） |

## 五、GPIO外设开发与实操

### 5.1 GPIO驱动实现要点

```
─────────────────────────────────────────────────────
│              GPIO 驱动 API 速查表                     │
────────────────────────────────────────────────────
│  API             │  功能说明                        │
────────────────────────────────────────────────────
│  rt_pin_mode()   │  配置引脚模式（输入/输出/开漏）   │
│  rt_pin_write()  │  设置引脚电平（高/低）           │
│  rt_pin_read()   │  读取引脚电平                    │
│  rt_pin_attach_irq() │  绑定引脚中断回调函数         │
|  rt_pin_irq_enable() |  使能或屏蔽指定引脚的中断      |
────────────────────────────────────────────────────
```

### 5.2 引脚模式配置

| 模式 | 说明 |
|------|------|
| 输入（上拉） | 内部上拉电阻，默认高电平 |
| 输入（下拉） | 内部下拉电阻，默认低电平 |
| 输出 | 推挽输出，驱动能力强 |
| 开漏输出 | 需外接上拉电阻，支持线与逻辑 |

### 5.3 中断触发模式

| 触发模式 | 说明 |
|---------|------|
| 上升沿 | 电平从低变高时触发 |
| 下降沿 | 电平从高变低时触发 |
| 双边沿 | 上升沿和下降沿都触发 |
| 高电平 | 高电平时持续触发 |
| 低电平 | 低电平时持续触发 |

### 5.4 **GPIO 中断完整使用流程**

```
① rt_pin_mode(pin, PIN_MODE_INPUT_PULLUP)
        ↓  设置引脚为上拉输入模式
② rt_pin_attach_irq(pin, PIN_IRQ_MODE_FALLING, callback, RT_NULL)
        ↓  绑定回调函数，设置下降沿触发
③ rt_pin_irq_enable(pin, PIN_IRQ_ENABLE)
           使能中断，真正"打开"中断
```

### 5.5 实操问题：按键消抖

```
问题现象：按键触发两次中断
原因分析：机械抖动导致信号多次跳变
──  ──  ──  ──
│  │  │  │  │  │  │  │
────  ──  ──  ──
    ↓抖动区域↓
    
解决方案：
─────────────────  ─────────────────
│  方案A：软件消抖  │  │  方案B：使用button │
│  延时10-20ms后   │  │  库（推荐）       │
│  再次检测电平    │  │  自动处理消抖     │
─────────────────  ─────────────────
```

### 5.6 调试技巧

- **单步调试**：分析GPIO驱动从上层API到底层STM32 HAL库的完整调用栈
- **验证Ops指针**：确认操作函数指针的正确赋值
- **源码分析**：通过 `list_device` 命令查看注册的设备列表

## 六、I2C 总线驱动开发

### 6.1 I2C 通信流程

```
─────────────────────────────────────────────────────────────
│                    I2C 消息传输结构                          │
│                                                             │
│  struct rt_i2c_msg {                                         │
│      rt_uint16_t addr;   ← 设备地址（7位，传输时左移1位）    │
│      rt_uint16_t flags;  ← 读写标志（0=写，1=读）            │
│      rt_uint8_t  *buf;   ← 数据缓冲区指针                    │
│      rt_uint32_t len;    ← 数据长度                          │
│  };                                                          │
─────────────────────────────────────────────────────────────
```

### 6.2 I2C 地址格式

```
7位设备地址:  0b0101000 (示例)
              ↓ 左移1位 + 读写位
8位传输格式:  0b1010000R/W  (R/W=0写, R/W=1读)
```

### 6.3 I2C 总线锁死恢复

```
问题：I2C总线锁死（SDA或SCL被拉低无法释放）
解决方案：产生9个SCL时钟脉冲 → 释放SDA线 → 发送STOP条件
```

## 七、SPI 总线驱动开发

### 7.1 SPI 总线-设备模型

```
─────────────────────────────────────────────────────────
│              SPI 总线-设备模型                            │
│                                                         │
│   SPI总线控制器 (注册)                                   │
│        │                                                │
│        ├──→ spi10 (总线1上的0号设备)                      │
│        │    ── Flash芯片                               │
│        ├──→ spi11 (总线1上的1号设备)                      │
│        │    ── 传感器A                                 │
│        ──→ spi20 (总线2上的0号设备)                      │
│             ── 显示屏                                  │
─────────────────────────────────────────────────────────
```

### 7.2 SPI 配置参数

| 参数 | 可选值 | 说明 |
|------|--------|------|
| 时钟频率 | 1MHz/10MHz等 | SPI时钟速率 |
| 数据宽度 | 8位/16位 | 每次传输的数据位数 |
| CPOL | 0/1 | 时钟极性（空闲电平） |
| CPHA | 0/1 | 时钟相位（数据采样边沿） |
| 数据位序 | MSB/LSB | 高位/低位优先传输 |

### 7.3 设备命名规则

```
spixy 格式：
  x = 总线号 (0, 1, 2...)
  y = 设备序号 (0, 1, 2...)
  
示例：
  spi10 → 总线1上的0号设备
  spi23 → 总线2上的3号设备
```

## 八、开发环境配置对比

### 8.1 两种开发模式对比

| 对比维度 | 基于芯片（BSP）模式 | 基于SDK（CubeMX）模式 |
|---------|---------------------|----------------------|
| 适用场景 | 多种芯片适配 | 特定芯片型号 |
| 配置方式 | 手动配置 board.h/board.c | CubeMX自动生成配置 |
| 自动化程度 | 低（需手动编写） | 高（图形化配置） |
| 灵活性 | 高（完全可控） | 中（受工具限制） |
| 学习曲线 | 较陡 | 较平缓 |
| 适用人群 | 资深嵌入式工程师 | 快速原型开发 |

### 8.2 硬件I2C支持现状

```
─────────────────    ─────────────────
│  软件模拟I2C     │    │  硬件I2C        │
│  (Soft I2C)      │    │  (Hardware)     │
─────────────────    ├─────────────────
│ ✅ 兼容性好      │    │ ✅ 效率高       │
│ ✅ 引脚灵活      │    │  需芯片支持    │
│  占用CPU       │    │  部分包仅支持  │
│    资源          │    │    软件模拟     │
─────────────────    ────────────────
                                 │
                    如需硬件I2C：
                     手动更新驱动
                     或使用主线版本
```

## 九、核心API速查手册

### 9.1 GPIO 相关

| API 函数 | 功能说明 |
|---|---|
| `rt_pin_mode(pin, mode)` | 设置引脚模式（输入/输出/上拉等） |
| `rt_pin_write(pin, value)` | 设置引脚电平（高/低） |
| `rt_pin_read(pin)` | 读取引脚电平 |
| `rt_pin_attach_irq(pin, mode, hdr, args)` | 绑定中断回调函数 + 设置触发模式 |
| `rt_pin_irq_enable(pin, enabled)` | 使能/屏蔽引脚中断 |
| `rt_pin_detach_irq(pin)` | 脱离（解绑）引脚中断回调函数 |

### 9.2 IO设备管理

| API | 功能 |
|-----|------|
| `rt_device_create()` | 创建设备句柄 |
| `rt_device_register(dev, name, flags)` | 注册设备到系统 |
| `rt_device_find(name)` | 查找已注册设备 |
| `rt_device_open(dev, flags)` | 打开设备 |
| `rt_device_read/write/ioctl()` | 读写/控制设备 |
| `rt_device_close(dev)` | 关闭设备 |
| `rt_device_set_rx_indicate()` | 设置接收回调 |
| `rt_device_set_tx_complete()` | 设置发送完成回调 |

### 9.3 I2C 相关

| API | 功能 |
|-----|------|
| `rt_i2c_transfer(bus, msgs, num)` | 传输I2C消息 |

### 9.4 SPI 相关

| API | 功能 |
|-----|------|
| `rt_spi_bus_register()` | 注册SPI总线控制器 |
| `rt_spi_device_attach()` | 挂载SPI设备到总线 |
