# RT-Thread IPC机制与线程同步通信 培训笔记

## 课程概览

- **前置基础**：环境搭建、RTOS启动流程
- **核心议题**：多线程间的同步与通信（IPC）
- **关键概念**：临界区（同一时间仅允许一个线程访问的资源）、阻塞与非阻塞（等待资源时的状态差异）、线程挂起（阻塞时的状态转换）

## 五大IPC机制全景图

```
RT-Thread IPC机制
── 线程同步
│   ├── 信号量 (Semaphore) —— 二值/计数，用于同步与资源管理
│   ├── 互斥量 (Mutex) —— 所有权+优先级继承，用于临界区保护
│   ── 事件集 (Event) —— 32位标志位，用于多事件同步
── 线程通信
    ├── 消息邮箱 (Mailbox) —— 固定4字节，用于指针/整形传递
    ── 消息队列 (Message Queue) —— 变长+紧急插队，用于不定长数据传递
```

## 线程同步机制

### 1. 信号量（Semaphore）

| 维度 | 二值信号量 | 计数信号量 |
|------|-----------|-----------|
| 用途 | 线程同步 | 管理多个资源实例 |
| 初始值 | 通常为 0 | 资源数量 |
| 典型场景 | 任务间触发 | 资源池管理 |

- **API**：动态创建 `rt_sem_create` / 静态初始化 `rt_sem_init`，获取 `take` / 释放 `release`
- **等待策略**：`flag` 参数建议实时性要求高的场景优先选择**优先级等待**模式，而非先进先出
- **实战逻辑**：线程一计数释放信号量 → 线程二等待信号量执行 LED 操作

### 2. 互斥量（Mutex）

**优先级反转问题：**

```
低优先级线程(L) 持有互斥量
    ↓
高优先级线程(H) 抢占（需等互斥量）
    ↓
中优先级线程(M) 抢占（无需等互斥量）
    ↓
结果：M 反而先于 H 执行！← 优先级反转
```

**优先级继承协议（解决方案）：**

```
低优先级线程(L) 持有互斥量
    ↓
L 临时提升至 H 的优先级
    ↓
高优先级线程(H) 等待互斥量释放
    ↓
结果：M 无法抢占，H 优先获得资源 ← 优先级反转被解决
```

- **核心特性**：所有权属性（仅持有者能释放）+ 递归访问（避免死锁）
- **调试验证**：对比有无互斥量保护下 `number1` 和 `number2` 的数值变化，直观展示临界区保护效果

### 3. 事件集（Event）

- **机制**：32位无符号整数表示事件标志位，支持一对多/多对多同步
- **等待模式**：
  - `RT_EVENT_FLAG_OR`：逻辑或，任一事件触发即返回
  - `RT_EVENT_FLAG_AND`：逻辑与，所有指定事件都触发才返回
  - `RT_EVENT_FLAG_CLEAR`：接收后清除对应标志位
- **示例流程**：线程一先以"逻辑或"等待事件3或5 → 再以"逻辑与"等待两者同时发生

## 线程通信机制

### 1. 消息邮箱（Mailbox）

| 特性 | 说明 |
|------|------|
| 消息大小 | 固定4字节（32位指针大小） |
| 适用数据 | 指针、整形数据 |
| 发送方式 | 通常非阻塞（适合中断中使用） |
| 接收方式 | 通常阻塞（需设超时） |

- **实战流程**：线程二交替发送字符串指针 → 线程一接收并打印 → 收到 `"over"` 终止

### 2. 消息队列（Message Queue）

```
普通发送顺序：a → b → c → d → e → f → g → h

紧急插队 rt_mq_urgent：i 插入队列头部

读取顺序：i → a → b → c → d → e → f → g → h
```

- **核心优势**：支持不定长消息传输，通过链表管理消息块
- **紧急插队**：`rt_mq_urgent` 接口将消息插入队列头部，确保高优先级消息优先处理

## 五大IPC机制对比总结

| 机制 | 核心用途 | 数据特性 | 关键API/特性 |
|------|---------|---------|-------------|
| 信号量 | 同步/资源计数 | 无数据传递 | `take` / `release` |
| 互斥量 | 临界区保护 | 无数据传递 | 优先级继承、所有权 |
| 事件集 | 多事件同步 | 标志位触发 | AND/OR逻辑等待 |
| 消息邮箱 | 轻量通信 | 固定4字节 | 非阻塞发送 |
| 消息队列 | 灵活通信 | 不定长数据 | `rt_mq_urgent` 插队 |
