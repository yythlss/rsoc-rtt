## 二、裸机系统与 RTOS 多任务模型

### 2.1 裸机前后台系统

常见裸机程序采用“前后台”结构：

- **前台**：中断服务程序；
- **后台**：`while(1)` 主循环。

```c
int main(void)
{
    hardware_init();

    while (1)
    {
        sensor_process();
        spi_process();
        uart_process();
        lcd_refresh();
    }
}
```

后台任务按照程序顺序依次运行。如果其中一个任务发生长时间阻塞，其后的任务也无法及时得到执行。

```text
ADC
 ↓
SPI  ← 阻塞 1 s
 ↓
LCD
 ↓
Network
```

### 2.2 RTOS 的基本思想

RTOS 将复杂应用拆分为多个独立任务，每个任务由一个线程承载：

```text
Sensor       → Thread 1
UART         → Thread 2
Network      → Thread 3
Display      → Thread 4
Storage      → Thread 5
```

线程由操作系统统一管理，调度器根据线程状态、优先级等信息决定 CPU 当前执行哪个线程。对于单核 MCU，同一时刻仍然只有一个线程真正占用 CPU，多任务效果来自线程之间的快速调度和上下文切换。

## 三、RT-Thread 系统启动流程

STM32 上电后首先进入芯片启动代码，然后完成 C 运行环境初始化，再进入 RT-Thread 的系统启动过程。不同工具链的运行时入口可能不同，但 RT-Thread 会在进入用户 `main()` 之前完成内核初始化。

```text
Reset
  ↓
Startup Code
  ↓
C Runtime
  ↓
rtthread_startup()
  ↓
rt_hw_board_init()
  ↓
Kernel Timer Init
  ↓
Scheduler Init
  ↓
Application Init
  ↓
创建 Main Thread
  ↓
初始化系统线程
  ↓
启动 Scheduler
  ↓
main_thread_entry()
  ↓
Components Init
  ↓
main()
```

### 3.1 `main()` 已经位于线程环境中

RT-Thread 会先创建 Main Thread，再由该线程进入 `main_thread_entry()`，最终执行用户 `main()`。

```text
RT-Thread Kernel
      ↓
Main Thread
      ↓
main_thread_entry()
      ↓
main()
```

因此 `main()` 并不是 MCU 复位后的第一个 C 函数，而是 RT-Thread 内核、调度器和线程管理环境建立后的应用入口。

## 四、RT-Thread 自动初始化机制

RT-Thread 提供组件自动初始化机制，使各模块可以将初始化函数注册到系统初始化流程中，而不必全部在 `main()` 中手动调用。

```text
Module Init Function
        ↓
注册到自动初始化体系
        ↓
RT-Thread Startup
        ↓
rt_components_init()
        ↓
按初始化顺序执行
        ↓
进入 main()
```

这种机制可以使驱动、组件和应用各自维护初始化函数，降低 `main.c` 与各模块之间的耦合。

## 五、线程控制块 `struct rt_thread`

RT-Thread 使用线程控制块 TCB（Thread Control Block）保存每个线程的运行信息。对应核心数据结构为：

```c
struct rt_thread
```

线程控制块包含线程名称、状态、优先级、入口函数、参数、线程栈和时间片等信息。

```text
struct rt_thread
│
├── object information
├── stack pointer
├── entry
├── parameter
├── stack address
├── stack size
├── thread state
├── current priority
├── initial priority
├── time slice
├── timer
└── kernel management information
```

### 5.1 线程对象模型

RT-Thread 内核使用统一对象模型管理线程等内核资源：

```text
rt_object
    ↑
rt_thread
```

基础对象提供名称、类型、标志、链表等公共属性，线程对象在此基础上增加线程相关字段。

## 六、线程栈与上下文切换

每个线程拥有独立线程栈。线程栈既保存函数局部变量和调用现场，也用于保存线程切换时的 CPU 上下文。

```text
Thread A Running
      ↓
保存 Thread A Context
      ↓
Thread A Stack

Thread B Stack
      ↓
恢复 Thread B Context
      ↓
Thread B Running
```

线程再次被调度时，系统从该线程自己的栈中恢复上下文，因此线程可以从上次被切换的位置继续执行。

### 6.1 线程栈大小

线程栈过小可能导致 Stack Overflow，进一步造成内存破坏；线程栈过大则会浪费 MCU RAM。大型局部变量、深层函数调用和递归都会增加线程栈需求。

## 七、线程状态与生命周期

RT-Thread 线程主要包含以下状态：

| 状态 | 含义 |
|---|---|
| `RT_THREAD_INIT` | 初始态 |
| `RT_THREAD_READY` | 就绪态 |
| `RT_THREAD_RUNNING` | 运行态 |
| `RT_THREAD_SUSPEND` | 挂起态 |
| `RT_THREAD_CLOSE` | 关闭态 |

基本状态转换：

```text
              startup
INIT ----------------------> READY
                               |
                               | scheduler
                               v
                            RUNNING
                             /    \
                            /      \
                    delay/wait    preempt
                         /          \
                        v            v
                    SUSPEND        READY
                        |
                  resume/timeout
                        |
                        v
                      READY
```

线程创建后首先处于 `INIT`，调用 `rt_thread_startup()` 后进入 `READY` 并参与调度。

线程可以因为延时、等待 IPC 对象或主动挂起从 `RUNNING` 进入 `SUSPEND`；条件满足后重新进入 `READY`。

## 八、线程调度：优先级抢占与时间片轮转

RT-Thread 中优先级数字越小，线程优先级越高。

```text
Thread A : priority = 10
Thread B : priority = 20
```

A 的优先级高于 B。当 B 正在运行而 A 进入就绪态时，A 可以抢占 B。

```text
Thread B RUNNING
       ↓
Thread A READY
       ↓
A priority higher
       ↓
Thread B 被抢占
       ↓
Thread A RUNNING
```

### 8.1 时间片轮转

时间片用于相同优先级就绪线程之间的轮转。

```text
Thread A
priority = 16
time slice = 5

Thread B
priority = 16
time slice = 5
```

当两者同时就绪时，可以按照时间片轮转：

```text
A → B → A → B → ...
```

因此：

```text
Priority   → 不同优先级之间谁先执行
Time Slice → 同优先级线程之间如何轮转
```

## 九、RT-Thread 系统线程

RT-Thread 除用户线程外，还存在系统线程，主要包括 Main Thread、Timer Thread（配置相关）和 Idle Thread。

### 9.1 Main Thread

用户 `main()` 最终在 Main Thread 上下文中执行。

### 9.2 Idle Thread

Idle Thread 是系统最低优先级线程。当没有其他可运行线程时，CPU 执行 Idle Thread。

```text
No Ready User Thread
       ↓
Idle Thread
```

Idle Thread 还可承担退出线程的资源回收，以及低功耗等系统空闲任务。

## 十、静态线程与动态线程

### 10.1 静态线程

静态线程使用：

```c
rt_thread_init()
```

用户提前准备线程控制块和栈：

```c
static struct rt_thread thread1;
static rt_uint8_t thread1_stack[1024];
```

然后调用：

```c
rt_thread_init(&thread1,
               "thread1",
               thread1_entry,
               RT_NULL,
               thread1_stack,
               sizeof(thread1_stack),
               20,
               10);
```

### 10.2 动态线程

动态线程使用：

```c
rt_thread_create()
```

例如：

```c
rt_thread_t tid;

tid = rt_thread_create("thread1",
                       thread1_entry,
                       RT_NULL,
                       1024,
                       20,
                       10);
```

动态创建时，线程控制块和线程栈由系统在运行时从动态内存中申请。

### 10.3 两种方式对比

| 项目 | 静态线程 | 动态线程 |
|---|---|---|
| API | `rt_thread_init()` | `rt_thread_create()` |
| TCB | 用户提供 | 运行时分配 |
| Stack | 用户提供 | 运行时分配 |
| Heap 依赖 | 否 | 是 |
| 内存确定时间 | 编译 / 链接阶段 | 运行阶段 |
| 内存确定性 | 较高 | 相对较低 |
| 使用复杂度 | 较高 | 较低 |

## 十一、线程创建、启动与延时

`rt_thread_create()` 或 `rt_thread_init()` 只负责建立线程，此时线程处于 `INIT`。必须进一步调用：

```c
rt_thread_startup(thread);
```

才能进入 `READY` 并参与调度。

```text
Thread Entry
     ↓
create / init
     ↓
RT_THREAD_INIT
     ↓
rt_thread_startup()
     ↓
RT_THREAD_READY
     ↓
Scheduler
     ↓
RT_THREAD_RUNNING
```

典型线程入口：

```c
static void thread_entry(void *parameter)
{
    while (1)
    {
        rt_kprintf("thread running\n");
        rt_thread_mdelay(500);
    }
}
```

调用延时后：

```text
RUNNING
   ↓
rt_thread_mdelay()
   ↓
SUSPEND
```

当前线程暂时退出 CPU 竞争，延时结束后重新进入 `READY`。

## 十二、SCons 与 RT-Thread 构建系统

RT-Thread 工程使用 SCons 进行构建管理。常见构建文件包括：

```text
SConstruct
SConscript
```

其中 `SConstruct` 是工程顶层构建入口，`SConscript` 用于描述具体目录中的源文件、头文件路径、依赖和编译参数。

### 12.1 Source Files

`src` 用于指定参与编译的源文件：

```python
src = ['file1.c', 'file2.c']
```

### 12.2 `CPPPATH`

`CPPPATH` 用于配置头文件搜索路径。

```text
source.c
  ↓
#include "board.h"
  ↓
Compiler
  ↓
根据 CPPPATH 查找 board.h
```

### 12.3 `DefineGroup`

`DefineGroup()` 用于把一组源文件、依赖和编译配置组织为一个构建组。

```text
Group
├── Name
├── Source Files
├── Dependency
├── Include Paths
└── Compile Options
```

### 12.4 条件依赖

RT-Thread 可以根据配置宏决定某个模块是否参与构建。

```text
Kconfig / Configuration
        ↓
配置宏
        ↓
Depend / GetDepend
        ↓
条件满足？
     /       \
   Yes       No
    ↓         ↓
加入 Build   不参与 Build
```

因此文件存在于工程目录，并不代表一定参与最终编译。

### 12.5 子目录构建

不同目录可以拥有自己的 `SConscript`：

```text
Project
│
├── applications/
│   └── SConscript
├── drivers/
│   └── SConscript
├── components/
│   └── SConscript
└── ...
```

父级构建脚本继续加载子目录构建脚本，从而形成模块化、分层的工程构建结构。
