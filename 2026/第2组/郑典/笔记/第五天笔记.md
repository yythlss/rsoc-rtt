# 第五天笔记

## 一、RT-Thread 软件包生态

### 1. 索引与仓库机制

- RT-Thread 的软件包通过 **Kconfig 配置索引** 统一管理，索引文件位于 Env 目录下的 `packages`（软件包）文件夹中；在工程 `Kconfig` 里通过 `source "$PKGS_DIR/Kconfig"` 引入，其中 `PKGS_DIR` 默认即 `packages`。
- 每个软件包都是**独立维护的仓库**（多数托管在 Gitee/GitHub），通过 git 拉取到本地后参与编译；要给某个软件包贡献代码，需要向对应仓库提交 **PR**，而不是直接改本地副本。

### 2. 版本兼容策略

- RT-Thread Studio 为兼容不同版本内核，内置了**两份 Env 配置**：
  - 内核 **5.1.0 以下** → 使用 **1.5.x** 版本的 Env；
  - 内核 **5.1.0 及以上** → 使用**新版 Env**。
- 选错 Env 版本可能导致软件包索引、menuconfig 或 scons 构建行为不一致，排查包相关问题时先确认当前内核版本与 Env 版本是否匹配。

### 3. 软件包使用要点

- 添加软件包后要**关注依赖项**：例如使用传感器类软件包时，通常依赖 **sensor 设备框架**，只开启软件包本身不够，还要手动把依赖框架一并使能。
- 部分软件包的**官方文档可能缺失或滞后**，此时要以**头文件和源码**为准去理解 API（函数签名、结构体字段、返回值），必要时直接看示例代码。
- 常用组件：传感器驱动（sensor 框架）、WiFi（RW007）、MQTT（如 paho-mqtt / kawaii-mqtt）、FreeRTOS 兼容层（POSIX/FreeRTOS wrapper）等。

## 二、HT10 温度传感器驱动

> HT10 是典型的 I2C 温湿度传感器，接入 RT-Thread 后走 **sensor 设备框架**，应用层通过标准设备接口读取数据。

### 1. 环境配置

- 在 menuconfig 中**使能 HT10 软件包**（RT-Thread online packages → peripheral libraries and drivers → sensors drivers）。
- **手动开启依赖的 sensor 设备框架**（RT-Thread Components → Device Drivers → Using Sensor），否则会编译报错。
- 如需在 `rt_kprintf` 中**打印浮点数**，需额外使能 **libm** 软件包（默认 libc 不带浮点格式化），或者改用整数定点打印（如温度 ×10 后拆成整数和小数）。

### 2. API 调用流程

- 先调用软件包提供的**初始化函数**，传入正确的 I2C 总线名（如 `"i2c3"`），获取设备句柄/设备对象：

```c
#include <rtthread.h>
#include <rtdevice.h>
#include <sensor.h>

/* 以软件包导出的 init 为例：绑定到 i2c3 总线 */
int ret = ht10_init("i2c3");        /* 具体函数名以软件包头文件为准 */
if (ret != RT_EOK)
{
    rt_kprintf("ht10 init failed\n");
    return;
}

rt_device_t dev = rt_device_find("ht10");   /* 或软件包注册的设备名 */
if (dev == RT_NULL)
{
    rt_kprintf("find ht10 device failed\n");
    return;
}
rt_device_open(dev, RT_DEVICE_FLAG_RDONLY);
```

- 使用软件包提供的 `read` 函数（或传感器框架的 `rt_device_read`）读取温度与湿度：

```c
struct rt_sensor_data data;

/* 传感器框架统一读取：返回 1 表示读到一条数据 */
if (rt_device_read(dev, 0, &data, 1) == 1)
{
    /* 温度单位通常为 0.1 ℃，data.data.temp 为整数 */
    rt_kprintf("temp: %d.%d C\n", data.data.temp / 10, data.data.temp % 10);
    rt_kprintf("humi: %d.%d %%\n", data.data.humi / 10, data.data.humi % 10);
}
```

### 3. 调试技巧

- 初始化后和读取前都要做**空指针判断与异常处理**，避免设备未就绪导致访问空指针。
- **创建独立线程定时采集**（如每 500 ms 延时采集一次），避免在主线程或循环里高频轮询阻塞其它任务：

```c
static void ht10_collect_entry(void *parameter)
{
    while (1)
    {
        /* 读取并打印温湿度 */
        rt_thread_mdelay(500);
    }
}
```

- 若遇到 `sensor_ops` 未定义等编译报错，通常是 **sensor 框架没开启**，回到 menuconfig 检查 `RT_USING_SENSOR`。

## 三、WiFi 通信与 MQTT 协议

### 1. RW007 WiFi 模块配置

- 在 menuconfig 中**使能 RW007 软件包**（RT-Thread online packages → IoT - internet of things → Wi-Fi → RW007）。
- **关键步骤：核对引脚映射**。软件包默认的 SPI 片选(CS)、中断(INT/IRQ)、复位(RST) 引脚往往与开发板原理图不一致，必须在 menuconfig 中改成正确的引脚编号（用 `GET_PIN(...)` 编号），否则模块无法工作。
- 编译下载后，通过命令行验证：
  - `wifi scan` 扫描热点；
  - `wifi join <ssid> <password>` 连接（如手机热点）；
  - `ping` 外网地址，验证网络连通。

### 2. MQTT 客户端通信

- 使用开源 MQTT 软件包（如 paho-mqtt / kawaii-mqtt），服务器可先用 **EMQX 等公共服务器**。
- 配置要点：
  - 服务器地址、端口（通常 **1883**）；
  - **Client ID 必须全局唯一**（公共服务器一般无需用户名/密码）；
  - 订阅与发布**主题建议错开**，避免自己的消息串台。
- 发送消息可选用 **QoS 0**（至多一次），不可靠但资源消耗极低，适合资源受限的 MCU。
- 命令行典型流程：

```
msh />wifi join your_hotspot your_password
msh />mqtt start
msh />mqtt sub rtthread/topic
msh />mqtt pub rtthread/topic hello_from_board
```

### 3. 注意事项

- 嵌入式 MCU 资源有限，shell **不支持 Ctrl+C 终止线程**，实验结束后通常需复位或执行 `reboot` 释放资源。
- **Client ID 不唯一**会导致 MQTT 服务器把前一个连接踢下线（互踢掉线），务必为每块板子设置不同 ID。

## 四、DFS 虚拟文件系统

### 1. 组件使能与挂载

- 在 menuconfig 中开启 **DFS 组件**（RT-Thread Components → DFS: device virtual file system）、**elm（FatFs）文件系统**，并配置**自动挂载 Flash 分区**。
- 将 W25Q64 外部 Flash 挂载到根目录（如 `/fl`），需配置正确的**扇区大小**（W25Q64 常见为 4096）。
- 可借助 **FAL 组件**统一管理片内/片外 Flash 分区（定义分区表），再由文件系统挂载到对应块设备：

```
RT-Thread Components
  └─ Device virtual file system (DFS)
       ├─ Enable elm-chan fatfs
       └─ Mount root filesystem on flash partition (auto mount /fl)
```

### 2. SPI 总线冲突解决

- 当 **WiFi 模块（RW007）与 SPI Flash 共用同一条 SPI 总线**时，必须避免片选相互干扰：在读写 Flash 的代码中**拉高 WiFi 的片选引脚**（如 `GPF10`），使其处于未选中状态，防止 WiFi 模块响应 Flash 的 SPI 事务。

```c
#define RW007_CS_PIN  GET_PIN(F, 10)

/* 读写 SPI Flash 前，先把 WiFi 片选拉高（失能） */
rt_pin_mode(RW007_CS_PIN, PIN_MODE_OUTPUT);
rt_pin_write(RW007_CS_PIN, PIN_HIGH);
```

### 3. 文件读写操作

- 应用层使用 **POSIX 标准接口**：`open()`、`write()`、`close()` 等。
- 打开文件时注意标志位：只读 `O_RDONLY`、只写 `O_WRONLY`、创建 `O_CREAT`、追加 `O_APPEND`、截断 `O_TRUNC` 等；并**判断文件描述符是否有效**（`fd < 0` 表示失败）。

```c
#include <dfs_posix.h>

static void file_write_demo(void)
{
    int fd;

    /* 创建并只写打开文件，若存在则清空 */
    fd = open("/fl/test.txt", O_WRONLY | O_CREAT | O_TRUNC, 0);
    if (fd < 0)
    {
        rt_kprintf("open /fl/test.txt failed\n");
        return;
    }

    write(fd, "hello rt-thread\n", 16);
    close(fd);
}
```

- 完整流程：**创建文件 → 写入数据 → 关闭文件 → 命令行验证**：

```
msh />ls /fl
Directory /fl:
test.txt           16
msh />cat /fl/test.txt
hello rt-thread
```

### 4. 扩展

- **DFS 提供统一接口**，屏蔽底层存储差异：上层都用 `open/read/write/close`，底层可以是 FatFs、ROMFS、NFS、设备文件等。
- 可通过 **SFUD 组件**驱动串行 Flash，统一适配不同厂家的 SPI NOR Flash，**无需关心具体芯片型号**，只要 SFUD 识别到 ID 即可按统一方式读写。
