# 第二天：RT-Thread 内核启动流程、线程机制与 SCons 构建系统

## 一、RT-Thread 内核启动流程与线程机制

### 1. 从裸机到 RTOS

裸机程序通常采用“前后台系统”：中断负责处理实时事件，`while(1)` 后台循环负责执行应用任务。当后台任务中存在等待标志位、延时或其他阻塞操作时，后续任务会被一起阻塞，可能导致 LCD 刷新等实时任务不能及时响应。

裸机模式的主要局限包括：并发效率低；一个任务阻塞可能影响其他任务，实时性较差；代码维护性差，修改一个模块可能牵连整个主循环；模块化程度和代码复用性不足。RT-Thread 通过线程、调度器、IPC 和定时器等内核机制，把应用拆分为多个相互独立的任务，由系统统一管理 CPU 时间。

### 2. RT-Thread 启动流程

不同工具链在进入 `main()` 前的入口不同：MDK 通常经过 `__main`，IAR 经过 Low Level Init，GCC 则经过 `_entry` 或类似入口。RT-Thread 会利用这些入口完成系统初始化，典型调用路径如下：

```text
上电复位 -> Reset_Handler -> SystemInit()
        -> 工具链入口（如 _entry）-> rtthread_startup()
        -> rt_hw_board_init()       // UART、时钟、SysTick 等板级初始化
        -> 打印 Logo
        -> rt_system_timer_init()   // 系统定时器初始化
        -> rt_system_scheduler_init() // 调度器初始化
        -> 信号量等可选内核组件初始化
        -> 创建 Application/Main 线程
        -> 创建 Timer 线程和 Idle 线程
        -> rt_system_scheduler_start()
        -> 最高优先级线程开始运行
```

自动初始化机制通过 `INIT_BOARD_EXPORT`、`INIT_APP_EXPORT` 等宏，把函数地址放入特定的链接段。链接器按段名排序，系统启动时再用函数指针依次遍历并调用这些函数，因此可以自动完成板级、组件和应用初始化。

调度器启动后采用抢占式优先级调度：优先级数值越小，优先级越高，系统总是优先运行就绪队列中优先级最高的线程。当多个线程优先级相同时，按照时间片轮转，让同优先级线程依次获得 CPU。

### 3. 线程状态与上下文切换

RT-Thread 线程通常包含以下五种状态：

| 状态 | 含义 | 常见触发方式 |
| --- | --- | --- |
| 初始态 `RT_THREAD_INIT` | 控制块和线程栈已经初始化，但还没有进入就绪队列 | `rt_thread_init` 或 `rt_thread_create` 后 |
| 就绪态 `RT_THREAD_READY` | 可以被调度器选中运行 | 调用 `rt_thread_startup` 后 |
| 运行态 `RT_THREAD_RUNNING` | 当前正在占用 CPU | 调度器选中该线程 |
| 挂起态 `RT_THREAD_SUSPEND` | 等待延时、信号量、事件或消息，不参与调度 | `rt_thread_delay`、等待 IPC 等 |
| 关闭态 `RT_THREAD_CLOSE` | 线程结束或被删除，等待清理 | 入口函数返回、`rt_thread_delete` 等 |

线程创建后并不会自动运行，必须调用 `rt_thread_startup()` 将其加入就绪队列。线程切换时，内核先保存当前线程的上下文（将寄存器压栈），再恢复目标线程保存的上下文（从栈中弹出寄存器），从而保证每个线程都能从上次暂停的位置继续执行。

线程控制块 `struct rt_thread` 中的关键成员包括：`stat` 保存线程状态及相关标志；`current_priority` 保存当前有效优先级；`init_tick` 和 `remaining_tick` 分别表示初始时间片和剩余时间片；`sp` 保存线程栈指针，用于上下文保存和恢复。

Idle 线程的优先级最低，通常为 31。它在没有其他就绪线程时运行，负责回收已经进入关闭态的动态线程，同时可以执行喂狗、休眠等低功耗处理。

### 4. 静态线程与动态线程

| 对比项 | 静态创建 | 动态创建 |
| --- | --- | --- |
| API | `rt_thread_init` | `rt_thread_create` |
| 内存来源 | 用户预先定义控制块和栈数组，通常位于 `.bss`/`.data` | 从系统堆中分配控制块和线程栈 |
| 生命周期 | 与静态对象一致，不由系统释放 | 删除后进入关闭队列，由 Idle 线程回收 |
| 优点 | 资源确定、不会出现堆碎片、运行时失败路径少 | 使用灵活，适合运行时按需创建 |
| 风险 | 需要提前确定线程数量和栈大小 | 可能分配失败，长期创建和删除会产生内存碎片 |

在高可靠场景中通常优先使用静态线程，因为 RAM/Flash 占用可以在编译和链接阶段确定，运行过程中不会因为堆不足或碎片导致线程创建失败。

### 5. 多线程实战：创建、启动和查看线程

作业中的 `thread_study.c` 同时演示了动态线程和静态线程：`th_led1` 使用 `rt_thread_create` 动态创建，优先级为 16，周期性翻转红色 LED 并打印计数；`th_led2` 使用 `rt_thread_init` 静态初始化，使用预先分配的 `thread2_stack`，周期性翻转蓝色 LED；`th_monitor` 是一个优先级更高的动态线程，用于每隔 2 秒打印两个线程的状态。

每个线程创建后都要检查返回值，再调用 `rt_thread_startup` 启动。线程通过 `rt_thread_mdelay(500)` 主动让出 CPU。使用 FinSH/msh 执行 `list_thread`，可以查看线程名称、优先级、状态和栈使用情况，验证线程是否成功创建、运行和退出。

## 二、SCons 构建系统语法与应用

### 1. SCons 脚本结构

RT-Thread 使用 SCons 管理工程构建。`SConscript` 通常位于源码子目录中，描述当前目录的源文件和构建规则；`SConstruct` 是顶层构建入口；`rtconfig.py` 定义工具链、编译器选项和目标平台；`rtconfig.h` 保存图形化配置生成的宏定义。

典型配置形式如下：

```python
from building import *

cwd = GetCurrentDir()
src = Glob('*.c')
CPPPATH = [cwd]
group = DefineGroup('Applications', src, depend=['RT_USING_FINSH'])
Return('group')
```

其中，`CPPPATH` 用于添加头文件搜索路径，`SRC` 或 `Glob()` 用于指定源文件，`DEPENDS`/`depend` 用于控制宏依赖：只有启用对应宏时，相关源码才会参与构建。

### 2. 常用构建命令

```text
scons                         编译工程
scons -c                      清理编译生成文件
scons --target=mdk5           生成 MDK 工程
scons --target=iar            生成 IAR 工程
scons --target=vscode         生成 VS Code 工程
scons --dist                  将 BSP 打包为可独立开发的工程压缩包
```

`scons --dist` 会整理当前 BSP 并移除与独立开发无关的文件，便于工程迁移和分发。

### 3. Env、RT-Thread Studio 与 Menuconfig

Env 和 RT-Thread Studio 都提供图形化配置能力。通过 Menuconfig 可以选择内核功能、线程数量、FinSH、软件包和外设驱动等选项，保存后配置结果会写入 `rtconfig.h`，SCons 再根据这些宏决定参与编译的源码。

软件包管理器支持在线获取和集成软件包，例如 LVGL、kernel samples 等。启用软件包后，相关源码和配置会自动纳入构建系统，减少手动复制文件和修改工程配置的工作量。

## 三、STM32F407 工程创建与调试

本次实操使用 STM32F407 星火一号开发板，在 RT-Thread Studio 中基于具体芯片型号创建工程，并配置芯片型号、ST-Link 调试器、UART 串口、FinSH/msh 命令行和 kernel samples 软件包。

调试时可以在汇编启动入口、`_entry`、`rtthread_startup`、板级初始化、调度器初始化和应用线程创建处设置断点，观察程序从复位到第一个线程运行的完整过程。重点检查硬件初始化是否完成、调度器是否启动、Application/Timer/Idle 线程是否创建，以及用户线程是否成功进入就绪态。

## 四、学习总结

RT-Thread 把应用任务从裸机主循环中拆分出来，通过线程状态管理和优先级调度实现清晰的并发执行。静态线程适合资源固定和高可靠系统，动态线程适合需要灵活创建和销毁的场景。SCons、Menuconfig 和 Studio 把源码组织、编译配置和软件包集成统一起来，提升了嵌入式工程的可维护性和开发效率。
