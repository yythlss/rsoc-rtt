## 二、 MQTT 物联网通信协议机制剖析

### 2.1 发布/订阅（Pub/Sub）解耦架构
MQTT 基于轻量级发布/订阅模型构建，客户端之间无需建立直接的点对点连接，而是通过主题（Topic）实现解耦：
* **空间解耦**：发布者与订阅者无需知道彼此的 IP 地址与物理位置。
* **时间解耦**：订阅者离线时，若设置了持久化会话（`CleanSession = 0`），Broker 可暂存 QoS 1/2 消息。
* **同步解耦**：发布操作为异步非阻塞行为，不会阻塞发布者的本地采集线程。

### 2.2 QoS 服务质量等级对比
* **QoS 0（At most once，最多一次）**：消息基于底层 TCP 发送，不进行应用层 ACK 确认，开销最小，适用于高频温湿度等允许少量丢包的遥测数据。
* **QoS 1（At least once，至少一次）**：包含 `PUBACK` 确认机制，若未收到确认则重传，可能导致重复消息，适用于告警通知。
* **QoS 2（Exactly once，恰好一次）**：通过四步握手（`PUBLISH` $\rightarrow$ `PUBREC` $\rightarrow$ `PUBREL` $\rightarrow$ `PUBCOMP`）确保严格有且仅到达一次，开销最大，适用于关键控制指令。

## 三、 RT-Thread DFS 虚拟文件系统与 Flash 存储分层

RT-Thread 针对存储设备构建了由顶向下的四层文件存储抽象：

```text
1. POSIX API 层      open() / close() / read() / write() / fsync()
2. DFS 抽象层        Device File System (统一挂载表管理 /fal, /sd 等挂载点)
3. 具体文件系统实现   Elm-FatFS / LittleFS / ROMFS
4. 块设备与驱动层    FAL (Flash 抽象层) ──▶ SFUD (通用 SPI Flash 驱动) ──▶ W25Q64
```

### 关键机制：`fsync()` 保证数据落盘
标准 C 库与 POSIX `write()` 操作默认写入内核的文件缓冲区以提升 I/O 吞吐率。在嵌入式掉电易失环境下，必须通过周期性或定批量（如每 10 次写入）显式调用 `fsync(fd)`，将 RAM 缓冲区中的脏数据同步刷写进物理 SPI Flash 扇区中。

## 四、 cJSON 数据解析与动态内存防御性编程

在嵌入式端解析不可信的云端下行 JSON 报文时，必须遵循严格的内存与类型防御规范：

```c
/* 1. 解析 JSON 根对象并判空 */
cJSON *root = cJSON_Parse(payload_str);
if (root == RT_NULL)
{
    LOG_E("JSON syntax error!");
    return;
}

/* 2. 获取指定键值对象并进行类型检查 */
cJSON *cmd_item = cJSON_GetObjectItem(root, "msg");
if (cmd_item != RT_NULL && cJSON_IsString(cmd_item) && cmd_item->valuestring != RT_NULL)
{
    /* 3. 安全提取字符串内容并执行业务 */
    if (rt_strcmp(cmd_item->valuestring, "led on") == 0)
    {
        rt_pin_write(PIN_LED_R, PIN_LOW);
    }
}

/* 4. 必须显式释放 cJSON 结构体树所占用的堆内存 */
cJSON_Delete(root);
```

> ⚠️ **核心原则**：`cJSON_Parse` 会在系统堆中动态创建大量树状节点对象。无论解析成功与否，在退出函数前必须调用 `cJSON_Delete(root)`，否则将引发灾难性的系统堆内存泄漏。

## 五、 生产者-消费者模式与 IPC 选型

在 AHT10 采集线程（生产者）与 MQTT 发布线程（消费者）之间：
* **为什么选择邮箱（Mailbox）**：
  传感器温湿度数据仅占用十几个字节，采集线程通过 `rt_malloc` 分配结构体指针压入邮箱；
  邮箱仅传递 4 字节指针，避免了消息队列深拷贝带来的 CPU 周期消耗，实现了极低开销的高性能流转；
* **内存所有权转移协议**：
  生产者分配内存并发送指针 $\rightarrow$ 消费者接收指针 $\rightarrow$ 消费者完成网络发布 $\rightarrow$ 消费者负责调用 `rt_free()` 释放内存。
