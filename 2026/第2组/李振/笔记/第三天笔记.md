# RT‑Thread 线程间通信学习笔

## 一、基础概念

多线程同时运行时，经常需要：

2. 线程之间传递数据
3. 线程之间同步（A做完再做B）
4. 保护共享资源，防止数据错乱

RT‑Thread提供4种最常用线程间通信/同步方式：

- 信号量（semaphore）：同步、资源计数
- 互斥锁（mutex）：独占访问共享资源，解决优先级反转
- 事件集（event）：一对多、多事件触发
- 消息队列（msgqueue）：线程之间传递整块数据

> 注意：全局变量也算最简单通信方式，但没有保护，容易出现竞争，只适合只读数据。

## 二、信号量 Semaphore

### 作用

- 线程同步（任务A通知任务B）
- 资源计数，限制最多N个线程访问资源

信号量有一个计数器：

- `rt_sem_take()`：P操作，计数器‑1，如果计数器=0，线程阻塞
- `rt_sem_release()`：V操作，计数器+1，唤醒等待线程

### 常用API

```
// 创建动态信号量
rt_sem_t sem;
sem = rt_sem_create("sem", 0, RT_IPC_FLAG_FIFO);

// 获取信号量，永久等待
rt_sem_take(sem, RT_WAITING_FOREVER);

// 释放信号量
rt_sem_release(sem);

// 删除
rt_sem_delete(sem);
```

参数说明：

- 第二个参数：初始计数值
- `RT_IPC_FLAG_FIFO`：先来先服务；`RT_IPC_FLAG_PRIO`：高优先级先唤醒

### 使用场景

2. 中断通知线程（中断里release，线程take阻塞等待）
3. 两个线程任务同步
4. 资源池，最多N个线程使用

### 简单示例

```
rt_sem_t test_sem;

void thread_a(void *param)
{
    while(1)
    {
        rt_kprintf("thread_a: do something\n");
        rt_thread_mdelay(1000);
        rt_sem_release(test_sem);
    }
}

void thread_b(void *param)
{
    while(1)
    {
        rt_sem_take(test_sem, RT_WAITING_FOREVER);
        rt_kprintf("thread_b 收到信号，开始执行\n");
    }
}
```

## 三、互斥锁 Mutex

### 作用

用来**独占式保护共享资源**，同一时刻只能有一个线程拿到锁。
自带**优先级继承**，可以缓解优先级反转问题，优先选用mutex而不是二值信号量。

### 常用API

```
// 创建互斥锁
rt_mutex_t mtx;
mtx = rt_mutex_create("mtx", RT_IPC_FLAG_FIFO);

// 获取锁
rt_mutex_take(mtx, RT_WAITING_FOREVER);

// 释放锁
rt_mutex_release(mtx);

// 删除
rt_mutex_delete(mtx);
```

### 使用规范

- 拿到锁一定要及时释放，不要长时间持有锁
- 不能在中断里面操作互斥锁
- 避免嵌套锁

### 示例

```
int share_data = 0;
rt_mutex_t data_mtx;

void thread1(void *param)
{
    while(1)
    {
        rt_mutex_take(data_mtx, RT_WAITING_FOREVER);
        share_data ++;
        rt_kprintf("thread1: share_data = %d\n",share_data);
        rt_mutex_release(data_mtx);
        rt_thread_mdelay(500);
    }
}

void thread2(void *param)
{
    while(1)
    {
        rt_mutex_take(data_mtx, RT_WAITING_FOREVER);
        share_data --;
        rt_kprintf("thread2: share_data = %d\n",share_data);
        rt_mutex_release(data_mtx);
        rt_thread_mdelay(500);
    }
}
```

## 四、事件集 Event

### 作用

一个线程可以等待**一个或多个事件标志**
支持两种等待模式：

- 逻辑或：任意一个事件到来就唤醒
- 逻辑与：所有等待事件全部到位才唤醒

事件集以**位**作为标志，一个32位变量最多可以管理32个独立事件。

### 常用API

```
rt_event_t event;
event = rt_event_create("event", RT_IPC_FLAG_FIFO);

// 发送事件，置位bit0、bit1
rt_event_send(event, (1 << 0) | (1 << 1));

// 等待事件
rt_event_recv(event,
              (1 << 0)|(1 << 1),
              RT_EVENT_FLAG_AND | RT_EVENT_FLAG_CLEAR,
              RT_WAITING_FOREVER,
              RT_NULL);

rt_event_delete(event);
```

标志位说明

- `RT_EVENT_FLAG_AND`：全部事件满足
- `RT_EVENT_FLAG_OR`：任意一个满足
- `RT_EVENT_FLAG_CLEAR`：等待成功之后自动清除对应事件位

适用场景：一个任务等待多个条件全部就绪。

## 五、消息队列 Message Queue

### 作用

线程之间传递**整块数据**，不是简单信号。
可以用于：线程A发数据、线程B接收并处理，实现生产者‑消费者模型。
消息队列每个元素大小固定，缓存多条消息。

### 常用API

```
rt_mq_t mq;
//名称，最大消息条数，单条消息字节大小，模式
mq = rt_mq_create("mq", 10, 32, RT_IPC_FLAG_FIFO);

//发送消息
rt_mq_send(mq, buf, sizeof(buf));

//接收消息
rt_mq_recv(mq, buf, sizeof(buf), RT_WAITING_FOREVER);

rt_mq_delete(mq);
```

适合场景：串口接收线程把数据抛给解析线程、数据转发。

## 六、四种IPC对比总结

| 方式     | 适合用途           | 能否传递数据 | 特点           |
| -------- | ------------------ | ------------ | -------------- |
| 信号量   | 任务同步、资源计数 | 否           | 计数器机制     |
| 互斥锁   | 共享资源独占保护   | 否           | 自带优先级继承 |
| 事件集   | 多事件条件同步     | 否           | 按bit标记事件  |
| 消息队列 | 线程传递数据包     | 是           | 缓存多条消息   |

> 简单选择口诀
> 1、只是通知另一个线程干活 → **信号量**
> 2、保护全局变量，防止同时修改 → **互斥锁**
> 3、需要等待多个条件同时完成 → **事件集**
> 4、线程之间需要发送数据、数据包 → **消息队列**

## 七、常见坑

2. 信号量初始值设置错误，线程直接take成功，同步失效
3. 拿到互斥锁忘记释放，线程死锁
4. 消息队列缓冲区太小，发送阻塞
5. 在中断里面使用会阻塞的IPC（mutex、消息队列带等待时间），系统崩溃；中断只能用不带阻塞的信号量release、event_send、mq_send
6. 优先级反转：保护共享资源优先使用mutex，不要用二值信号量
