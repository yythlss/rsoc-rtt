# RT‑Thread IO设备框架笔记

## 一、RT‑Thread I/O设备框架概念

### 1.1 框架作用

RT‑Thread 把硬件外设抽象成标准设备，**应用层使用统一接口，不需要关心底层芯片差异**，实现驱动和应用解耦，方便程序跨芯片移植。
整体分层：

2. **应用层**：调用标准IO接口
3. **IO设备管理层**：内核设备框架，`rt_device`，统一管理所有设备
4. **底层驱动层**：GPIO、I2C、SPI等硬件具体操作

### 1.2 设备模型

所有外设都继承`rt_device`基类，设备类型常见：

- 字符设备：UART、虚拟设备
- 块设备：SD卡、Flash
- PIN设备（GPIO）
- I2C总线设备
- SPI总线设备

### 1.3 设备操作通用流程

`rt_device_find` → `rt_device_open` → `read/write/control` →`rt_device_close`

## 二、RT‑Thread I/O通用API

### 通用设备API

```
// 根据名字查找设备
rt_device_t rt_device_find(const char *name);
// 打开设备
rt_err_t rt_device_open(rt_device_t dev, rt_uint16_t oflag);
// 关闭设备
rt_err_t rt_device_close(rt_device_t dev);
// 读设备
rt_ssize_t rt_device_read(rt_device_t dev,rt_off_t pos,void *buffer,rt_size_t size);
// 写设备
rt_ssize_t rt_device_write(rt_device_t dev,rt_off_t pos,const void *buffer,rt_size_t size);
// 设备控制（ioctl）
rt_err_t rt_device_control(rt_device_t dev,int cmd,void *args);
```

> 总线类设备（I2C/SPI）一般不直接使用read/write，会使用专门封装好的API。

## 三、GPIO(PIN)应用与驱动开发

### 3.1 PIN驱动框架

RT‑Thread将GPIO封装成PIN设备，引脚编号使用**芯片引脚号**

### 3.2 常用GPIO API

```
// 设置引脚模式
rt_pin_mode(pin_num, PIN_MODE_OUTPUT);
// 设置引脚输出高/低电平
rt_pin_write(pin_num, PIN_HIGH);
// 读取引脚电平
rt_pin_read(pin_num);
// 绑定外部中断
rt_pin_attach_irq(pin_num, mode, irq_callback, param);
// 使能引脚中断
rt_pin_irq_enable(pin_num, PIN_IRQ_ENABLE);
```

### 3.3 简单点灯示例

```
#include <rtthread.h>
#define LED_PIN    5
static void led_demo(void)
{
    rt_pin_mode(LED_PIN, PIN_MODE_OUTPUT);
    while(1)
    {
        rt_pin_write(LED_PIN, PIN_HIGH);
        rt_thread_mdelay(500);
        rt_pin_write(LED_PIN, PIN_LOW);
        rt_thread_mdelay(500);
    }
}
MSH_CMD_EXPORT(led_demo, gpio led test);
```

## 四、I2C从机应用与驱动开发

> RT‑Thread I2C框架分为：I2C总线适配器、I2C设备
> **从机模式**：芯片作为I2C Slave，等待主机发起读写

### 4.1 I2C从机关键API

```
//查找i2c总线
struct rt_i2c_bus_device *rt_i2c_bus_device_find(const char *bus_name);
//配置从机地址
rt_i2c_slave_configure(bus, slave_addr);
//从机接收
rt_i2c_slave_recv(bus,buf,len);
//从机发送
rt_i2c_slave_send(bus,buf,len);
```

### 4.2 使用步骤

2. menuconfig开启对应I2C外设、配置为从机模式
3. 获取I2C总线句柄
4. 设置本机从机地址
5. 调用收发函数，等待主机访问

## 五、SPI从机应用与驱动开发

SPI从机：由外部SPI主机控制时钟信号

### 5.1 SPI框架基础

SPI总线包含：SCLK、MOSI、MISO、片选CS
从机不能主动发起传输，必须等待主机拉低片选、提供时钟。

### 5.2 SPI从机常用API

```
//查找SPI总线
struct rt_spi_bus *rt_spi_bus_find(const char *bus_name);
//配置SPI从机参数（模式、波特率、数据位）
rt_spi_slave_config(bus,cfg);
//从机收发
rt_spi_slave_transfer(bus,tx_buf,rx_buf,length);
```
