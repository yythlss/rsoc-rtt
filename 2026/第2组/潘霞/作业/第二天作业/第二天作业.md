# 一、STM32F407启动流程

### 1.启动文件进入RT-Thread

启动文件startup_xx.s根据不同编译器进入不同函数：

```
MDK:$Sub$$main()
IAR:_low_level_init()
GCC:entry()
```

这些函数最终都会进入 rtthread_startup()

```
上电复位  ->  启动文件  ->  编译器相关入口  ->  rtthread_startup() 
```

### 2.关闭中断， 进入系统启动阶段

进入rtthread_startup()后，系统首先执行

```
rt_hw_interrupt_disable();
```

作用是暂时关闭中断，防止系统初始化过程中被中断打断，之后开始执行板级初始化和RT-Thread内核初始化

### 3.板级硬件初始化

主要执行：

```
rt_hw_board_init();
```

这个函数负责初始化与具体硬件平台有关的内容，例如：系统时钟、串口、SysTick、GPIO、堆内存、中断控制器、板级外设。

接着执行：

```
rt_components_board_init();
```

该函数会调用通过INIT_BOARD_EXPORT()注册的板级初始化函数

### 4.RT-Thread内核基础初始化

板级初始化完成后，系统会继续执行：

```
rt_show_version()  #显示RT-Thread版本信息
rt_system_timer_init()  #初始化系统定时器
rt_system_scheduler_init()  #初始化线程调度器
rt_system_signal_init()  #初始化信号机制
```

### 5.创建main线程

接下来执行：

```
rt_application_init();
```

该函数内部会初始化main线程：

```
rt_thread_init(main_thread,main_thread_entry,...);
```

此时系统并不是直接执行用户写的main()函数，而是先创建一个名为main_thread的RT-Thread线程。main_thread_entry()是RT-Thread对用户main()函数的封装

### 6.创建定时器线程和空闲线程

系统随后创建两个重要的系统线程

**定时器线程**

```
rt_system_timer_thread_init();
```

内部初始化

```
rt_thread_init(rt_thread_timer_entry);
```

定时器线程用于处理系统中的软件定时器和线程延时等功能

**空闲线程**

```
rt_thread_idle_init();
```

内部初始化

```
rt_thread_init(rt_thread_idle_entry);
```

空闲线程在系统没有其他就绪线程时运行，通常用于：处理空闲任务，执行空闲钩子函数，进行资源回收。进入低功耗模式

### 7.启动调度器并选择线程

完成各类线程初始化后，系统执行：

```
rt_system_scheduler_start();
```

这一步表示正式启动RT-Thread调度器

调度器会根据线程的优先级和时间片选择需要运行的线程，可能运行：

```
main_thread_entry()
rt_thread_timer_entry()
rt_thread_idle_entry()
其他用户线程
```

需要注意：

```
rt_system_scheduler_init()   #是初始化调度器
rt_system_scheduler_start()   #是真正的启动调度器
```

### 8.执行组件初始化并进入main()

调度器启动后，系统首先可能运行main_thread_entry()

在main_thread_entry()中，通常会执行：

```
rt_components_init();
```

该函数会按照初始化顺序执行自动注册的初始化函数

对应的初始化宏主要包括：

```
INIT_PREV_EXPORT()
INIT_DEVICE_EXPORT()
INIT_COMPONENT_EXPORT()
INIT_ENV_EXPORT()
INIT_APP_EXPORT()
```

组件初始化完成后，才会进入用户编写的main()，然后开始执行应用程序。例如：

```
int main(void)
{
    while(1)
    {
         //用户应用任务
    }
}
```



**RT-Thread的核心启动流程可以概括为：**

```
rtthread_startup()
{
    rt_hw_board_init();              # 板级硬件初始化

    rt_system_timer_init();          # 系统定时器初始化
    rt_system_scheduler_init();      # 调度器初始化

    rt_application_init();           # 创建 main 线程

    rt_system_timer_thread_init();   # 定时器线程初始化
    rt_thread_idle_init();           # 空闲线程初始化

    rt_system_scheduler_start();     # 启动调度器
}
```

启动调度器以后，系统会根据线程优先级选择需要运行的线程，对于单核STM32F407，同一时刻实际只有一个线程占用CPU，但系统通过快速的上下文切换实现多线程并发执行的效果



# 二、RT-Thread引导机制

RT-Thread 的引导机制核心是“自动初始化”。也就是说，系统启动时不需要在 main() 里手动逐个调用各模块初始化函数，而是通过初始化宏把函数注册到对应的初始化表中，系统在启动过程中按顺序自动执行。

### 1. 自动初始化的基本思想

RT-Thread 将不同阶段的初始化函数分成多个层次，例如：板级初始化、设备初始化、组件初始化、环境初始化、应用初始化

这样做的好处是：各模块职责清晰、初始化顺序明确、不需要在main()中手动堆叠大量初始化代码、便于移植和维护

### 2.常见自动初始化宏

```
INIT_BOARD_EXPORT()
INIT_PREV_EXPORT()
INIT_DEVICE_EXPORT()
INIT_COMPONENT_EXPORT()
INIT_ENV_EXPORT()
INIT_APP_EXPORT()
```

这些宏的作用是把对应的初始化函数注册到指定的初始化段中，系统启动后统一扫描并执行

### 3.INIT_BOARD_EXPORT()的使用

INIT_BOARD_EXPORT()用于板级初始化阶段，通常在内核完成启动之前执行，适合放置：时钟初始化、串口初始化、GPIO初始化、板载外设初始化。这类初始化和具体硬件平台关系最密切，因此放在最早阶段执行

### 4.INIT_APP_EXPORT()的使用

INIT_APP_EXPORT()用于应用初始化阶段。它通常在系统线程已经建立、调度器已经启动之后执行，适合放置：用户功能模块初始化、测试任务初始化、应用线程创建、业务逻辑入口

### 5.自动初始化原理

自动初始化的本质是：

5.1使用宏把初始化函数转换成函数指针

5.2将函数指针放入指定链接段

5.3系统启动时遍历这些链接段

5.4依次调用对应初始化函数

因此，自动初始化不是“自动寻找函数”，而是“启动时遍历预先注册好的函数表”



# 三、内核基础与对象模型

### 1.RT-Thread的对象化设计

RT-Thread虽然主要使用C语言编写，但它采用了类似面向对象的设计思想。线程、信号量、互斥量、事件、邮箱、消息队列、定时器等，都被抽象成统一管理的内核对象，这种设计的优点是：统一管理、便于调试、便于扩展、对不同内核对象使用相似的管理机制

### 2.线程控制块

线程在RT-Thread中由线程控制块struct rt_thread描述，它保存了线程运行所需的关键状态信息，例如：

| 成员             | 作用                     |
| ---------------- | ------------------------ |
| stat             | 表示线程当前状态         |
| current_priority | 表示线程当前优先级       |
| init_tick        | 表示线程初始化时的时间片 |
| sp               | 保存线程当前栈指针       |
| stack_addr       | 线程栈起始地址           |
| stack_size       | 线程栈大小               |
| entry            | 线程入口函数             |
| parameter        | 线程入口参数             |

其中，sp最重要。线程切换时，系统通过保存和恢复栈指针来完成上下文切换

### 3.内存分配方式

**静态线程rt_thread_init()**

静态线程的控制块和栈空间在编译期就已经分配好，通常定义在全局区或静态区

优点：内存分配确定，不依赖动态堆，运行更稳定，适合高可靠场景

缺点：不够灵活，占用的资源在编译时就固定下来

**动态线程rt_thread_create()**

动态线程由系统从堆中分配控制块和栈空间

优点：使用灵活，线程可以按需创建和删除，适合功能变化较多的场景

缺点：依赖动态内存，可能出现申请失败，长期运行可能引入内存碎片

### 4.高可靠场景常用静态线程

4.1避免运行时内存申请失败

4.2减少内存碎片

4.3资源占用可提前估算

4.4系统行为更可控

4.5更容易通过可靠性测试



# 四、线程状态机与调度算法

### 1.线程五态

RT-Thread线程通常由五种状态：

| 状态   | 含义                       |
| ------ | -------------------------- |
| 初始态 | 线程已创建，但尚未启动     |
| 就绪态 | 线程已经准备好运行         |
| 运行态 | 当前正在占用CPU            |
| 挂起态 | 线程在等待资源、延时或事件 |
| 关闭态 | 线程已经结束或被删除       |

**触发线程状态转换的典型API**

线程状态会随着线程创建、启动、延时、挂起、恢复和删除等操作发生变化

| 状态转换                 | 典型API或触发条件                                        | 说明                                                         |
| ------------------------ | -------------------------------------------------------- | ------------------------------------------------------------ |
| 无状态->初始态           | rt_thread_init()、rt_thread_create()                     | 初始化或创建线程，此时线程还没有参与调度                     |
| 初始态->就绪态           | rt_thread_startup()                                      | 启动线程，并将线程加入就绪队列                               |
| 就绪态->运行态           | 调度器选择                                               | 由调度器选择优先级最高的就绪线程运行，不是由普通应用API直接完成 |
| 运行态->就绪态           | 时间片耗尽、被高优先级线程抢占、rt_thread_yield()        | 当前线程暂时让出CPU，但仍然可以参与调度                      |
| 运行态->挂起态           | rt_thread_delay()、rt_thread_mdelay()、rt_thread_sleep() | 线程主动延时，延时期间不参与调度                             |
| 运行态->挂起态           | rt_thread_suspend()                                      | 主动挂起指定线程                                             |
| 运行态->挂起态           | 等待信号量、互斥量、事件或消息                           | 当资源暂时不可用时，线程阻塞等待                             |
| 挂起态->就绪态           | rt_thread_resume()                                       | 将被挂起的线程恢复，并重新加入就绪队列                       |
| 挂起态->就绪态           | 延时结束或等待的资源可用                                 | 线程等待条件满足后重新进入就绪态                             |
| 运行态或就绪态->关闭态   | rt_thread_delete()、线程入口函数返回                     | 删除线程，或者线程执行结束                                   |
| 非运行态静态线程->关闭态 | rt_thread_detach()                                       | 将静态线程从系统对象管理中脱离，不释放其静态分配的栈和控制块 |

需要注意：

1.1rt_thread_startup()的作用是将初始态线程启动，并放入就绪队列

1.2就绪态进入运行态，主要由调度器决定

1.3rt_thread_delay()、rt_thread_mdelay()会使当前线程进入挂起状态

1.4rt_thread_suspend()用于主动挂起线程，rt_thread_resume()用于恢复线程

1.5rt_thread_yield()通常不会使线程进入挂起态，线程让出CPU后仍然处于就绪状态

1.6当线程等待信号量、互斥量、事件、邮箱或消息队列时，如果资源暂时不可用，也会进入挂起状态

1.7rt_thread_delete()用于删除动态线程，静态线程通常使用rt_thread_detach()脱离系统管理

### 2.抢占式调度

RT-Thread采用基于优先级的抢占式调度，优先级越小优先级越高

当高优先级线程变为就绪态时，调度器会优先让它运行，从而抢占低优先级线程

### 3.时间片轮转

当多个线程优先级相同，并且都处于就绪态时，系统会根据时间片轮流运行这些线程。例如两个优先级都为16的线程，各自时间片为5ticks：

线程A运行5ticks->切换到线程B->线程B运行5ticks->再切回到线程A
