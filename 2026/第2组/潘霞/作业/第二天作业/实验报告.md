# 一、实验目的

基于RT-Thread操作系统和STM32F407星火一号开发板，完成多线程创建、线程调度、线程状态查看、按键控制

# 二、实验任务

本实验主要实现三个线程

| 线程名称   | 创建方式   | 优先级 | 时间片 | 栈大小    | 功能                                            |
| ---------- | ---------- | ------ | ------ | --------- | ----------------------------------------------- |
| th_led1    | 动态创建   | 16     | 5ticks | 1024Bytes | 翻转LED_R，并打印计数和系统tick                 |
| th_led2    | 静态初始化 | 16     | 5ticks | 1024Bytes | 翻转LED_B，并打印计数                           |
| th_monitor | 动态创建   | 10     | 5ticks | 1024Bytes | 检测按键，控制th_led1暂停和恢复，并查看线程状态 |

其中，th_monitor的优先级为10，高于两个LED工作线程的优先级16，因此当按键时间发生时，监控线程能够优先响应

# 三、程序设计思路

### 3.1动态线程th_led1

th_led1使用rt_thread_create()动态创建，线程栈由系统动态分配。该线程循环翻转LED_R，每次翻转后打印当前计数值和rt_tick_get()获取到的系统tick值

当按键触发暂停请求后，th_led1会主动关闭LED_R，并调用rt_sem_take()等信号量。此时线程进入等待状态，不再继续翻转LED_R

### 3.2静态线程th_led2

th_led2使用rt_thread_init()静态初始化，线程控制块和线程栈均定义为全局变量。该线程循环翻转LED_B，并在串口中打印当前计数值

与动态线程不同，静态线程的TCB和栈空间在编译阶段已经确定，不需要运行时动态申请内存，因此更适合一些对稳定性要求较高的场景

### 3.3监控线程th_monitor

th_monitor使用rt_thread_create()动态创建，优先级设置为10.该线程负责检测LEFT按键触发时间，并根据当前状态控制th_led1暂停或恢复

在本次实验中，原本任务要求中提到使用rt_thread_suspend()和rt_thread_resume()控制线程。但是在当前版本中源码说明rt_thread_suspend()只能用于挂起当前线程自身，即：

```
rt_thread_suspend(rt_thread_self());
```

因此本实验没有让监控线程直接挂起th_led1，而是采用信号量方式实现控制：

第一次按下LEFT按键：设置暂停请求，th_led1自身进入信号量等待状态

第二次按下LEFT按键：释放信号量，使th_led1从等待状态恢复运行

这种方式符合当前 RT-Thread 版本的使用限制，也能实现按键控制线程暂停和恢复的实验效果

### 4.4 自动初始化与命令导出

本实验使用 INIT_APP_EXPORT(thread_study_init) 将实验初始化函数注册到 RT-Thread 自动初始化流程中。系统启动后会自动执行该初始化函数，不需要在 main.c 中手动调用。

同时，实验使用 MSH_CMD_EXPORT() 导出了线程查看命令，例如：

```
MSH_CMD_EXPORT(thread_dump, show thread status and stack space);
```

通过 FinSH/MSH 输入 thread_dump，可以查看当前线程状态、优先级、栈大小、栈使用情况等信息

## 5. 实验现象

### 5.1 程序运行初始现象

程序烧录运行后，`th_led1` 和 `th_led2` 同时启动。两个 LED 工作线程优先级相同，时间片相同，因此可以看到两个 LED 以相近频率闪烁。

![image-20260818210605960](D:\TYPORA\figures\image-20260818210605960.png)

图中可以看到开发板上两个 LED 同时处于闪烁工作状态，说明动态创建的 `th_led1` 和静态初始化的 `th_led2` 都已经正常运行

### 5.2 按下 LEFT 按键后的现象

第一次按下 LEFT 按键后，串口输出：

```
[key] LEFT pressed, request pause th_led1
[th_led1] wait semaphore, LED_R paused
```

此时 th_led1接收到暂停请求后进入信号量等待状态，LED_R 停止闪烁；th_led2不受影响，继续翻转 LED_B

![image-20260818210732275](D:\TYPORA\figures\image-20260818210732275.png)

该现象说明按键中断能够正常触发，监控线程能够正确处理按键事件，并通过信号量机制控制 th_led1 暂停

### 5.3 再次按下 LEFT 按键后的现

再次按下 LEFT 按键后，串口输出：

```
[key] LEFT pressed, release semaphore for th_led1
[th_led1] semaphore released, LED_R resume
```

此时 th_monitor 释放信号量，th_led1从等待状态恢复运行，LED_R 重新开始闪烁

该现象说明信号量释放后，等待中的线程能够被唤醒，线程恢复执行

## 6. 串口输出分析

![image-20260818210821589](D:\TYPORA\figures\image-20260818210821589.png)

从串口输出可以看到：

```
[th_led1] count=10 tick=7121
[th_led2] count=16
```

其中，count表示线程循环执行次数，也可以理解为 LED 翻转次数的计数。tick表示系统当前 tick 值，由 rt_tick_get() 获取，用于观察系统运行时间

串口中还输出了线程状态和栈空间信息，例如：

```
[th_led1] stat=SUSPEND(0x02) stack_free=780 stack_size=1024
[th_led2] stat=SUSPEND(0x02) stack_free=776 stack_size=1024
[th_monitor] stat=RUNNING(0x03) stack_free=756 stack_size=1024
```

其中：

stat表示线程当前状态

stack_size表示线程栈总大小

stack_free 表示线程当前剩余栈空间

stack_free可用于判断线程栈是否足够，避免线程栈溢出

例如 th_led1 的 stack_size=1024，stack_free=780，说明该线程大约使用了 1024 - 780 = 244字节栈空间，栈空间仍然比较充足

![image-20260818211045732](D:\TYPORA\figures\image-20260818211045732.png)

可以查看当前系统中的线程信息，包括线程名、优先级、状态、栈大小、最大栈使用率、剩余 tick 等

截图中可以看到 th_led1、th_led2、th_monitor 等线程已经创建成功。其中 th_led1 和 th_led2 多数情况下显示为 suspend，这是正常现象。原因是两个 LED 线程每次翻转 LED 后都会调用 rt_thread_mdelay() 进行延时，因此在查看线程状态的瞬间，线程大概率处于延时等待状态

当第一次按下 LEFT 按键后，th_led1会等待信号量，因此保持在挂起状态；再次按下 LEFT 按键后，信号量被释放，th_led1恢复运行，然后继续周期性闪烁

## 8. 实验结果总结

本实验完成了 RT-Thread 多线程编程的基本要求：

1. 使用 rt_thread_create()动态创建了 th_led1线程
2. 使用 rt_thread_init()静态初始化了 th_led2线程
3. 使用动态线程 th_monitor实现按键检测和线程控制
4. 使用信号量实现了 th_led1的暂停与恢复
5. 使用 INIT_APP_EXPORT()实现模块自动初始化
6. 使用 MSH_CMD_EXPORT()导出了自定义线程查看命令
7. 通过串口输出和开发板 LED 现象验证了程序运行结果

实验结果表明，RT-Thread 可以通过线程优先级、时间片和 IPC 机制实现多个任务的并发运行和同步控制。在 STM32F407 单核处理器上，同一时刻只有一个线程真正占用 CPU，但由于系统调度器能够快速切换线程，因此从现象上可以看到多个 LED 任务同时运行
